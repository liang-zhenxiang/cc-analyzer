# 工作流体检（Issue #391）· UI/UX 设计规格

**一句话定位**：从本机日志里可复算的**绝对读数**出发，指出使用方式上值得改的几处——每项三件东西：一个事实、它的分子分母、一个具体处方。不比较上一段区间、不给分、不排名、不做心理分析。

作者：liangzhenxiang。日期：2026-11-25。本文只写视觉与交互规格，不含实现代码。所有尺寸以 **CSS px** 为单位；颜色以令牌名为准，十六进制只是当前取值的参考，不复制进组件。

### 0.2 与既有卡的区隔（必须一眼读出来）

| 本卡 | 已有近似物 | 区别 |
| --- | --- | --- |
| 工作流体检 | 「值得注意的变化」（#383） | 那张卡问「与上一段比，什么变了」；本卡问「不管上一段，这个习惯本身是否越过绝对阈值」 |
| 工作流体检 | 设置里的「数据体检」（#H9） | 那个查 **JSONL 文件完整性**（截断行、解析警告），有等级与分数；本卡查**使用方式**，没有分数 |
| 工作流体检 | 「工作习惯」四格（#H10） | 那个陈述形状（早鸟 / 夜猫 / 连击 / 峰值小时）；本卡给**可执行处方**，且不是 2×2 格子 |
| 工作流体检 | 「回声」（#371） | 回声把重复话题聚成组；本卡不重复该维度 |
| 工作流体检 | 晨报（H1） | 晨报是 42px 高的三列带子 + 彩色左竖条；本卡是纵向诊断清单，零彩色竖条 |

**为什么这两张卡不会被混淆**——这是本轮的核心设计问题，答案拆在六个可辨识的维度里：

| 维度 | 值得注意的变化 | 工作流体检 |
| --- | --- | --- |
| 行结构 | 一行一句事实 + 右侧范围 + 箭头 | **维度 + 级别 / 事实 / 处方** 的两段式，左侧有 92px 维度列与纵向诊断轨 |
| 整行交互 | 整行是按钮，点哪都展开 | **整行不可点**；只有行内「证据」和显式动作链接可点 |
| 状态语言 | 只有错误率有 ▲/▼，红/绿**只染箭头** | 三档**纯墨色形状**（实心 / 空心 / 短横）+ 级别字，零语义色 |
| 证据形态 | 三列对照表（指标 / 当前 / 上一个） | **定义列表 + 4px 刻度条**（读数 / 判定线），没有「上一个」列 |
| 动作 | 无 | 显式「处方」行；全卡最多一个跳转链接 |
| 空态 | 仍渲染，陈述「没达到阈值」 | 两种空态（全部健康 / 样本不足）都**整卡不渲染** |

### 0.3 数据契约（纯函数层）

建议模块 `web/src/features/usage/workflowCheckup.ts`。组件不碰时钟、不做 I/O、零新增 Tauri 命令。

```
buildWorkflowCheckup(inputs, days, now) -> {
  status: "ok" | "quiet" | "insufficient" | "empty"
  items: CheckupItem[]          // 最多 4 条，已排序；quiet/insufficient/empty 时为空
  checked: number               // 样本达标的检查项数（分母）
  total: number                 // 规则总数（首版 5）
  ineligible: number            // total - checked
  dropped: number               // 触发但因上限没显示的条数
  counts: { focus: number; notice: number; observe: number }  // 触发总数，不受上限影响
  summary: string               // "4 项检查里 2 项值得看一眼"；非 ok 状态为空串
  insufficient: { sessions: number; toolCalls: number; tokens: number } | null
  window: { startDay: number; days: number; label: string }
}

CheckupItem = {
  id: "context-pressure" | "error-focus" | "compaction-rate" | "cache-hit" | "delegation"
  level: "focus" | "notice" | "observe"
  dimension: string             // 上下文压力 / 错误集中 / …
  fact: string                  // 已格式化的事实句，数字已嵌入
  action: CheckupAction
  note: string | null           // 仅 observe
  intensity: number             // 同级排序用，测试钉住
  evidence: {
    rows: { label: string; value: string; numeric: boolean }[]  // 计数 / 读数 / 判定 / 样本 / 窗口
    meter: { value: number; max: number; threshold: number;
             direction: "above" | "below"; caption: string } | null
  }
}

CheckupAction =
  | { kind: "advice"; text: string }
  | { kind: "jump"; text: string; linkLabel: "打开错误档"; target: "errors" }
  | null
```

口径细节：

- **窗口**：最近 N 个本地自然日（含今天），与页面 KPI 同一段。起点 `addLocalDays(dayStartOf(now), -(days - 1))`，右界 `addLocalDays(dayStartOf(now), 1)`；不越过今天结束。`now` 用页面那份 `insightsNow`，不另取时钟。
- **未知 ≠ 0**：缺 `usage` 的会话不进上下文与缓存的分母；缺 `errorExtract` 的会话不进错误的分母；缺 `toolCalls` 的会话不进委派的分母；缺 `compactEvents` 的会话按 0 次压缩计（与 `compactionStats` 同约定）。事实句用**实际进入分母的样本数**，不把没扫到的事实说成 0。
- **分母不许借错**：压缩频率的分母是 `statsForRange(...).sessions`（窗口内有记录的会话），**不是** `compactionStats(...).sessions`（发生过压缩的会话）。后者会让「22 次 / 48 个会话 = 0.46 次/会话」变成「22 次 / 18 个压过的会话 = 1.22 次/会话」，同一批数据给出两倍多的读数。
- **缓存分母不许借周报**：按 Issue 用 `input + cacheCreation + cacheRead`，不是周报的 `input + cacheRead`。两套数字同时出现在一个应用里会互相打脸；本卡的依据区必须把分母原文写出来。
- **可复算**：事实句里的每个数字都能在证据区找到它的分子、分母、阈值、样本量与窗口。组件不重算，只排版 `buildWorkflowCheckup` 的结果。
- **确定性**：同一输入每次得到同一组值、同一顺序、同一组级别与形状（本卡没有颜色，只有形状）。同分排序规则见 §0.5。

### 0.4 五条规则、阈值与样本下限

| id | 维度 | 判定读数 | 触发条件 | 样本下限 | 关注线（严格） | 方向 |
| --- | --- | --- | --- | --- | --- | --- |
| `context-pressure` | 上下文压力 | 峰值 ≥ `200K × 85% = 170K` 的会话 ÷ 有 usage 的会话 | 占比 **> 25%** | ≥ 8 个有 usage 的会话 | 占比 **> 50%** | above |
| `error-focus` | 错误集中 | 单一工具占全部工具失败的份额；该工具失败率 = 失败 ÷ 该工具调用 | 份额 **≥ 60%** 且失败率 **> 10%** | ≥ 20 次工具调用（全部工具） | 失败率 **> 20%** | above |
| `compaction-rate` | 压缩频次 | 窗口内压缩次数 ÷ 有记录会话数 | **> 0.40 次/会话** 且压缩 **≥ 3 次** | ≥ 5 个有记录的会话 | **> 0.80 次/会话** | above |
| `cache-hit` | 缓存利用率 | `cacheRead ÷ (input + cacheCreation + cacheRead)` | **< 15%** | 窗口 token ≥ 5M | **< 8%** | below |
| `delegation` | 委派使用 | 用过子 agent 的会话 ÷ 有工具事实的会话 | **< 5%** | ≥ 20 个有工具事实的会话 | —（恒为 observe） | below |

- 阈值全部写成具名常量并导出（`CHECKUP_THRESHOLDS`），测试逐条覆盖触发 / 不触发 / 样本不足三态。**除 `error-focus` 的份额（≥ 60%，等于算）之外，其余触发条件与本表所有关注线都是严格不等号**：恰好等于触发线不触发，恰好等于关注线仍停在「留意」。
- **Issue 正文的两个示例恰好都不越线**：`12 / 48 = 25.0%` 在「> 25%」下不触发，`19 / 48 = 0.396 次/会话` 在「> 0.40」下也不触发。实现与测试夹具不要照抄这两个数；本规格的事实示例改用 `25 / 48 = 52.1%` 与 `22 / 48 = 0.46 次/会话`。错误示例 `137 / 149 = 92%` 与委派示例 `2 / 48 = 4.2%` 是越线的，可以直接用。
- `error-focus` 的两个条件必须同时成立：份额 ≥ 60%（集中）是「值不值得看」，失败率 > 10% 是「是不是真的坏」。只有集中、失败率很低（工具本身调用量巨大）不该被判为坏习惯。
- `compaction-rate` 的 ≥ 5 个会话下限是本设计补充的样本护栏：原 Issue 只要求「压缩 ≥ 3 次」，但 1 个会话压 3 次会得到 3.0 次/会话的假习惯。3 次事件仍保留为触发条件，两者不互相替代。
- `cache-hit` 的 5M 是 token 样本，不是会话样本；token 少的时候一次冷启动就能把命中率压到 15% 以下。
- `delegation` 永远没有处方。是否适合委派取决于具体任务，编一句「多用子 agent」是臆断；它只作为观察项出现。

### 0.5 级别、排序与上限

- **级别**：`focus`（关注）> `notice`（留意）> `observe`（观察，对应 Issue 的「中性」）。级别由规则内的关注线决定，不由排名决定——排名会随窗口变，级别必须只由读数决定。
- **排序**：先按级别；同级按 `intensity` 降序；再按规则序号（上下文 1 / 错误 2 / 压缩 3 / 缓存 4 / 委派 5）。`intensity`：
  - above：`(reading - trigger) / trigger`
  - below：`(trigger - reading) / trigger`
  - `error-focus` 的 `intensity` 用**失败集中度**（份额），关注线用的是**失败率**——前者负责同级排序，后者负责级别；两个数都在证据里，不要用错。
  - 同级同强度的两条，顺序永远一致。
- **上限 4 条**：`focus/notice` 先排，`observe` 最后；超出 4 条时截断，`dropped` 记下被截掉的条数。`observe` 是最先被挤掉的——它没有处方，价值低于任何一条可执行的项。
- **只有观察项时整卡不渲染**（`status: "quiet"`）。一张只有「你很少用子 agent」、没有处方的卡就是一张成绩单，正是 Issue 禁止的东西。
- **状态判定优先级**：
  1. `empty`：窗口内没有任何会话记录 → 组件返回 `null`（页面级空态已经在说话）。
  2. `insufficient`：有会话，但 `checked === 0`（没有任何一项达到样本下限）→ **整卡不渲染**（见 §4 的修订说明）。
  3. `quiet`：`checked > 0`，但没有 `focus/notice` 项（含只有 observe 的情况）→ 整卡不渲染。
  4. `ok`：至少一条 `focus/notice` → 渲染清单。

## 1 版式与尺寸

### 1.1 位置与网格

- 用量档，紧跟 `InsightsCard`，在 `BillingWindowCard` 之前；与它们同一列、同一 `gap: var(--sp-3)`。
- 整行宽度，不新增栅格列、不改页面断点。DOM 顺序：晨报 → 时间胶囊 → 值得注意的变化 → **工作流体检** → 计费窗口卡 → KPI 行。
- `Panel title="工作流体检" ariaLabel="工作流体检"`；标题仍是 h2，项内的维度名是 h3。
- 顶部右侧（`Panel` 的 `actions` 槽）放总述读数，不占正文高度：

  ```
  ┌ Panel 40px ────────────────────────────────────────────────────────────┐
  │ 工作流体检                              4 项检查里 2 项值得看一眼        │
  ├ body padding 12 ───────────────────────────────────────────────────────┤
  │  ┊ ●  上下文压力     25 / 48 个会话的上下文峰值超过 170K（…85%）  证据  │
  │  ┊    关注           处方  在接近上限前开新会话，而不是硬接——…           │
  │  ┊──────────────────────────────────────────────────────────────────── │
  │  ┊ ○  错误集中       全部 149 次工具失败里有 137 次来自 Bash（92%）…     │
  │  ┊    留意           处方  去看错误档案里 Bash 的前三个失败签名 打开错误档 →│
  │  ┊                                                                      │
  │  └ 脚注（--fs-xs，1–3 行）                                              │
  └────────────────────────────────────────────────────────────────────────┘
  ```

- `actions` 槽只放总述读数，不放按钮；不设第二个视图、不设导出。窗口选择器仍只有页头那一份。

### 1.2 卡内结构与高度

- 表头 40（标题 + 总述读数同一行，总述不撑高）。
- 体内距上下各 12。
- 清单：每项两行。行内 `padding: var(--sp-1) 0`（4 上下），行内容 = 事实 18（`--lh-sm`）+ 行距 4 + 处方 16（`--lh-xs`）= 38；**单项 46px**。项间 `border-top: 1px solid var(--border)`，首项无上边线、末项无下边线。
- 脚注：`margin-top: var(--sp-2)`，`--fs-xs / --lh-xs`，1–3 行。

| 条数 | 100% 高度（约） | 130% 高度（约） |
| --- | --- | --- |
| 1 | 134 | 149 |
| 2 | 181 | 206 |
| 3 | 228 | 263 |
| 4 | **275** | **321** |

- 上表按 1400 宽、脚注 1 行算。960 宽时脚注折 2–3 行：100% 的 4 条约 **291**；130% 的 4 条约 **342–363**，事实再折 1 行则 **≤ 386**。
- **上限就是 4 条**：当前 5 条规则里，`delegation` 是 observe，四条 `focus/notice` 全中时它被挤掉。未来规则增加到 7 条也还是 4 条——上限在数据层，不在 CSS。
- **不折叠整卡、不设「展开其余 N 项」**：那是一张小号的手风琴，会与上面「值得注意的变化」撞形态。条数由严重度上限控制。
- **不设 `max-height`、不出现卡内第二根滚动条**。展开一条证据时卡片会长高约 **185px**（130% 约 **220px**），这是用户主动动作，页面整体滚动。4 条 + 1 条证据展开的最坏高度：1400 宽约 **460（100%）/ 541（130%）**；960 宽 + 130% 约 **606**，接近一屏——用户点开证据后滚动阅读，不压缩字号、不裁字。
- **不预留空行**：只有 2 条就只占 2 条的高度，不为了「稳定高度」补两条虚线。
- **为什么不是 2×2 诊断板**：两列确实能把高度砍半，但它会立刻读成「工作习惯」四格的兄弟（同样的 2×2、同样的格子边界），而且切断纵向诊断轨的单一路径。高度由 4 条上限与两行密度控制，不靠换版式。7 条规则全中时也仍只显示 4 条，高度不变。

### 1.3 行几何

```
列：16px（诊断轨）│ 8px gap │ 92px（维度/级别）│ 8px gap │ minmax(0, 1fr)
行：第 1 行 18px（事实）│ 4px 行距 │ 第 2 行 16px（处方/说明）
```

```
x:  0   8   16        124                       content ……………………………
    [轨][●] [ 上下文压力 ] [ 25 / 48 个会话的上下文峰值超过 170K …  证据 ]
            [ 关注       ] [ 处方  在接近上限前开新会话，而不是硬接——…      ]
            [            ] [ ┌ 判定依据（展开时，从 content 列起）───────── ]
```

- 诊断轨：2px 宽、`--border-strong`、从清单顶到清单底；标记压在轨上。**轨是「刻度轴」，不是连接线**，首末标记之外各延伸一小段是刻意的。
- **为什么不做「健康 / 留意 / 关注」三段固定刻度**：本卡只渲染越线的项，健康段永远是空的；画一条空着的「健康」刻度会让人以为健康项被检查过并落在了那里。轨承担方向（越靠上越值得看，因为清单按级别排序），级别字承担档位——两者合起来是刻度，不需要三段背景带。
- 标记：8px，垂直居中于第一行（中心 = 行内上距 4 + 18 / 2 = 13px）。
  - `focus`：8×8 实心圆，`--text`；
  - `notice`：8×8 空心环，`border: 1.5px solid var(--text-secondary)`，内部 `--bg-subtle` 在轨上打洞；
  - `observe`：8×2 短横，`--text-tertiary`，`border-radius: 1px`。
- 维度名：`--fs-sm / --lh-sm`、`--text` / 600，**不换行**（当前最长 5 个汉字；130% 下 78px + 字距 < 92px）。列宽 92 是版式常量，不写进全局 token；不要加第 6 个汉字，也不要把字号再提一级。
- 级别字：第二行、`--fs-xs / --lh-xs`；`focus` 用 `--text-secondary` / 600，`notice` 用 `--text-tertiary` / 500，`observe` 用 `--text-tertiary` / 400。它对读屏隐藏（`aria-hidden`），语义由 h3 里的 sr-only 前缀承担，避免念两遍。
- 事实：`--fs-sm / --lh-sm`、`--text`、`overflow-wrap: anywhere`；数字用 `--font-mono` + `tabular-nums`，**不另给颜色**。
- 处方/说明：`--fs-xs / --lh-xs`、`--text-secondary`；行首标签 `处方` / `说明` 用 `--text-tertiary` / 600，`margin-right: var(--sp-1)`。
- 「证据」按钮：事实行末尾，`margin-left: var(--sp-1)`；`--text-secondary`；**常驻 1px 下划线**，下划线色 `--border-strong`，`text-underline-offset: 2px`；hover 时文字与下划线变 `--text`。没有折角箭头、没有背景块——它与上面那张卡的 6px 折角是两套语言。
- 动作链接：处方行末尾，`--accent`、500、下划线 `currentColor`、`margin-left: var(--sp-2)`、`white-space: nowrap`；hover `--accent-hover`。它是本卡常态下唯一的彩色像素。
- 行几何在模块顶部用局部自定义属性收口（`--checkup-rail: 2px`、`--checkup-dim: 92px`、`--checkup-marker: 8px`、`--checkup-meter: 4px`），**不新增全局 token、不改 `tokens.css`**。它们是「形」与版式常量，不是间距档位。

### 1.4 顶部总述

- 位置：`Panel` 表头右侧，`--fs-xs / --lh-xs`，`white-space: nowrap`，数字等宽。
- 文案：`{checked} 项检查里 {focus + notice} 项值得看一眼`。
  - 例：`4 项检查里 2 项值得看一眼`。
  - 分母是**样本达标的检查项数**，不是规则总数；因样本不足没判的项不算「检查过」。分子是**所有触发的 focus/notice**，不受 4 条显示上限影响；被上限挤掉时由脚注说明。
- 颜色：正文 `--text-tertiary`，两个数字 `--text` / 600 / mono。没有背景、没有边框——它是读数，不是徽章。
- `insufficient` / `quiet` / `empty` 三种状态整卡不渲染，因此都没有这枚总述。

## 2 状态与颜色

### 2.1 三档状态：形状 + 墨色 + 文字

| 级别 | 标记 | 级别字 | 维度名 | 含义 |
| --- | --- | --- | --- | --- |
| 关注 `focus` | 8px 实心圆 `--text` | `--text-secondary` / 600 | `--text` / 600 | 读数显著越过关注线，优先改 |
| 留意 `notice` | 8px 空心环 1.5px `--text-secondary` | `--text-tertiary` / 500 | `--text` / 600 | 越过触发线，值得看一眼 |
| 观察 `observe` | 8×2 短横 `--text-tertiary` | `--text-tertiary` / 400 | `--text` / 600 | 只陈述事实，没有处方 |

- **三通道冗余**：形状（实/空/横）+ 墨色（三档文字色）+ 级别字（关注/留意/观察）。灰度、色觉差异、高对比度下都成立。
- **不新增图例**：每行都印着级别字，再加一排图例只是把三个词重复一遍。

### 2.2 为什么「值得改」不用 `--danger` / `--warning` / `--success`

这是本轮最关键的颜色判断：

| 令牌 | 项目定义 | 为什么不能用来标「值得改」 |
| --- | --- | --- |
| `--danger` | 确定的**错误** | 习惯不是错误。红点会把「可以更好」说成「你做错了」，把一张诊断卡变成训话卡；还会与上面那张卡里唯一允许的红色（错误率 ▲）撞语义 |
| `--warning` | **非确定信息** | 本卡的读数全是确定的整数与比率，用琥珀色是在谎报「不确定」 |
| `--success` | 确定的**正常读数** | 本卡只渲染越线的项；给一个问题行绿点等于把绿的含义反过来 |
| `--chart-*` / `--cat-*` | 图表系列 / 记录类别 | 本卡没有系列，也没有类别；借用会同时污染两个维度 |
| `--accent` | 链接、焦点环、选中底 | 只给「打开错误档」这一处真实出口，不给判断 |

**结论：整张卡是「无彩色 + 一处强调色」。** 级别只靠形状、墨色、字重与顺序；常态下唯一有色的像素是那个真的能跳转的链接（键盘聚焦时另有焦点环）。这既回答了「习惯没有对错」，也符合项目「颜色只出现在数据上」的硬规则——这里的判断是一句话，不是数据；数据是数字，数字用正文墨色。

### 2.3 `--warning`：本卡不使用（修订于实现验收）

初稿把 `insufficient` 的引导词「样本不足」设为 `--warning`。样本不足时卡片已改为整卡不渲染（见 §4），本卡因此**不再使用 `--warning`**。若将来恢复该提示，`--warning` 仍是唯一正确的令牌——它确实标的是非确定信息。

### 2.4 深色与高对比度

- 深色：`--text` #f0f2f5、`--text-secondary` #b4bcc6、`--text-tertiary` #8b939e 在 `--bg-subtle` #14161a 上分别是 13:1 / 8:1 / 5.5:1；实心点、环、短横三档形状都能分辨。轨 `--border-strong`（白 0.14）在深底可见。
- 高对比度：墨色自动变成纯黑/纯白/实色灰；轨 `--border-strong` 是实色 #3f4854 / #9e9e9e；证据井 `--bg-inset` #eef1f5 / #000；链接 `--accent` #0b3f9c / #8ab4ff，均在 8:1 以上。
- 「证据」的下划线在高对比度下由 `--border-strong` 变实色，不再依赖低透明度。
- 不使用 `opacity` / `color-mix` / `fill-opacity` 任何叠层。

## 3 动作与证据

### 3.0 事实句定稿

| 规则 | 事实句 | 边界处理 |
| --- | --- | --- |
| `context-pressure` | `{n} / {m} 个会话的上下文峰值不低于 {line}（压缩阈值 {threshold} 的 85%）` | `{line} = formatAxisValue(200_000 × 0.85)`，当前是 `170K`；`{threshold}` 是 `200K`。**动词必须与判定的不等号一致**：判定是 `峰值 >= 170K` 才计入分子，所以文案写「不低于」，不能写「超过」——峰值恰好 170,000 时会进分子，说「超过」就是对读者说谎 |
| `error-focus` | `全部 {allToolErrors} 次工具失败里有 {toolErrors} 次来自 {tool}（{share}%），{tool} 失败率 {rate}%` | 份额的分母是全部工具失败；失败率的分母是该工具调用。两个分母都要在证据里出现 |
| `compaction-rate` | `{sessions} 个会话里发生了 {count} 次压缩，平均每 {per} 个会话压一次` | `per = sessions / count`，一位小数；证据的 `count / sessions` 用两位小数（`0.46 次/会话`） |
| `cache-hit` | `输入侧只有 {rate}% 来自缓存读取——大部分上下文每次都在重新写入` | `rate < 1%` 时改写为 `输入侧只有不到 1% 来自缓存读取——…`；不写 `0%` 冒充确定读数 |
| `delegation` | `{sessions} 个会话里只有 {n} 个用过子 agent` | `n === 0` 时改写为 `{sessions} 个会话里没有一个用过子 agent`（初稿写「没有会话用过」，同一句里「会话」出现两次，读起来拗口） |

- 事实句只由纯函数拼出；组件不拼句、不改词。测试断言整句，不只断言数字。
- `85%` 与 `200K` 分别从 `CHECKUP_THRESHOLDS.contextPeakRatio` 与 `DEFAULT_CONTEXT_THRESHOLD` 派生，**不写死在文案里**；改常量时事实句必须跟着变，否则它会对读者说谎。
- 百分比事实取整（`52%` / `92%`），压缩比率保留两位（`0.46 次/会话`）；证据一位小数（`52.1%` / `91.9%`），压缩证据两位。**事实与证据的「同值」按数值判定，不按字面**：事实取整、证据一位小数，字面子串本来就对不上（`137 / 149 = 91.9%`，不是 `92.0%`）。
- **取整不得跨过判定线**（`formatFactPercent`）：当某个百分比读数**本身**就是判定读数时（`cache-hit` 的命中率、`error-focus` 的失败率、`delegation` 的比例），事实句的显示精度必须让「显示值与判定线的比较结论」与「真实值与判定线的比较结论」一致，且显示值不得恰好等于判定线。从 0 位小数开始试，不够就加到 1 位、2 位（最多 2 位）。
  - 命中率真实 14.96%、判定 `< 15%` → 0 位得 `15%`（与判定线相等，会打印出「只有 15%」，读者读到「15% < 15%」自相矛盾）→ 1 位得 `15.0%`（仍相等）→ 2 位得 `14.96%`，合格。
  - 失败率真实 10.04%、判定 `> 10%` → 0 位 `10%` 相等 → 1 位 `10.0%` 相等 → 2 位 `10.04%`，合格。
  - 读数 92%、判定 `≥ 60%` → 0 位 `92% > 60%` 结论一致且不相等，直接用 `92%`，不必加精度。
  - 与判定线无关的百分比（如证据区的读数）不受此规则约束，仍按上面的固定精度。
- 不出现「你」「应该」「问题」「异常」；`错误集中` 说的是工具失败的事实，不是给用户下判断。

### 3.1 动作的两种形态

| 规则 | 第二行 | 跳转 |
| --- | --- | --- |
| `context-pressure` | `处方` + 「在接近上限前开新会话，而不是硬接——压缩一次会丢掉整段上下文」 | 无 |
| `error-focus` | `处方` + 「去看错误档案里 {tool} 的前三个失败签名」 | **`打开错误档 →`** |
| `compaction-rate` | `处方` + 「把长任务拆成多次会话，每次带更少的历史」 | 无 |
| `cache-hit` | `处方` + 「同一件事尽量在同一个会话里做完；频繁重启会让缓存反复失效」 | 无 |
| `delegation` | `说明` + 「这一项只陈述事实，不给建议——是否适合委派取决于具体任务。」 | 无 |

- **有动作 vs 没动作**：每一行都有第二行，所以没有一行是「半截」的。区别在于第二行开头的标签：`处方` 与 `说明`。`delegation` 不是「缺动作」，而是「本来就不该有动作」——`说明` 把它讲清楚。
- **只有一个真实跳转**：`error-focus` 的处方指向应用里已有的错误档，所以做成按钮；其余三条的处方是用户在工作方式上的改变，应用里没有对应屏幕，做成按钮就是假按钮。**宁可不给链接，也不给点了不动的链接。**
- 跳转按钮只在 `onOpenErrors` 存在时渲染；没有回调时（单测、嵌入场景）保留处方文字、隐藏按钮，不渲染 disabled 态——一个按不动的「打开错误档」会让用户以为是坏了。
- 按钮不是 `Button` 组件的 `primary`/`secondary`：那是有边框的控件，会和页头的「导出快照」抢重量。用行内文字按钮（同 `EquivalentsToggle` / `ErrorArchivePanel.sessionLink` 的先例）。
- 点击后：页面 `setView("errors")`，并在下一帧把焦点移到「总览视图」分段控件里「错误」那一枚，避免焦点掉回 `<body>`。这是本卡唯一需要页面配合的交互。
- 文案边界：`打开错误档` 只切到错误档；档内默认子视图仍是时间线，处方文字已经写明「错误档案」，用户知道下一步点哪个子标签。不新造跨档深链。

### 3.2 证据展开

- 触发：事实行末尾的「证据」按钮。展开后按钮文字变「收起」；`aria-expanded` / `aria-controls` 指向 `checkup-evidence-{id}`。
- **手风琴**：同一时刻只开一条。四条同时展开会多出约 700px；这与上面那张卡的理由相同，不是形态抄袭——本卡的区别在触发位置（行内小按钮）与内容形态（见下）。
- 结构：

  ```
  ┌（从 content 列起）─── --bg-inset 凹槽，左边 2px --border-strong ─────┐
  │ 判定依据                                                             │
  │ 计数      25 / 48 个会话（有 usage 的会话）                          │
  │ 读数      52.1%                                                      │
  │ 判定      触发 > 25% · 关注 > 50%                                    │
  │ 样本      48 个会话（下限 8）                                        │
  │ 窗口      近 30 天 · 10/23–11/21                                     │
  │ ▓▓▓▓▓▓▓▓▓▓┃▓▓▓░░░░░░                                                 │
  │ 52.1% · 判定线 25% · 高于判定线才成立                                │
  └──────────────────────────────────────────────────────────────────────┘
  ```

- **为什么是定义列表 + 刻度条，不是表格**：上面那张卡比较「当前 / 上一个」，所以是三列表；本卡比较「一个读数 / 一条判定线」，没有第二列可放。`dl` 是这件事的正确形状，4px 刻度条让「越过判定线」变成空间事实。
- 定义列表：`grid-template-columns: max-content minmax(0, 1fr)`，行距 `var(--sp-1)`，列距 `var(--sp-3)`；`dt` `--fs-xs / --lh-xs` / `--text-tertiary`，`dd` `--fs-sm / --lh-sm` / `--text-secondary`，数字 mono / `--text`。最多 5 行（计数 / 读数 / 判定 / 样本 / 窗口）；`error-focus` 把「计数」拆成「失败集中度」与「失败率」两行，仍是 5 行。
- 「判定」行同时写触发线与关注线（观察项只有触发线），级别因此可以从证据复算：`25 / 48 = 52.1% > 关注线 50%` 是关注；同样的读数如果只到 `30%`，就只是留意。不要只写触发线，否则读者看不出实心点与空心环的差别从哪来。
- 刻度条：轨道 4px 高、`--bg-active`、`--r-xs`；填充 `--text-secondary`，宽度 = `clamp(value / max, 0, 1) × 100%`；判定线是 1px × 10px 的 `--text` 竖线（上下各出 3px），位置 = `clamp(threshold / max, 0, 1) × 100%`。**判定线必须画在填充之上**（后绘制或 `z-index`），否则读数超过判定线时它会被填充盖住——那正好是最需要看见它的时候。超出 max 时填充截到 100%，**文字仍然是真值**（文字是权威，条只是形状）。
- 方向：`above` 的文案是「高于判定线才成立」，`below` 是「低于判定线才成立」。条本身总是从左往右按读数填充，不为 below 反向——反向条会让人以为「越满越好」。
- `observe` 不给刻度条：它没有判定「好坏」的资格，只给数字。
- 证据没有可聚焦元素；`Escape` 收起，焦点留在「证据」按钮上。展开不动画，出现即到位。
- **点击「证据」时显式 `event.currentTarget.focus()`**：WKWebView 对鼠标点击的按钮不一定给焦点，不显式聚焦的话，鼠标点开证据后按 `Escape` 没有落点。`:focus-visible` 只在键盘路径画环，鼠标用户不会看到多余焦点框。
- 证据的内边距：`var(--sp-2) var(--sp-3)`；上边距 `var(--sp-1)`；左边 2px 竖线；圆角 `--r-xs`。**没有上边框**——上面那张卡是「上边线分隔」，本卡是「凹槽 + 左刻度线」，两套语言。

### 3.3 键盘与焦点

- Tab 序：第一项「证据」→ 第一项链接（若有）→ 第二项「证据」→ …，最多 5 个停点。不做 roving tabindex，不做方向键导航：控件太少，方向键只会增加学习成本。
- 行本身不是按钮、不在 Tab 序；点事实文字不展开。这是与上面那张卡最明显的操作差异。
- 焦点环：`outline: var(--focus-ring-width) solid var(--ring)`，`outline-offset: var(--focus-ring-offset)`，`border-radius: var(--r-xs)`。两个控件都在内容区中间，离 Panel 边缘 ≥ 12px，环不会被 `overflow: hidden` 裁掉。
- 「证据」按钮内边距 `var(--sp-05) var(--sp-1)`（2/4），命中区约 30×24；链接内边距 `var(--sp-05) 0`，靠文字长度达标。inline 元素的垂直内边距不撑行盒，行高不变。
- `Escape` 只收起证据，不清除任何选中（本卡没有选中态）。
- 切窗口（7/30/90）后：`openId` 指向的规则若仍存在，证据保持展开并显示新读数；若消失，什么都不渲染，不报错。

### 3.4 ARIA

- 根：`Panel` 的 `ariaLabel="工作流体检"` → `region`「工作流体检」。
- 每项：`<li data-checkup-id data-checkup-level>`；维度名 `<h3>`，里面先放视觉隐藏的级别词（`关注：` / `留意：` / `观察：`），再放维度名。可见的级别字 `aria-hidden`，避免读两遍。
- 事实 `<p>`；「证据」是 `<button type="button">`，可访问名 `展开证据：上下文压力` / `收起证据：上下文压力`（包含可见词「证据」「收起」，满足 Label in Name）。
- 动作 `<button>`，可见文字 `打开错误档 →`；`aria-label="打开错误档，查看 Bash 的失败签名"`。箭头 `aria-hidden`。
- 证据容器：`<dl aria-label="上下文压力的判定依据">`；刻度条 `aria-hidden`，读数由可见的 caption 与 `dl` 承担。
- 没有 live region：展开是用户主动的，`aria-expanded` 已经播报；本卡没有随时间自动变化的数字。
- 颜色不是唯一通道：级别字、形状、顺序、下划线、链接文字都是第二通道。

## 4 空态与样本不足

| 状态 | 条件 | 渲染 | 文案 |
| --- | --- | --- | --- |
| 全部健康 | `checked > 0` 且无 focus/notice | **整卡不渲染** | 无。不印「一切正常」、不印「五项全过」 |
| 只有观察项 | 仅 `delegation` 触发 | **整卡不渲染** | 无。没有处方的观察不该单独占首屏 |
| 样本不足 | 有会话，但 `checked === 0` | **整卡不渲染** | 无。数据层仍返回 `status: "insufficient"` 与三个计数（供测试与将来的页头提示使用），但卡片不占版面 |
| 没有数据 | 窗口内无任何会话 | **整卡不渲染** | 页面级空态已经在说话 |

- **样本不足为什么也不渲染**（修订于实现验收）：初稿要求渲染一句「样本不足」。实际验收发现，一个有 2 个会话的窗口会因此在洞察卡之后多出一张**只有一句「数据不够」**的卡，把唯一有实质内容的周战报推出 1440×900 首屏。这张卡的全部价值是「给一个能改的动作」；样本不足时它一个都给不出，占的位置却比周战报还靠前。没有要说的就不占版面，与 `quiet` 同一条原则。
- 数据层保留 `insufficient` 状态与 `insufficient: {sessions, toolCalls, tokens}`：它是可测试的事实，将来若要放在页头做一行轻提示，不必重算。**只是卡片不渲染**。
- 因此 `--warning` 在本卡里已无使用位置。模块 CSS 不应再出现 `--warning`；若未来恢复样本不足提示，它仍是唯一正确的令牌（样本不足确实是非确定信息）。

- 全部健康时不渲染，是这个产品对「成绩单」的态度：没有要改的地方就不占版面，用户也不需要一张「你很健康」的贴纸。
- 只有部分规则样本不足、其余有结论时：卡片照常渲染有结论的项；脚注补一句 `另有 {ineligible} 项样本不足，未判定。`，不把没判的项混进「检查过」的分母。

## 5 与「值得注意的变化」并排时的节奏

两张卡上下相邻，都是 `--bg-subtle` 面板，所以必须靠**内部结构**换气：

1. **总述位置不同**：上面那张卡没有总述；本卡的表头右侧有一枚读数式总述。读者的第一眼落点不同。
2. **左边界不同**：本卡有一条贯穿的 2px 诊断轨 + 92px 维度列，形成「刻度 + 通道」；上面那张卡是全宽句子，左侧没有结构。
3. **行高与密度不同**：上面一行 28px，本卡一项 46px 且两行；眼睛会立刻知道「这里换成了更密的诊断块」。
4. **交互入口不同**：上面整行可点、右侧折角；本卡整行不可点，只有行中的「证据」和下划线链接可点，没有折角。
5. **颜色纪律不同**：上面允许错误率的红/绿箭头；本卡任何状态下都没有语义色，只有一处链接蓝。同一屏里「红只属于错误率」「蓝只属于出口」，两张卡不会互相冒充。
6. **脚注互相咬合**：上面说「与上一个等长区间比较」；本卡说「不与上一段区间比较」。两句话并排时，边界反而更清楚。

脚注定稿：

> 检查的是使用方式，不是日志文件完整性；只看绝对水平，不与上一段区间比较，也不给分、不排名。阈值与样本下限写在每项的依据里。

- 条件追加：
  - `ineligible > 0` → `另有 {n} 项样本不足，未判定。`
  - `dropped > 0` → `按严重度显示前 4 项。`
- 脚注 `--fs-xs / --lh-xs` / `--text-tertiary`；1400 宽 1 行，960 宽 2–3 行。它是本卡的「口径契约」，不收起、不进 title。

## 6 响应式、字号档、主题

### 6.1 宽度

- 整行宽度；`≤1080px` 不改结构，因为最小窗口 960 时内容区约 636px，三列（16 + 92 + 内容）仍然成立：内容列约 490px，事实与处方都能放下。
- 极窄（浏览器 e2e 可能 < 900px）：`@media (max-width: 900px)` 把三列塌成两列，维度与级别挪到事实上方：

  ```
  ┊ ●  上下文压力 · 关注
  ┊    25 / 48 个会话的上下文峰值超过 170K …
  ┊    处方 在接近上限前开新会话…
  ```

  列变成 `16px minmax(0, 1fr)`；证据仍从内容列起。桌面端最小 960，不会触发；这是给浏览器测试与未来窗口尺寸的兜底。
- 不出现横向滚动；没有卡内滚动条。
- 事实、处方、证据的 `dd` 全部允许换行，`overflow-wrap: anywhere`；唯一 `nowrap` 的是总述读数、级别字、维度名、「证据」按钮、动作链接——它们都 < 100px。

### 6.2 130% 字号档

| 位置 | 100% | 130% | 防护 |
| --- | --- | --- | --- |
| 维度名 | 5 字 ≈ 60px | 5 字 ≈ 78px | 列宽 92，`white-space: nowrap`；**不要加第 6 个汉字** |
| 级别字 | 2 字 22px | 29px | 同一列，第二行 |
| 总述读数 | ≈ 154px | ≈ 200–230px | 表头同排；标题 84 + 总述 230 + 内距 24 + gap 12 = 350 < 636 |
| 事实 | 18 行高 | 23.4 行高 | 允许折 2 行，行高由令牌派生，不写固定 height |
| 处方 | 16 行高 | 20.8 行高 | 同上 |
| 证据 `dt` | 5 字 55px | 72px | `max-content` + 内容列 ≥ 490，够 |
| 证据刻度条 | 4px | **4px（不缩放）** | 图形是「形」，不跟 `--font-scale` |
| 卡高（4 条） | 275 | ≤ 386（960 宽、脚注 3 行、事实折 1 行） | 不设 `max-height`，页面滚动 |
| 卡高（4 条 + 1 证据） | ≈ 460 | ≤ 606 | 用户主动展开；无内部滚动 |

- **最容易破的三处**：维度列写死 92 却加了 6 字标签；总述读数不换行且标题/总述挤在同一行；证据的 `dt` 用固定 px 宽度而不是 `max-content`。
- 130% 下**不减少条数、不隐藏处方**：那是数据规则，不是排版妥协。条数由严重度上限控制，不由字号控制。
- 130% 下总述读数仍 `nowrap`；若未来文案超过约 16 个汉字，改为 `normal` 并允许表头长到 2 行——当前文案不需要。

### 6.3 深色 / 高对比度

- 组件里没有主题分支，全部由令牌承担。
- 深色证据井 `--bg-inset` #0a0b0d 比面板 #14161a 更暗，凹槽方向正确；高对比度浅色 #eef1f5、深色 #000，凹槽更明确。
- 刻度条在高对比度下：轨道 `--bg-active`、填充 `--text-secondary`、判定线 `--text`，三者在两套高对比度主题里都 ≥ 7:1。
- 链接与焦点环的颜色来自 `--accent` / `--ring`；个性化强调色（teal / violet / amber / rose / green）只改这两个，不会把级别墨色带走。
- 没有 `@media (prefers-color-scheme)`：主题由应用的 `data-theme` 决定。

- `Panel`、`EmptyState`（本卡不用 EmptyState；空态由整卡不渲染承担）。
- `InsightsCard` 的「手风琴 + Escape + 焦点留在触发点」与「令牌派生行高」写法；**不要复用它的三列表、整行按钮、折角箭头**。

## 9 最容易出错的三个点

1. **把「值得改」画成红色/琥珀色**
   `--danger` 是确定的错误，`--warning` 是非确定信息，`--success` 是确定的正常读数——「这个习惯可以更好」不属于三者。一旦给级别上色，卡就从诊断变成训话，而且会和「值得注意的变化」里唯一允许的红/绿箭头撞语义。正确解是**形状 + 墨色 + 级别字**三通道；整卡唯一的颜色是「打开错误档」这个真实出口。样本不足不再有引导词（整卡不渲染），所以本卡零语义色。

2. **把质变算成量变：压缩频率与缓存命中率的分母**
   压缩频率的分母是「有记录的会话」，不是 `compactionStats.sessions`（发生过压缩的会话）；缓存命中率的分母是 `input + cacheCreation + cacheRead`，不是周报的 `input + cacheRead`。借错分母不会报错，只会得到一张看起来合理、与卡内证据对不上的事实句——这正是这张卡最不能犯的错。顺便：Issue 正文的 `12 / 48` 与 `19 / 48` 两个示例都恰好不越线（25.0% 不大于 25%，0.396 不大于 0.40），夹具不要照抄。

3. **又做成一张「一行一句 + 整行展开」的列表**
   如果行是整行按钮、右侧放折角、展开区是三列表，它就会变成「值得注意的变化」的第二份。必须守住：92px 维度列 + 2px 诊断轨、两行（事实 / 处方）、整行不可点、行内「证据」文字按钮、证据是 `dl` + 4px 刻度条而不是对照表、空态是整卡不渲染而不是一句「一切正常」。

> 其余容易漏的：事实取整、证据一位小数，但压缩证据要两位小数（`0.46`）否则看不出与 `0.40` 的差；`error-focus` 的份额分母是全部工具失败、失败率分母是该工具调用，两个 149 与 761 不能混；4 条上限要在数据层做且先挤掉 observe；`summary` 的分子不受显示上限影响；只有 observe 触发时整卡不渲染；跳转后焦点要落在「错误」标签而不是 `<body>`。
