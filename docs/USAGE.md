# 使用手册

从拿到应用到用上每个功能的完整说明。

## 获取应用

### 方式一：下载构建产物（推荐）

到 [Releases](https://github.com/liang-zhenxiang/cc-analyzer/releases) 页面下载对应平台的产物：

| 平台 | 产物 | 说明 |
| --- | --- | --- |
| macOS Apple Silicon | `CC-Analyzer_<版本>_aarch64.dmg` | |
| macOS Intel | `CC-Analyzer_<版本>_x64.dmg` | |
| Windows x64 | `CC-Analyzer_<版本>_x64-setup.exe` | 安装程序：装到用户目录，带开始菜单项与卸载入口，**不需要管理员权限** |
| Windows x64（便携版） | `CC_Analyzer_x64_portable.zip` | 解压即用，不写注册表、无需安装 |

macOS：打开 dmg，把 **CC Analyzer** 拖到窗口里的 `Applications` 快捷方式上。
产物使用 ad-hoc 签名，首次打开若被 Gatekeeper 拦截，右键 →「打开」即可（只需一次）。

Windows：**推荐用安装程序**（`-setup.exe`），双击后按提示完成即可。如果是
放到 U 盘随身携带、或不允许安装到系统的场景，用便携版 zip 解压后直接运行
`CC Analyzer.exe`。

### 方式二：从源码构建

见 [README 的 Build 一节](../README.md#build-from-source)。三个平台都走
Tauri 官方打包流程：

```bash
npm install                # 构建工具链（Tauri CLI）
npm run build:macos:arm64  # 或 build:macos:intel / build:windows
```

## 系统要求

- macOS 10.13+（Intel）/ macOS 11+（Apple Silicon）
- Windows 10+
- 应用分析的数据来自本机 Claude Code 的会话目录（`~/.claude/projects`），
  本机安装过 Claude Code 并产生过会话即可

## 快捷键与全局搜索

- **⌘K / Ctrl+K**（或顶栏放大镜按钮）唤起全局搜索：跨全部项目搜索**四类内容**——
  你的指令与助手回复、工具输出正文、工具调用里的文件路径、工具报错文本。结果按
  项目 → 会话分组，↑↓ 选择，Enter 跳转到该会话并定位记录、展开详情，Esc 关闭。

  每条命中最左边是**来源标签**（我 / 助手 / 工具输出 / 文件路径 / 错误），输入框下方
  一行**来源过滤器**可以只留其中几类——找文件时点「文件路径」那一档噪声最小；也可以
  直接在输入框里敲前缀（`路径:` `错误:` `我:` `助手:` `输出:`），边打边切档。

  几条口径值得知道：工具输出在入索引前会**剥掉终端转义序列**，所以搜 `[31m` 不会再
  命中一堆控制字节；单条工具输出最多索引 2000 个字符（超出部分不参与搜索）；匹配是
  **大小写不敏感的子串**，不做模糊匹配与排名——先解决「找不到」。索引在后台渐进构建
  （面板内显示已索引的会话数与条目数），**纯内存不落盘、不上传**；命中路径在应用内
  按原样显示（搜索不导出、不进日志，脱敏会让「为什么这条命中」无从核对）。

## 软件更新

「设置 → 软件更新」里可以选择更新渠道并检查更新：

- **稳定版**（默认）：维护者人工验证后发布的版本。
- **Beta**：每轮新功能自动构建的先行版，接受先行体验与不稳定性再选。

更新检查只是读取 GitHub 发布页的一次下载请求，不上传任何数据（详见
SECURITY.md）。启动时自动检查默认开启，可在此关闭；发现新版后可一键
「安装并重启」，安装包经签名校验。

## 功能总览

应用围绕「AI 编码会话回顾」组织，顶部工作区标签在「会话分析」「用量总览」
「实时监控」三类页面之间切换（设置是浮层面板，不是第四个标签）。

### 会话分析

1. 左侧会话列表按 **时间线（今天 / 昨天 / 本周 / 本月 / 更早）** 与
   **项目** 分组，可折叠；列表顶部可在「时间线」与「项目」两种分组方式
   之间切换，会显示标题补全进度。
2. 双击会话进入分析页。页首是会话头（标题 · 总耗时 · 项目 · 相对时间 ·
   打开位置）。
3. **Token 计数**：点会话头里的「Token 计数」展开（默认折叠）。四类计数
   各占一行——输入 / 缓存写入（5 分钟与 1 小时 TTL 二级展开）/ 缓存读取 /
   输出，每行标出它读自哪个日志字段，以及它在四类合计中的占比。
   **四类计数不合并，也不显示「总 token 数」**：它们的量级能差三个数量级，
   加起来不代表任何东西。本面板**不含金额**——应用不内置定价表，算不出来时
   明确写「成本未知 · 未收录该模型定价」，而不是给一个 0 或留空。
4. **日志视图**：一行一个活动（用户 / LLM / 工具 / Agent / workflow /
   「等用户」间隙行），带耗时、占比、瀑布列；支持按行类型、成败状态、
   时长区间与自由文本筛选。token 列是**提示词总量**（输入 + 缓存写入 +
   缓存读取），悬停可见拆分。
5. **耗时树**：Agent 与 workflow 子会话以树形展开，时长按图解析；
   勾选「仅分析所选时间块」可以只看选中的时间范围。
6. 日志与树**双向定位**：在树里点一条记录，日志滚动过去，反之亦然。
7. **记录详情**：单条记录展开可见结构化结果、子会话预览，以及
   「用 claude 分析此子 agent」入口。
8. **终端输出保真**：工具输出（`Bash` 等）在日志里是带 ANSI 转义序列的
   原文。展开行与右侧详情面板会**按转义语义渲染**——16 基本色用主题调色板
   （浅色/深色各一套）、256 色与真彩色原样呈现、加粗/暗淡/斜体/下划线/
   删除线/反显都成立，用 `\r` 覆盖写的进度行按终端行为收敛到最后那一段。
   表格单元、「复制摘要」、CSV 与 HTML 报告则一律是**剥掉转义后的纯文本**：
   屏幕上看到的字就是能搜到、能粘出去的字。

### 分析报告

- 点击「生成分析报告」，应用会把结构化摘要交给本机 `claude` CLI，
  返回 Markdown 报告（表格、代码块、列表均有渲染，代码块带语法高亮）。
- 报告大纲固定：概述 / 耗时分桶 / 慢工具 / 错误 / 子代理 / 工作流 /
  并行度 / 文件地图 / 证据。
- 生成过程中可点「停止分析」取消；生成结束后按钮消失是预期行为。
- 可以只对某个子 agent 或选中的时间块生成报告（节点级分析）。

### 导出与分享

打开会话后，头部「导出」按钮会弹出一个浮层，把一个会话导成两种产物：

- **HTML 报告**（默认）——单文件、自包含：不引任何外链、不带脚本、用系统
  字体栈渲染，断网打开也完整；浅色/深色跟随系统，打印时自动去掉底色并重复
  表头。文件里带 CC Analyzer 字标与仓库地址，适合直接发给同事。
- **CSV** —— 逐条记录，固定 13 列（`record_id` / `timestamp` / … / `summary`），
  UTF-8 带 BOM、CRLF 行尾，Windows Excel 打开中文不会乱码。

范围可选「当前筛选结果」（默认，即筛选命中的那批记录）或「全部记录」；
浮层顶部会写清楚这次将导出多少条，两个范围导出的是不同批数据、不只是换个
文件名。条数是**记录级**的：表格会把「用户 + LLM」这类相邻行合并成一行，
所以导出的记录条数可能略多于屏幕上的表格行数。超过 2000 条时只导出前
2000 条，并在浮层里明示，不会静默截断。「保存…」走系统保存对话框（HTML
文件名形如 `cc-analyzer-<会话前缀>-filtered.html`），「复制到剪贴板」则把
同一份内容放进剪贴板——CSV 这一路不带 BOM，避免粘贴结果里混进不可见字符。

CSV 里以 `=`、`+`、`-`、`@` 开头的摘要会自动加一个前导单引号：表格软件
会把这类字段当公式求值（CWE-1236），而这份文件是给人用 Excel 打开的。

导出物只包含该会话自身的数据与项目**目录名**：不含完整路径、不含其它会话、
不含原始 JSONL 原文。记录原文与完整工具输出出于体量考虑不导出。

### 本地归档

Claude Code 会自动清理约 30 天前的历史，所以「上个月 / 去年用了多少」这类问题
不能只靠 `~/.claude`。设置里的「本地归档」（**默认关闭**）打开后，点一次
「立即归档」就会：

- 把每个会话的 JSONL **复制**一份到应用数据目录的 `archive/<项目>/<会话>.jsonl`，
  并写一份索引记录原路径、大小、**原始时间**与归档时刻；
- 首次是全量，之后按 mtime / 大小做增量——重复点只有变化过的会被重新复制；
- 归档完成后会话列表会自动刷新，来自归档的会话带一枚「归档」标记。

几件可以放心的事：

- **不动原始文件**：`~/.claude` 下的会话既不移走也不改写，归档只是多留一份副本；
- **纯本地**：不联网、不上传，也不内置任何遥测；
- **时间仍是原始时间**：会话列表的分组、相对时间与用量趋势都按会话**发生**的时刻算，
  不是按备份时刻；
- **失败会说出来**：单个文件复制失败会列出原因；索引损坏会就地提示（下一次归档会重建）。

开关关掉只是停止归档，**已经归档的副本会保留**——它们正是你不想丢的那部分。

### 归档包：换机器时把历史带走

本地归档默认只在这台机器上。要把历史搬到另一台机器：设置 → 本地归档 → 「导出归档包…」，
设一个口令（输两次）、选保存位置，得到一个 `.ccabundle` 单文件。

到了另一台机器：设置 → 本地归档 → 「导入归档包…」，选文件、输口令，应用会在弹层里给出读数
（新增 / 已存在 / 并列 / 失败）。两条规则值得记住：

- **同一份包导入两次是安全的**：第二次会全部报「已存在」，不会重复。
- **同一会话在两台机器各自继续过**，两份都会留下——会话列表里会看到它出现的两个时间点。
  我们**不覆盖**任何一份，宁可多留也不丢。

关于口令与隐私，四句话说完：

- 口令**不保存在任何地方**，关掉窗口就没了；**没有找回的办法**，忘了就是打不开这个包。
- 加密、打包、解密与搬运**都在本机完成**，不上传、不联网。
- 包是**标准的 age 格式**，命令行 `age -d` 同样能解开它——数据不被这个应用绑架。
- 包放在哪里，就按哪里的敏感度对待它：它是一份加密的会话记录。

导入只写应用自己的归档目录，**绝不改动 `~/.claude` 里的原始文件**；解密用的临时目录无论成败都会清掉。

### 用量总览

切到「用量总览」标签，应用会逐个解析本机会话并渐进聚合（扫描中会显示
「已分析 N / M 个会话」，已分析的部分先呈现；再次进入命中解析缓存，
即时出图）。页面内容：

1. **KPI 读数行**：所选时间范围内的 Tokens 总量、会话数、消息数与估算
   成本。每个数字带来源徽章——前三项标「读自日志」，估算成本标
   「按定价快照估算」并注明快照日期。
2. **时间范围**：近 7 / 30 / 90 天三档切换，趋势、分布与热力图随之更新。
3. **每日 Token 消耗**：按天柱状图，可在 全部 / 输入 / 输出 / 缓存写入 /
   缓存读取 之间切换——四类计数量级相差很大，合并成一个数字看不出
   这天到底烧在哪。
4. **消耗日历（近 12 个月）**：GitHub 贡献图形态的滚动 365 天网格，一眼
   读完这一年哪些天在烧、烧得有多凶。两条口径事实：**窗口固定滚动
   12 个月，不随上方的区间选择器变化**（脚注写明）；**色深 = 当日估算
   成本的四分位档**（0 档 = 无消耗，图例就是刻度的一部分）。悬停给出
   日期 · 估算成本 · token · 会话数 · 项目的完整读数；点击某天在网格
   下方展开**一日回望**，再点收起。

   **一日回望**由两层组成。上面一行是**当天摘要**：当日消耗（成本与 token 双数）、
   会话数、消息数、**活跃跨度**（当天首条→末条记录的时刻，不是「有活动的小时数」）、
   最常用模型、涉及项目数——每个数字带来源徽章，口径脚注随行。下面是**24 小时时间线**：
   一行一个会话，左边是项目色点与标题，中间是 24h 轨道（实色基线标出这一天里它活跃的
   时间段，每个有记录的整点小时立一块活动块，块高 4 / 8 / 12px 对应 1–2 / 3–5 / ≥6 条
   记录，空缺就是间歇），右边给起止时刻、时长与当日的 `$成本 · token · 占比`。行按起点
   排序，**点行直接打开那个会话**；跨午夜的会话按记录时间切，只画落在当天的那段并标
   「跨天」；单会话、零跨度会话与「这一天没有任何记录」都有如实的形态。键盘同样可达：
   方向键按天 / 按周
   移动，Home / End 跳行首尾，Enter 展开，Escape 收起。窗口不够宽时
   横向滚动收在日历自己的容器里，文档不会被撑宽。

   图例之下还有一行**一年洞察**——从滚动 365 天数据自动生成的六句实事：最长连胜、
   当前连胜、最贵一天、最长空白、活跃占比、本月环比（等长对齐窗：本月前 N 天 vs
   上月同期 N 天）。两条口径事实：**「有消耗」与格子 0 档同档**（当日估算成本 > $0，
   **定价未知的天不计入有消耗**，数字能逐格对上）；并列（最长连胜 / 最长空白 /
   最贵一天）一律取最近一段。句内的日期可点击下钻到一日回望（与格子点击同一条
   状态，再点收起）；当前连胜分三态如实说——今天还没有消耗时报「此前连续 N 天」，
   不预设今天结束。每句的完整口径挂在悬停 title 上。
5. **按项目 / 按模型分布**：Top N 水平条形与堆叠占比条，尾部归入「其他」。
6. **活跃时段（7×24）**：以消息数为热度的热力图，回顾工作节律。

7. **5 小时计费窗口仪表**：当前窗口的消耗表盘、开启时刻、关闭倒计时，
   以及按消耗速度外推的「预计到达限额时刻」。窗口口径与 ccusage 的
   `blocks` 一致（首条活动起算 5 小时）；订阅计划在「设置 → 计费窗口」
   选择，限额为社区整理的估算值（非官方）；运行不足 30 分钟的窗口会
   明示「样本不足」而不是外推一个看起来很自信的时刻。
8. **本窗口消耗 Top 会话**（在 5 小时窗口卡里）：这个窗口是谁在烧——每个会话
   一行（标题、窗口内消耗、占比条、占比百分比），按消耗降序，**点一行就打开
   那个会话**。超过 5 个会话时最后一行是「其余 N 个会话」的合并值，占比表不会
   看起来漏账。

   **占比分母 = 本窗口总消耗**，也就是表盘中心那个数：两者出自同一个窗口读数，
   所以不会互相打架。一条规则值得知道：**跨窗口的会话按记录时间被切开**——同一
   会话前一半在刚关闭的那个窗口、后一半在这个窗口，两边各算各的，不会被整条记
   到某一个窗口里。这一块只读本机日志、不做任何推算，也不联网；目前只归因
   5 小时窗口，周窗口与按模型 / 工具的切分留给后续。
9. **导出快照**：用量页头部右上角有一个「导出快照」——把当前区间下的 KPI、
   每日趋势、按项目 / 按模型分布、活跃时段热力图、两层限额与本窗口 Top 会话，
   导出成**一个 HTML 文件**。

   这份文件是**自包含**的：零脚本、零外链资源、所有文本都转义、只出现项目目录名
   （不出现完整路径），双击就能在浏览器里看，也可以直接发给同事或归档进仓库。
   数据口径跟着一起走——哪些数字读自日志、哪些是按定价快照估算的，文档里都写着，
   生成时刻与数据窗口分开标注。「本快照包含 / 不含」那行是特意写的：页面上还有
   消耗日历、工具与 skill 普查、压缩统计、错误档，这四块**不在**快照里，免得
   收到文件的人以为这就是整页仪表盘。

   与其它导出一样：不联网、不上传、不生成分享链接——文件在你手上，你自己搬。

关于**估算成本**的口径：

- 成本 = 各模型四类 token 分别按内嵌离线定价快照（USD / 百万 token）
  计价后求和，**是估算、不是账单**；订阅套餐的实际计费方式（限额、
  5h 窗口等）不在此模型内。
- 定价快照带日期，随界面明示；应用**不会联网**更新价格，升级快照
  随应用版本整体替换。
- 快照未收录的模型不计价：读数旁会写「部分会话未知价」并给出未计入
  的量，而不是把它们当成 0。

### 里程碑

「用量总览」标签页内的分段控件有**三档**：`用量 | 里程碑 | 错误`。里程碑档回答的是
前三档都没回答过的问题——**「我这一路走到哪了」**。它不是又一张图表，而是把**全历史**
用量折成一组**能从本机日志逐条核对**的事实：**每枚徽章都必须能被日志复算，复算不出来
就不发这枚徽章**。所以这一档没有排行榜、没有分享链接、没有撒花动画。

口径就写在页首，逐字这么一句：**全部已扫描的会话纳入统计，含本地归档；不含 Claude Code
已清理且未归档的会话**——我们只能对读到的日志负责。两个推论值得先知道：这一档**不显示
时间范围控件**（「近 7 / 30 / 90 天」对全历史没有任何作用，摆一个不起作用的控件会让人
以为数字受它影响）；它也**不新增任何扫描**，吃的是用量档同一次扫描的全历史结果，所以
在这个标签页里来回切档不会重新读一遍日志。

三组事实从上到下依次回答「从哪儿开始」「走了多远」「峰值在哪」：

1. **首次**（≤ 5 枚）：第一次会话、第一次压缩、第一次用子 agent、第一次用 skill、
   第一次用 MCP 工具。每枚给**日期**（`YYYY-MM-DD`）与一个**可点入口**。原料不存在的
   （比如从没用过 skill）**整枚不列**，这一组下面会写一行原因（例如「本机日志里没有
   skill、MCP 工具的调用记录，这两枚不列」）——**不显示成「未达成」**：「你还没用过」
   与「离达成还差多少」是两件事，后者归下一组。
2. **累计阶梯**（7 枚）：累计 token、累计会话数、累计消息数、涉及项目数、用过模型数、
   累计压缩次数、工具种类数。每枚给当前值、档位读数（`N/M 档`）、一条**本档 → 下一档**
   的距离条与一行距离文字（`还差 12.4M 到 100M`）。档位是**写死的常量**，逐条列在这里：

   | 阶梯 | 四档 / 三档门槛 |
   | --- | --- |
   | 累计 token | 1,000,000 / 10,000,000 / 100,000,000 / 1,000,000,000 |
   | 累计会话数 | 1 / 10 / 100 / 1,000 |
   | 累计消息数 | 100 / 1,000 / 10,000 / 100,000 |
   | 涉及项目数 | 1 / 5 / 10 / 25 |
   | 用过模型数 | 1 / 3 / 5 |
   | 累计压缩次数 | 1 / 10 / 100 |
   | 工具种类数 | 1 / 5 / 15 |

   距离条画的是**本档到下一档**这一段走了多远，不是「当前值 ÷ 最终档位」的全程进度
   ——刚起步时那会变成一根看得见的毫毛，把「我在这一档里走了多远」埋掉。
3. **单会话记录**（3 枚）：单会话最多 token、单会话最长时长、单会话最多压缩次数。
   每枚给值、是哪个会话（标题 + 日期）与一个点进去打开它的入口；并列（同值）时取
   **更早达成**的那一个，口径行写明。单日口径（最贵一天之类）不在这里，它归
   「消耗日历 / 一年洞察」。

**未达成的阶梯项怎么读**：它不给灰色剪影、不给锁、不给「??」。形态上是两处差别——
距离条上没有那截填充（0px 对 ≥2px，一个与颜色无关的几何事实），以及档位读数
（`0/4 档` 对 `3/4 档`）。**未达成项的当前值一个字都不降权**：同字号、同字重、与已达成项
同一个文字色。理由是简单的一条——高对比度档下灰阶会塌缩，状态只靠「灰一档」就没了。
已经到最高档的那几枚写「**已到最高档**」，不留白、也不假装还有下一档。

**点入口去哪**：两个入口各回各的家，且与既有页面走同一条握手——

- **会话标题**（首次类的证据行、记录类的证据行）→ 切到「会话分析」并落到那个会话。
  卡片上的数字与点进去看到的记录出自**同一份日志**，与压缩统计 Top3 是同一条握手。
- **日期**（记录类的副读数，`YYYY-MM-DD`）→ 切回「用量」档，并把**那一天**在消耗日历里
  展开成一日回望。它与日历格子点击、洞察句里的日期链接共用同一份展开状态（面板内部
  仍然是唯一的状态源，页面只是发一个「请展开这一天」的请求）。

这一档的四种状态都如实：扫描中沿用用量页的骨架（**不出现「0」这种假读数**）；一个会话
都没有时给一整页**说清事实的空态**（「还没有可以回顾的里程碑」+ 为什么是空的），而不是
「0 枚徽章」的空货架；读取失败沿用用量页那套错误态（含「重试」与详情里的原始错误串）；
有会话但某几枚算不出来（例如日志里没有任何 skill 调用），能算的照算，算不出的整枚不
渲染并给一行原因。

**刻意不做的事**，两条值得说明：

- **不做累计成本**。金额来自内嵌的定价快照，而「定价未知的天不计入」会制造一个**看不见
  的低估**——同一屏上的数字会有不同的完备性。里程碑的全部价值就是「这个数是全的」，
  所以累计成本继续由 KPI「估算成本」与日历色深承担，不在这里发第二枚徽章。
- **不做连胜 / 最贵一天 / 活跃占比**。那六句住在日历图例之下，口径是**滚动 365 天**；
  里程碑的口径是**全历史**。同一个概念有两个窗口，同屏就会出现两个打架的数字——所以
  一个概念只在一处出现。

### 菜单栏读数

两层用量可以常驻在 **macOS 菜单栏**（Windows 为托盘图标）：

- **图标旁的文字只放一个读数**：设了预算就是当前 5 小时窗口的百分比（接近限额、超出预算时
  前置半角 `!`，如 `!91%` / `!112%`）；没设预算就是已用 token 的紧凑写法（`88k` / `1.2M`）——
  没有分母就不显示百分比，这条在托盘上也一样。
- **悬停给出完整读数**：5 小时窗口一行、窗口还有多久关闭一行、滚动 7 天一行，最后一行是
  **这份读数是几分钟前算的**与来源（读自本地日志）。读数里的百分比来自限额——那是社区估算值
  或你自设的数字，所以含估算时会在末尾单列一行说明：**估算不会只靠颜色或图标暗示**。
- **更新时机**：应用启动、每分钟一次、设置变化，以及用量总览扫描出新数据时。全程读本机日志、
  **不联网**；也不驻留后台——关掉窗口应用即退出，读数随之消失。
- **不想要它**：设置 → 常驻读数 → 关掉「显示用量读数」。关掉的只是显示，用量总览与所有统计
  口径完全不受影响，随时可再打开。

### 实时监控

「实时监控」标签里有**两个子视图**，页内分段控件在它们之间切换：默认的
**脉搏**（原生视图，纯读本机日志）与**外部仪表盘**（你自行运行的服务）。

#### 脉搏（默认）

脉搏不联网、不新增任何请求，只把本机 `~/.claude` 日志按「此刻」重新组织，四块
面板从上到下依次回答三个问题：

1. **5 小时窗口**：当前计费窗口的一排五个读数——`已用`、`窗口关闭`（含还剩多久）、
   `窗口平均`（速率，单位 tokens/小时）、**`近 15 分钟`（窗口内的实测速率，不是外推）**、
   `预测触顶`（按当前速度预计触达限额的时刻）。这里**不画表盘、不出现百分比**；
   窗口开启不足 30 分钟时速率与预测都显示「样本不足」，没在「设置 → 阈值设置」里
   填 5 小时预算时预测显示「未设预算」。**这份 `已用` 与用量总览表盘的数字逐位相等**
   ——同一份日志、同一个窗口函数。
2. **最近 60 分钟**：每分钟一根柱的 token 速率曲线（四类 token 之和）。**最后一根是
   进行中的这一分钟**，用斜纹填充 + 虚线描边画出，绝不当作一个整分钟、也不外推；
   曲线右端有一条「现在」参考线。
3. **活跃会话**：最近 5 小时内有新记录的会话，一行一个——标题、项目、
   「N 秒 / 分钟前有新记录」以及三档新近度。**点一行直接打开那个会话**（切到会话
   分析并落到该会话）。一句口径随行常显：**这只说「多久前有新记录」，不代表会话
   正在运行**——一个长时间执行、期间不写日志的工具调用，在这里会被如实记成「更早」。
4. **上下文填充**：最近那个活跃会话最近 40 次调用喂给模型的上下文规模曲线
   （输入 + 缓存读 + 缓存写），压缩处标出断崖。参考带取**最近至多 5 次自动压缩前
   体量的区间**（至少 3 次才画，否则写「样本不足」）。**这里不画官方上下文上限，
   也不预测「还能撑几分钟」**——参考带是实际发生的压缩前体量，不是阈值。

四种状态都有如实形态：首拍未回来时是加载骨架，没有会话时是整页空态，读不到日志
时是整页错误态（原始异常串只在展开的「详情」里）；**已经拿到读数之后这一拍失败**
则**保留上一次读数**、状态行标「上次更新 时刻 · 本次读取失败」并给「重试」。
刷新在视图可见时自动进行，读取失败不清空旧数据；单拍变慢会自动把间隔拉长。

#### 悬浮（置顶小窗）

脉搏页头有「悬浮」按钮，点它把窗口切进置顶浮窗（适合常驻副屏当桌面小组件）：

- 浮窗态下**整条顶栏收起**，换成一条细头——拖动区（用鼠标按住细头即可拖动窗口）、
  标题「实时脉搏」与「退出浮窗」按钮。浮窗是无系统边框的窗口，细头是唯一能拖动它
  的地方。
- 布局收紧到 ≤420px 宽：四块面板**一块不少**（纵向滚动到达），窗口不出现横向溢出。

#### 外部仪表盘（子视图）

切到「外部仪表盘」这一步**不会自动打开**，点「打开监控」才探测并内嵌本机
`localhost` 上运行的仪表盘页面；连上后工具栏有「关闭监控」，可回到未打开的状态。
该仪表盘服务**不在本仓库内**，需要另行运行——页面会写明应用要连接的地址
（默认 `localhost:8090`），把服务启动起来再点「打开监控」。探测失败会重试 3 次，
然后给出一句说明、原始错误串的「详情」与「重试」按钮；不需要这个功能就不点它。
仪表盘也可以通过 `postMessage` 请求把窗口切进「浮窗模式」（小窗置顶），
浮窗状态下顶栏照常显示「退出浮窗」按钮。

### 设置

顶栏齿轮打开设置面板，可调分析预算（提示词大小、明细行数、慢工具条数、
子代理数量、解析分块、日志窗口行数）。这些值持久化在本机应用数据目录。

面板第一节是**界面字号**：五档 90% / 100%（默认）/ 110% / 120% / 130%，
点一下立即生效，选择记在本机。缩放只作用在文字上——字号与行高成对变化，
表格、读数行、报告与图表标注一起变大，而间距、图标与表盘尺寸保持不动，
所以放大的是可读性，不是整屏等比放大。选过的档位下次启动同样生效；想改回来，
点 `100%` 即可（它就是这一节的复位）。

紧挨着的是**界面对比度**：**普通**（默认）与**高对比度**。高对比度把语义色与类别色
两套令牌一起换掉——正文文字对底至少 17.4:1、次要文字 7.29:1、边框 3.83:1（相对亮度
实算，门槛 7 / 4.5 / 3），焦点环也加粗到 3px、与控件之间留 2px 底色间隙（深色按钮上
没有这圈间隙，环就只剩一侧能看见）。它**只改颜色与焦点环**：字号、间距、控件尺寸都
不动——高对比度不是放大。没做过显式选择时，应用跟随系统的「提高对比度」偏好
（`prefers-contrast: more`）；你手动选过之后，以你的选择为准，并记在本机。

两条边界写在明处：导出的会话报告与用量快照是独立文档，本轮仍用自己的调色板；Windows
的强制高对比度（`forced-colors`）也还没处理。

## 数据与隐私

- 会话数据只在本机解析与展示，应用不内置任何遥测或网络上传。
- 「生成分析报告」会把**结构化摘要**交给本机 `claude` CLI，由你配置的
  模型服务处理；对数据流向敏感时请收紧设置里的报告预算，或不使用该功能。
- 应用自身的状态（标题缓存 `meta-cache-v2.json`、阈值、主题）存储在
  应用数据目录（bundle id `io.github.liang-zhenxiang.cc-analyzer` 对应的
  application-support 目录），不写入 Claude Code 的原始数据。
