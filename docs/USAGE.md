# 使用手册

从拿到应用到用上每个功能的完整说明。

## 获取应用

### 方式一：下载构建产物（推荐）

到 [Releases](https://github.com/liang-zhenxiang/cc-analyzer/releases) 页面下载对应平台的产物：

| 平台 | 产物 | 说明 |
| --- | --- | --- |
| macOS Apple Silicon | `CC-Analyzer_<版本>_aarch64.dmg` | |
| macOS Intel | `CC-Analyzer_<版本>_x64.dmg` | |
| Windows x64 | `CC-Analyzer_<版本>_x64-setup.exe` | 安装程序：装到用户目录，带开始菜单项与卸载入口，**不需要管理员权限** |
| Windows x64（便携版） | `CC_Analyzer_x64_portable.zip` | 解压即用，不写注册表、无需安装 |

macOS：打开 dmg，把 **CC Analyzer** 拖到窗口里的 `Applications` 快捷方式上。
产物使用 ad-hoc 签名，首次打开若被 Gatekeeper 拦截，右键 →「打开」即可（只需一次）。

Windows：**推荐用安装程序**（`-setup.exe`），双击后按提示完成即可。如果是
放到 U 盘随身携带、或不允许安装到系统的场景，用便携版 zip 解压后直接运行
`CC Analyzer.exe`。

### 方式二：从源码构建

见 [README 的 Build 一节](../README.md#build-from-source)。三个平台都走
Tauri 官方打包流程：

```bash
npm install                # 构建工具链（Tauri CLI）
npm run build:macos:arm64  # 或 build:macos:intel / build:windows
```

## 系统要求

- macOS 10.13+（Intel）/ macOS 11+（Apple Silicon）
- Windows 10+
- 应用分析的数据来自本机 Claude Code 的会话目录（`~/.claude/projects`），
  本机安装过 Claude Code 并产生过会话即可

## 快捷键与全局搜索

- **⌘K / Ctrl+K**（或顶栏放大镜按钮）唤起全局搜索：跨全部项目搜索会话
  消息，结果按项目分组；↑↓ 选择，Enter 跳转到该会话并定位记录、展开详情，
  Esc 关闭。索引在后台渐进构建（面板内显示进度），纯内存不落盘。

## 软件更新

「设置 → 软件更新」里可以选择更新渠道并检查更新：

- **稳定版**（默认）：维护者人工验证后发布的版本。
- **Beta**：每轮新功能自动构建的先行版，接受先行体验与不稳定性再选。

更新检查只是读取 GitHub 发布页的一次下载请求，不上传任何数据（详见
SECURITY.md）。启动时自动检查默认开启，可在此关闭；发现新版后可一键
「安装并重启」，安装包经签名校验。

## 功能总览

应用围绕「AI 编码会话回顾」组织，顶部工作区标签在「会话分析」「用量总览」
「实时监控」三类页面之间切换（设置是浮层面板，不是第四个标签）。

### 会话分析

1. 左侧会话列表按 **时间线（今天 / 昨天 / 本周 / 本月 / 更早）** 与
   **项目** 分组，可折叠；列表顶部可在「时间线」与「项目」两种分组方式
   之间切换，会显示标题补全进度。
2. 双击会话进入分析页。页首是会话头（标题 · 总耗时 · 项目 · 相对时间 ·
   打开位置）。
3. **Token 计数**：点会话头里的「Token 计数」展开（默认折叠）。四类计数
   各占一行——输入 / 缓存写入（5 分钟与 1 小时 TTL 二级展开）/ 缓存读取 /
   输出，每行标出它读自哪个日志字段，以及它在四类合计中的占比。
   **四类计数不合并，也不显示「总 token 数」**：它们的量级能差三个数量级，
   加起来不代表任何东西。本面板**不含金额**——应用不内置定价表，算不出来时
   明确写「成本未知 · 未收录该模型定价」，而不是给一个 0 或留空。
4. **日志视图**：一行一个活动（用户 / LLM / 工具 / Agent / workflow /
   「等用户」间隙行），带耗时、占比、瀑布列；支持按行类型、成败状态、
   时长区间与自由文本筛选。token 列是**提示词总量**（输入 + 缓存写入 +
   缓存读取），悬停可见拆分。
5. **耗时树**：Agent 与 workflow 子会话以树形展开，时长按图解析；
   勾选「仅分析所选时间块」可以只看选中的时间范围。
6. 日志与树**双向定位**：在树里点一条记录，日志滚动过去，反之亦然。
7. **记录详情**：单条记录展开可见结构化结果、子会话预览，以及
   「用 claude 分析此子 agent」入口。

### 分析报告

- 点击「生成分析报告」，应用会把结构化摘要交给本机 `claude` CLI，
  返回 Markdown 报告（表格、代码块、列表均有渲染，代码块带语法高亮）。
- 报告大纲固定：概述 / 耗时分桶 / 慢工具 / 错误 / 子代理 / 工作流 /
  并行度 / 文件地图 / 证据。
- 生成过程中可点「停止分析」取消；生成结束后按钮消失是预期行为。
- 可以只对某个子 agent 或选中的时间块生成报告（节点级分析）。

### 用量总览

切到「用量总览」标签，应用会逐个解析本机会话并渐进聚合（扫描中会显示
「已分析 N / M 个会话」，已分析的部分先呈现；再次进入命中解析缓存，
即时出图）。页面内容：

1. **KPI 读数行**：所选时间范围内的 Tokens 总量、会话数、消息数与估算
   成本。每个数字带来源徽章——前三项标「读自日志」，估算成本标
   「按定价快照估算」并注明快照日期。
2. **时间范围**：近 7 / 30 / 90 天三档切换，趋势、分布与热力图随之更新。
3. **每日 Token 消耗**：按天柱状图，可在 全部 / 输入 / 输出 / 缓存写入 /
   缓存读取 之间切换——四类计数量级相差很大，合并成一个数字看不出
   这天到底烧在哪。
4. **按项目 / 按模型分布**：Top N 水平条形与堆叠占比条，尾部归入「其他」。
5. **活跃时段（7×24）**：以消息数为热度的热力图，回顾工作节律。

6. **5 小时计费窗口仪表**：当前窗口的消耗表盘、开启时刻、关闭倒计时，
   以及按消耗速度外推的「预计到达限额时刻」。窗口口径与 ccusage 的
   `blocks` 一致（首条活动起算 5 小时）；订阅计划在「设置 → 计费窗口」
   选择，限额为社区整理的估算值（非官方）；运行不足 30 分钟的窗口会
   明示「样本不足」而不是外推一个看起来很自信的时刻。

关于**估算成本**的口径：

- 成本 = 各模型四类 token 分别按内嵌离线定价快照（USD / 百万 token）
  计价后求和，**是估算、不是账单**；订阅套餐的实际计费方式（限额、
  5h 窗口等）不在此模型内。
- 定价快照带日期，随界面明示；应用**不会联网**更新价格，升级快照
  随应用版本整体替换。
- 快照未收录的模型不计价：读数旁会写「部分会话未知价」并给出未计入
  的量，而不是把它们当成 0。

### 实时监控

- 顶部工作区切换到「实时监控」后**不会自动打开**，点「打开监控」才探测并内嵌
  本机 `localhost` 上运行的仪表盘页面；连上后工具栏有「关闭监控」，
  可回到未打开的状态。
- 该仪表盘服务**不在本仓库内**，需要另行运行。探测失败会重试 3 次，
  然后给出失败说明与「重试」按钮；不需要这个功能就不点它。
- 仪表盘可以通过 `postMessage` 请求把窗口切进「浮窗模式」
  （小窗置顶）；浮窗状态下顶栏有「退出浮窗」按钮。

### 设置

顶栏齿轮打开设置面板，可调分析预算（提示词大小、明细行数、慢工具条数、
子代理数量、解析分块、日志窗口行数）。这些值持久化在本机应用数据目录。

## 数据与隐私

- 会话数据只在本机解析与展示，应用不内置任何遥测或网络上传。
- 「生成分析报告」会把**结构化摘要**交给本机 `claude` CLI，由你配置的
  模型服务处理；对数据流向敏感时请收紧设置里的报告预算，或不使用该功能。
- 应用自身的状态（标题缓存 `meta-cache-v2.json`、阈值、主题）存储在
  应用数据目录（bundle id `io.github.liang-zhenxiang.cc-analyzer` 对应的
  application-support 目录），不写入 Claude Code 的原始数据。
