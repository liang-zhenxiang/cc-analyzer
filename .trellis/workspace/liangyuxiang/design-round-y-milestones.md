## 1. 裁决 A：已达成 / 未达成怎么区分（几何与层级）

### 1.1 先把术语写死，后文只用这三条

| 术语 | 定义 | 举例 |
| --- | --- | --- |
| **达成项** | 有**可查证的锚点**的一枚 | 首次类的每一枚（有那个第一次）、记录类的每一枚（有那个极值会话）、阶梯里**已跨过至少一档**的那些 |
| **未达成项** | **阶梯里一档都没跨过的那些**（`已达 0/N 档`） | 本机 3 个会话、40 条消息 → 「累计消息数」档位 100/1k/10k/100k，实测 `0/4 档` |
| **距离条** | 6px 高的横向轨道：剩余段 `--chart-1-soft` + 已达段 `--chart-1` 实色 | §2 |

「未达成」**只有这一种形态**，理由是它必须与 R3 / R4 对齐：

- 首次类**没有未达成形态**——原料不存在就整枚不渲染（R3），不是「还差多少才第一次用 skill」。
- 记录类**没有未达成形态**——有会话就有极值。
- 阶梯**必须**有未达成形态——阈值写在常量表里，本机数据完全可能一档都没到。

### 1.2 裁决：两态的差别落在**「墨迹范围」**与**「档位读数」**两个通道上，而不是同一个版式换一种灰

一枚阶梯单元的第 3 槽（值槽之下、距离行之上）恒是一条**距离条**。两态在它上面分叉：

| 通道 | 达成项（`已达 ≥ 1 档`） | 未达成项（`已达 0 档`） |
| --- | --- | --- |
| **填充（形）** | `data-probe="milestone-fill"` **在场**，宽 = `max(2px, 本档→下一档的比例 × 轨道宽)`，实色 `--chart-1` | **整个填充元素不渲染**（`0px` 的填充等于「画了一点点进度」，那是在撒谎） |
| **轨道剩余段（形）** | 一条 `--chart-1-soft` 的底，右端到轨道尽头 | 同一条底，**占满整条** |
| **档位读数（文字）** | `3/4 档`（tabular） | `0/4 档`（tabular） |
| **距离行（文字）** | `还差 87.6M 到 100M` | `还差 60 到 100` |

**为什么这算「几何与层级」，不算「灰一档」**：

1. **填充的有无是一个布尔几何事实**，不是透明度差。`2px` 与 `0px` 之间没有中间态——
   它要么有一个实心方块，要么一件墨都没有。四个主题下 `--chart-1` 都是实色
   （浅 `#2f6b9f` / 深 `#82b5e8` / HC 浅 `#1c567f` / HC 深 `#7cb8f0`），不依赖任何 alpha。
2. **整条轨道的可见性不靠底线对比**：轨道底是 `--chart-1-soft`（复合后 1.41 / 1.87 /
   1.38 / 2.11），与日历的 `--cal-1` 空格（`#cfdaf5`，约 1.36）是同一个量级，它是
   **有色底**不是发丝线。HC 两档另有 1px `--border-strong` 描边兜底（§2.4）。
3. **两个通道同时在场**：只靠文字能判态（`0/4 档`），只靠形状也能判态（没有实心块），
   而这两个通道在**灰度截图、色觉障碍、四个主题**下都恒定。
4. **`--text-tertiary` 之类的「浅一档」只用在文字的三级层级上**（口径行、脚注），
   从不参与状态区分——状态的墨水是 `--chart-1` 与它的 `-soft` 底，与文字阶梯无关。

### 1.3 为什么这样读起来是「仪表」而不是「游戏」

逐条对照，每条都能在版式上指出落点：

| 游戏的招数 | 本页的做法 |
| --- | --- |
| 二元跳变（已解锁 / 未解锁） | **连续的尺**：已达成的刻度有实心块，未达成的刻度是空的刻度线，两段在同一条轨道上共存 |
| 把未达成的数字藏起来（灰剪影、`??`、锁定图标） | **当前值不降权**：达成项与未达成项的值槽是**同字号、同字重、同位置、同一个 `--text`**。R4 禁止剪影，而「把事实降一档」正是剪影的第一步 |
| 奖励语言（恭喜 / 解锁 / 继续加油） | 文案全是**事实陈述**：`2026-05-31`、`还差 87.6M 到 100M`、`已到最高档`。**全页没有一个感叹号** |
| 徽章只能给你一句「你解锁了 X」 | **证据行可以点进去核对**：首次 / 记录类的第 3 槽就是一条通往那个会话（或那一天）的按钮 |
| 装饰几何（星星、奖杯、丝带、进度环） | 本轮新增的几何只有两件：一条 **6px 直线**、一条 **1px 描边**（只在 HC 两档）。没有圆点阵列、没有分档刻度、没有百分比环 |
| 达成瞬间的庆祝 | **零动效**（§12）。页面不会为任何一枚里程碑动一下 |

### 1.4 「阶梯为什么不做分档刻度」

轨道上**不画 4 个等分刻痕**，即使那样看起来更像仪表。两条理由：

1. **档位门槛不是等差的**：`1M / 10M / 100M / 1B`、`1 / 10 / 100 / 1000`、
   `100 / 1k / 10k / 100k` 是十进制等比数列，等分刻痕在视觉上是对的、但**在数值上是巧合**；
   `1 / 5 / 10 / 25`（项目数）与 `1 / 3 / 5`（模型数）连巧合都不成立，等分刻痕会直接撒谎。
2. **对数刻痕要第二套数学**：按 `log10(档位 / 第一档)` 定位刻痕是正确的，但那会要求展示层
   自己算一个「档位 → 像素」的映射，而 `design.md §4` 明令**组件不做任何判定**、
   `§3.1` 明令 `HistoryFacts` 里只放事实。为一个装饰性刻度破这条规矩不划算。

刻度信息改由**文字**承担：值槽右端的 `3/4 档` + 距离行的 `还差 … 到 100M`。

## 2. 裁决 B：阶梯的进度用「长度」，不是色深、也不是块高

### 2.1 三条候选与裁决

| 语言 | 既有归属 | 能不能借 |
| --- | --- | --- |
| **色深**（`--cal-1..4`） | 消耗日历：当日估算成本四分位 | **不能**。它编码的是「量级分类」而不是「进度」；借走会让日历的色带同时表示两件事 |
| **块高**（4 / 8 / 12px） | 一日回望：整点小时的活动密度 | **不能**。它编码的是**离散分档的密度**，而阶梯的进度是**连续**的（12.4M / 100M），三档高度只能表达粗粒度 |
| **长度**（横向条的填充） | 日志表占比条、归因行占比条、周预算条 | **借得**，而且是这条家族线上唯一还没被占用的通道 |

### 2.2 与既有长度的关系：同一个「形」，三处的口径各自标注

`--chart-1` 实色窄条已经在仓库里出现两次（`.weeklyBarFill` 4px、`.attributionBarFill` 6px），
本页是**第三处**。三处问的问题不同，形相同：

| 位置 | 轨道回答的问题 | 口径标注在哪 |
| --- | --- | --- |
| 周预算条 | 本周已用 ÷ 周限额 | 行内 `$12.40 / $50.00` |
| 归因行占比条 | 这条会话占本窗口消耗的比例 | 行内百分比 + 脚注分母 |
| **里程碑距离条** | **本档 → 下一档走到了哪**（band 进度，不是全程进度） | 距离行 `还差 … 到 …` |

**「band 进度」是这条轨道的定义**：填充比例 =
`(当前值 − 本档门槛) / (下一档门槛 − 本档门槛)`。不画「当前值 ÷ 最终档位」的全程进度——
那会让刚起步的 `12.4M / 1B` 变成 1.2% 的一根毫毛，把「我在这一档里走了多远」这条最有用的
信息埋掉。未达成项（0 档）的 band 是 `[0, 第一档门槛]`，填充比例 = `当前值 / 第一档门槛`
——**但它不画**，见 §1.2 的裁决。

### 2.3 色值：零新增令牌

| 部位 | 令牌 | 备注 |
| --- | --- | --- |
| 轨道（整条，6px，`--r-xs` 圆角） | `--chart-1-soft` | 大面积填充只许 `-soft`（既有硬规矩） |
| 已达段的填充 | `--chart-1` | 6px 窄条用实色是既有豁免（同占比条 / 周预算条） |
| HC 两档的整条描边 | `--border-strong` | 见 §2.4 |
| 值 / 名称 / 档位 / 距离 / 口径 / 入口 | 全走 `--text*` 与 `--accent` | §8.3 表 A |

**为什么轨道底不用 `--border-strong`**（这是与既有两条进度条**不一致**的一处，请主会话复核）：

| 候选轨道底 | 填充 vs 轨道底（浅 / 深 / HC 浅 / HC 深） | 结论 |
| --- | --- | --- |
| `--border-strong` 复合色 | **3.84 / 5.53 / 1.19 / 1.27** | HC 两档**低于图形门槛 3**，填充与轨道在纯黑/纯白底上塌成一团 → **否** |
| `--bg-inset`（凹槽语义） | 5.07 / 9.12 / 6.90 / 9.97 | 填充对比很好，但轨道自身 vs 面板底只有 **1.11 / 1.09 / 1.13 / 1.12**——HC 浅下「这里有一条轨道」看不见，也就读不出「走了多远」→ **否** |
| `--chart-1-soft` 复合色 | **4.00 / 4.48 / 5.66 / 4.21** | 四主题全部过 3，且**整条轨道始终有色**（不是凹槽）→ **采用** |

### 2.4 高对比度两档的补救：整条轨道加 1px `--border-strong` 描边

浅色调的 `-soft` 在纯白底上只有 1.38（HC 浅），与日历那轮「半透明阶梯在纯白上相邻档塌缩」
是同一类问题。日历的补救是**给每格加 1px 描边**，本页照办，但**用 `--border-strong`
而不是 `--border`**——因为这里的对照物是 `-soft` 段而不是纯白：

| 描边色 | vs `-soft` 段（HC 浅 / HC 深） | vs 面板底 | 结论 |
| --- | --- | --- | --- |
| `--border` 复合色 | 3.50 / **1.95** | 4.83 / 4.12 | HC 深**不过** 3 → 否 |
| `--border-strong` 复合色 | **6.71 / 3.31** | 9.27 / 6.99 | 两档都过 → **采用** |
| 普通浅 / 普通深 | **不加描边** | — | 与日历同款取舍：「普通档刻意不加——描边会把色块阵列变成表格」 |

落地写法（与 `UsageCalendarPanel.module.css` 的既有分支同款，只有一处）：

```css
/* 轨道是 overflow: hidden 的圆角盒，inset 阴影会被填充盖住下半条；
   描边加在轨道外层的壳上（或一个绝对定位的 ::after 层），不占布局。 */
:global([data-contrast="high"]) .trackShell {
  box-shadow: 0 0 0 1px var(--border-strong);
}
```

**不许写成 `outline: 1px …`**：`focusRing.test.ts` 的字面量守卫
（`/outline(?:-width)?:\s*-?\d+(?:\.\d+)?px/`）会把它当成一个没走令牌的焦点环拦下（§14.1 第 7 条）。

## 3. 裁决 C：成本类里程碑 —— **本轮不做**

`design.md §4` 留了口子：「成本类（若设计保留）必须带 `ProvenanceBadge provenance="inferred"`
与『按定价快照折算』的口径句；定价未知的天不计入」。裁决是**不做**，四条理由：

1. **它是唯一一个「复算不出来」的数**。PRD 的 Goal 逐字：「**每枚徽章都必须能被日志复算，
   复算不出来就不发这枚徽章**」。另外七项阶梯读的都是日志本身（`totalsSum` / 事件计数 /
   去重集合），而累计成本读的是**一张会过期的定价表**。把它混进同一屏，R1 那句承诺就从
   「全部可核对」降级成「大部分可核对」——一句带例外的话，读起来就是一句广告词。
2. **「定价未知的天不计入」会制造一个看不见的低估**。用户看到 `$412`，而有 8% 的 token
   没有定价；这不是加一枚圆点能解决的，它让同一屏上的数字有了**不同的完备性**
   （token 类 100% 完备，成本类 <100%）。里程碑的全部价值恰恰是「这个数是全的」。
3. **情绪最强的数字配最弱的地基**是最糟的组合。按用户提示，「累计成本」是这一页情绪最强的
   数字；正因为它最响，它的口径必须最硬。
4. **它已经有承担者**：累计成本由用量总览的 KPI「估算成本」（带
   `ProvenanceBadge provenance="estimated"` + `快照日期 2026-10-01`）与消耗日历的色深承载，
   用户不是没有地方看它。里程碑这一页新增的是**锚点**，不是又一个金额。

### 3.1 备选（若主会话判定要保留）

只做**一枚**（`tier-cost`「累计估算成本」），且必须同时满足：

- 挂在**阶梯组的最末位**（第 8 枚），不新开第四组、不破坏「首次 / 阶梯 / 记录」三组结构；
- 名称行右端挂 `ProvenanceBadge provenance="inferred"`（10px 圆点，既有画法，不新造徽章）；
- 口径行逐字：`按定价快照折算`（完整句 `按 2026-10-01 的定价快照折算；定价未知的天不计入`
  进 `title` / `aria-label`）；
- 值走 `formatUsd`，距离行**不给 token 单位**（单位换来换去会让同一行的三个数字读起来是三种量）；
- 档位表另立（`$10 / $100 / $1000 / $10000`），并接受「最后一段没有上限含义」这件事。

**我不推荐这条**：它会让阶梯组出现一枚口径与其他七枚不同构的卡片，而口径是否同构正是
「游戏徽章」与「可核对事实」的分界线。

## 4. 层级与布局

### 4.1 页面骨架

```
UsageOverviewPage（既有，受控 view）
├─ .page
│  ├─ .header
│  │   ├─ .headerControls → SegmentedControl（用量 | 里程碑 | 错误）
│  │   │                    ＋ 时间范围控件（**里程碑档不渲染**）
│  │   └─ .headerActions   → 进度行（三档共用，文案按档分叉）
│  │                          ＋ 导出按钮（**仅用量档**，既有逻辑不动）
│  ├─ {view === "milestones"} →
│  │   MilestonesPanel                       [data-probe="milestones-view"]
│  │   ├─ .scope                             [data-probe="milestones-scope"]
│  │   ├─ Panel「首次」        [data-probe="milestones-group" data-group="firsts"]
│  │   ├─ Panel「累计阶梯」    [data-probe="milestones-group" data-group="tiers"]
│  │   └─ Panel「单会话记录」  [data-probe="milestones-group" data-group="records"]
│  └─ {view === "usage" | "errors"} → 既有分支不变
```

三条与本页骨架有关的裁决：

1. **里程碑档不渲染时间范围控件**。「近 7 / 30 / 90 天」对全历史口径（R2）没有任何作用；
   留一个不起作用的控件比留一个缺的控件更坏——用户会以为数字受它影响。这与脉搏那轮
   「浮窗里不出现分段控件」是同一条立场：**不摆在台面上的控件，就不会被误会**。
2. **进度行按档分叉文案**（右簇位置不动，避免切档时整页横跳）：
   - 用量 / 错误（既有）：`近 30 天内 12 个会话纳入统计`
   - 里程碑：`全部 128 个已扫描会话纳入统计`
3. **空态要让位**：`UsageOverviewPage` 现在那条 `!scanning && inputs.length === 0 &&
   progress.total === 0` 的整页早返回**是 view 无关的**，里程碑档会摸到用量档的
   「还没有可统计的会话」。实现把条件收窄成 `… && view !== "milestones"`（一行），
   让里程碑档渲染自己那句（§7.1）。**不要**去改那条文案本身——它会连带改掉用量档与错误档
   的既有截图与断言。

### 4.2 三组的顺序与权重

| 序 | 组 | 回答的问题 | 枚数 | 权重（视觉） | 顺序理由 |
| --- | --- | --- | --- | --- | --- |
| 1 | 首次 | 从哪儿开始 | ≤ 5 | **最低**（一枚只有日期 + 一个目标） | 它是**起点叙事**，也是全页最短的一组（一枚 4 行、一组一行网格） |
| 2 | 累计阶梯 | 走了多远 | 7 | **最高**（页面主体：值 + 档位 + 轨道 + 距离 + 口径，5 行） | 它是「用量随时间」的主轴，也是用户回访这一页的目的 |
| 3 | 单会话记录 | 峰值在哪 | 3 | 中（值 + 日期 + 会话 + 口径，4 行） | 收尾：从「累计」落到「单次」，从总量落到具体的那个会话 |

顺序与 PRD R3 的列举顺序一致（起点 → 过程 → 峰值），也与 `design.md §1` 的分层一致。
**不做四组**、**不把阶梯提到最前**：把阶梯放第一会让这一页在首屏就变成一张 7 行的表，
而「第一次」那一句正是用户打开这一页最先想看的东西（它是这一页唯一的叙事）。

### 4.4 为什么 15 枚里程碑是「无框网格单元」而不是 15 张小卡

1. **卡中卡是硬禁令**（Round W §1.3）：三组住在 `Panel` 里，单元若再套 `--bg-subtle` + 边框
   就是第二层卡片；若退成 `--bg-inset` 内嵌块，15 个灰块会把这一页变成一张表单。
2. **单元的内容是「一行事实」，不是「一块可操作的工具」**。仓库里同构的先例有三处：
   `CompactionStatsPanel .reading`（读数带里每一格都无框）、
   `BillingWindowCard .readouts`（四个读数无框）、
   `UsageCalendarPanel .daySummary .summaryItem`（日摘要每格无框）。
3. **无框 → 网格 gap 就是全部层级语言**，与「安静、可核对」的调性同向：页面里只有三张
   `Panel` 的边框，其余全是墨。

## 5. 单枚里程碑的内部结构

### 5.1 两种单元版式

**锚点类（首次 / 记录）——4 行**：

```
┌ 名称（--fs-xs / --text-secondary，单行省略）         ┐ 槽 1
│ 值（--fs-md / 600 / tabular / --text）   [副读数]   │ 槽 2（副读数右对齐）
│ ◆ 证据行（整行 <button>，打开会话 / 那一天）         │ 槽 3 ← 锚点
└ 口径行（--fs-xs / --text-tertiary，单行省略）        ┘ 槽 4
```

**阶梯类——5 行**：

```
┌ 名称                                                 ┐ 槽 1
│ 值                              [3/4 档]             │ 槽 2（档位读数右对齐）
│ ▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░   │ 槽 3 ← 6px 距离条
│ 还差 87.6M 到 100M                                   │ 槽 4
└ 口径行                                               ┘ 槽 5
```

两套版式的**同一个位置**（槽 2 右端）承担「副读数」：阶梯放档位、记录放日期、首次留空。
这是全页唯一的「值 + 副读数」格子语言，与 `.summaryItem`（值独占第二行、标签在第一行）同族。

**所有行都是单行**（`white-space: nowrap` + `overflow: hidden` + `text-overflow: ellipsis`），
因此**同一组内所有单元等高、所有轨道落在同一条基线上**——这一条不是巧合而是契约，
真机门禁按它断言（§11.2 第 1 条）。

### 5.2 三类各自的逐字内容

#### 首次类（`data-milestone` 前缀 `first-`）

| 键 | 名称（逐字） | 值槽 | 副读数 | 证据行（可点） | 口径行（逐字） |
| --- | --- | --- | --- | --- | --- |
| `first-session` | `第一次会话` | `2026-03-14` | — | `◆ {会话标题}` → 打开会话 | `会话日志的首条记录` |
| `first-compaction` | `第一次压缩` | `2026-05-31` | — | `◆ {会话标题}` → 打开会话 | `首个压缩边界记录` |
| `first-subagent` | `第一次用子 agent` | `2026-06-02` | — | `◆ {子 agent 类型或会话标题}` | `首个 Agent / Task 调用` |
| `first-skill` | `第一次用 skill` | `2026-06-18` | — | `◆ {skill 名}` | `首个 Skill 工具调用` |
| `first-mcp` | `第一次用 MCP 工具` | `2026-07-04` | — | `◆ {server}/{tool}` | `首个 mcp__ 前缀调用` |

- **值 = 日期**：首次类问的是「什么时候」，日期就是它的值。格式 `YYYY-MM-DD`（§5.3）。
- **证据行 = 目标名**：`◆` 是 `--chart-1` 的**文字形**（同 `.topDiamond`），其后是目标名，
  整行是一个 `<button>`。
- **目标优先级**（R3 允许两类）：有 `SessionMeta` → 打开那个会话（复用用量页 `onOpenSession`
  的既有握手）；没有会话元数据但有日期 → 退到「那一天」的一日回望（与日历 / 洞察句同一条
  下钻状态）；两者都没有 → **整行渲染成不可点的 `<span>` 而不是 disabled 按钮**
  （`InsightDate` 的既有立场：「点了没有任何反馈的控件是坏交互」）。

#### 阶梯类（`tier-`）

| 键 | 名称 | 档位表（写死常量，见 design.md §3.3） | 口径行逐字 |
| --- | --- | --- | --- |
| `tier-tokens` | `累计 Token` | 1M / 10M / 100M / 1B | `四类 token 之和` |
| `tier-sessions` | `累计会话数` | 1 / 10 / 100 / 1000 | `本地日志去重会话` |
| `tier-messages` | `累计消息数` | 100 / 1k / 10k / 100k | `用户与助手消息` |
| `tier-projects` | `涉及项目数` | 1 / 5 / 10 / 25 | `去重项目目录` |
| `tier-models` | `用过模型数` | 1 / 3 / 5 | `去重模型 id` |
| `tier-compactions` | `累计压缩次数` | 1 / 10 / 100 | `压缩边界记录` |
| `tier-tools` | `工具种类数` | 1 / 5 / 15 | `去重工具名` |

- **值**：token 走 `formatTokenCount`，其余计数走 `toLocaleString("en-US")`
  （与用量页 KPI「会话数」逐字同款）。
- **副读数**：`{已达}/{总档数} 档`，tabular。
- **距离行**：`还差 {formatTokenCount(下一档 − 当前值)} 到 {formatTokenCount(下一档)}`；
  已达最高档 → `已到最高档`（R4 明令：不留白）。
  **单位词不写进行内**——单位由口径行承担（`四类 token 之和` / `本地日志去重会话`）。
  理由：`还差 87.6M 到 100M` 比 `还差 87.6M token 到 100M` 短约 40px，
  而 130% 字号下这两行都只差一线。
- **没有入口按钮**。阶梯不对应任何一个可打开的会话——给一个假入口比不给入口坏。
  「可核对」由**同源**承担：口径行写明它与用量总览的 KPI 出自同一份 `inputs` 与同一个
  求和函数（`totalsSum`）。这句话也写进 §5.4 的面板脚注。

#### 记录类（`record-`）

| 键 | 名称 | 值槽 | 副读数 | 证据行 | 口径行逐字 |
| --- | --- | --- | --- | --- | --- |
| `record-session-tokens` | `单会话最多 Token` | `formatTokenCount` | `2026-10-02` | `◆ {会话标题}` → 打开会话 | `单会话四类之和最大` |
| `record-session-duration` | `单会话最长时长` | `formatDuration` | `2026-09-28` | 同上 | `首末记录时间差最大` |
| `record-session-compactions` | `单会话最多压缩次数` | `toLocaleString("en-US")` | `2026-08-11` | 同上 | `单会话边界记录最多` |

- 记录类的**日期放在副读数**（不是值槽）：这类问题的值是「多少」，日期是它的坐标。
  首次类相反的取舍理由见上一张表。
- 并列规则（`design.md §3.4`：同值取**时间更早**的那个）写进面板脚注，不写进单元。

### 5.3 日期格式：全历史窗口一律带年，`YYYY-MM-DD`

日历那轮的规则是「同年省略年份、跨年带年份」，前提是那张图**有年份表头**（滚动 365 天）。
里程碑没有那个前提（R2 的全历史可能跨年），而「哪一年」在这里是事实的一部分。因此：

- **行内一律 `YYYY-MM-DD`**（`2026-05-31`）：等宽、tabular、与 CHANGELOG / 文档里的日期一致；
  `--fs-md` 600 下 10 个字符在 130% 时约 **107px**，落在 216px 的最小格宽里绰绰有余。
- **完整句子进 `title` 与可访问名**：`2026年5月31日`（沿用日历「年号必须有可靠落点」的原则）。
- **不新增共享格式化函数**：`new Date(ts)` 取 `getFullYear/getMonth/getDate` 拼装是本页唯一需要
  的日期拼装，放在 `MilestonesPanel.tsx` 内部并注明「与 `insightDateText` 同源、差别只在
  带年策略」。`formatDayLabel` 的 `5/31` 不带年、`formatDateTime` 是带秒的 `zh-CN` 长格式，
  两者都不合这一处的用途——**这一条偏离了 `design.md §4` 的「日期走 `formatDayLabel`」，
  请主会话复核**（§14.2 已列为复核项之一，理由与替代方案在那里）。

### 5.4 面板脚注（三张各一条，逐字）

| 面板 | 脚注逐字 |
| --- | --- |
| 首次 | `只列出本机日志里真实发生过的第一次；没有记录的第一次不占位。` |
| 累计阶梯 | `档位是写死的常量；距离 = 下一档门槛 − 当前值。数字与用量总览的 KPI 出自同一份已扫描会话与同一个求和函数。` |

## 6. 首次类：原料不存在时整枚不渲染，「缺席」怎么不显得像缺图

「你还没用过 skill」与「离达成还差多少」是两件事（R3）。版式上要兑现这句话，五条一起做：

1. **网格用 `auto-fit`，缺一枚就少一格**（§4.6）。等分列留下的空洞正是「缺图」的观感。
2. **面板标题与任何位置都不出现 `3 / 5` 这种分母**。分母会把缺席变成「两枚没解锁」——
   那正是 R3 禁止的读法。**枚数只在脚注的一句话里出现**（下一条）。
3. **缺席说明写在组的脚注位，按组一条，不按枚逐条**（R6 的「一行原因」）：
   `[data-probe="milestones-gap-note"]`，逐字
   `本机日志里没有 skill、MCP 工具的调用记录，这两枚不列。`
   （名字按实际缺席项拼接、用顿号；只有一枚时写「这一枚不列」。）
4. **整组全缺席 → 该组不渲染 Panel**（不出现空货架），改由**页尾一条事实行**承担：
   `[data-probe="milestones-gap-note"]`，逐字 `本机日志里没有压缩 / 子 agent / skill / MCP
   记录，首次里程碑暂无可列的事实。`（措辞按实际缺的项拼。）
5. **缺席不占用任何高度预算**：没有占位符、没有虚线框、没有灰块。缺的那一格就是网格里的
   下一枚。

这是「一条事实行」与「一个空架子」的差别：空架子会让人去找「我少做了什么」，事实行只告诉你
「日志里没有这件事」。

## 7. 四态

四态的**位置分工**是这一节的核心：状态属于**页面**，不属于单元。

| 态 | 触发 | 落在哪 | 长相与文案（逐字） |
| --- | --- | --- | --- |
| **加载** | 首扫尚未回来（`scanning && progress.total === 0`） | 页级早返回（既有） | `EmptyState size="page" title="正在扫描会话列表…"`——**与用量页逐字同款**，里程碑档零新增骨架、不出现任何 `0` |
| **空** | 扫到 0 个会话 | 视图内（§4.1 第 3 条让位后） | **整块一条事实行**：`EmptyState size="page"`，标题 `还没有可以回顾的里程碑`，描述 `本机 ~/.claude/projects 下没有会话记录。产生一次会话后，这一页会从日志里折出第一次、累计阶梯与单会话记录。`。三张 Panel **一张都不渲染** |
| **失败** | 扫描失败（`error` 非空） | 页级早返回（既有） | 既有的整页 `ErrorState size="page"`（`会话列表读取失败` / hint / `detail` 默认不进 DOM / `onRetry` 重启扫描）——**与用量页同一套，不另造错误语言** |
| **数据不足** | ≥ 1 个会话，但某几枚算不出 | 组内 | **能算的照算**；算不出的整枚不渲染 + 组脚注一行原因（§6 第 3 / 4 条）。**不使用任何灰块或占位** |

### 7.1 三条与实现有关的边界

1. **视图内不再画第二个错误态**。里程碑与用量、错误两档共用同一次扫描、同一个 `error`；
   页级 `ErrorState` 已经覆盖三档，组件里再画一个就会出现「同一屏两种错误画法」。
   组件契约因此只有 `{ report, onOpenSession, onOpenDay }`——**没有 `error` / `loading` 入参**。
2. **`report.empty === true` 时视图渲染那条整块事实行**（防御态，正常不可达——页级早已拦下）。
   沿用 `.dayEmpty` 的既有立场：「正常不可达的防御态也只说一句实话」。
3. **渐进扫描期间里程碑随进度行一起长**。`useUsageOverview` 是渐进填充的，里程碑与 KPI 出自
   同一份 `inputs`、同一拍渲染，因此两者**不会一前一后**。这是既有取舍（KPI 也这么长），
   **不加「等扫完再显示」的闸门**——加了反而会让里程碑与它左边的进度行、上方的 KPI
   落在不同时点。

### 8.1 结论先写：**零新增令牌，`tokens.css` 一行都不改**

### 8.2 公式与门槛（可复算）

```
通道归一化 c = 分量 / 255
通道线性化 = c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ^ 2.4
L = 0.2126*R + 0.7152*G + 0.0722*B
对比度 = (L_亮 + 0.05) / (L_暗 + 0.05)

半透明令牌写成「复合等效色」：c = fg * a + bg * (1 - a)，逐通道
```

与 `tokens.test.ts` 里既有的 `luminance` / `contrast` 两个辅助函数同源（Round U §3.1 立的
规矩）。**门槛**：正文文字 ≥ 4.5、大字 / 图形 ≥ 3；项目自身另有更严的约定（正文 ≥ 7、
次要 ≥ 4.5、三级 ≥ 4.5、图形 ≥ 3），下表逐行写出档位。

**底色约定**：单元住在 `Panel` 体里，**底 = `--bg-subtle`**（浅 `#ffffff` / 深 `#14161a` /

## 9. 字号 130% 与 960 / 1100 窄窗

### 9.1 字号与「形」的分工

- 本文件只**消费** `--fs-*` / `--lh-*`，不写裸 px 字号；字号与行高成对乘 `--font-scale`
  （tokens.css 的既有机制）。
- **「形」不随字号缩放**：轨道高 6px、格最小宽 216px、`◆` 字形、面板表头 40px 都是形。
  130% 下单元从 82 / 92px 长到 **103 / 113px**，轨道仍 6px——**同一组里「同样长的一段填充」
  在任何字号档都表示同一件事**。
- **不新增换行**：所有行都是单行 + 省略号（§5.1）。130% 下不会出现「第二名挤到第二行」，
  因此**同组等高**这条契约在 130% 下自动成立。

### 9.2 横向不溢出的账（960 窗 + 130% 字号）

```
960（窗）
 − 24（页 --sp-3 × 2）
 = 936（页面内容宽）
936 − 2（Panel 边框 1px × 2）
    − 24（Panel 体 --sp-3 × 2）
 = 910（网格可用宽）
910 + 16（一个 --sp-4 列间隙）= 926 ÷ (216 + 16) = 3.99 → 3 列
每格 = (910 − 2 × 16) / 3 = 292.67px
```

再把视口收窄到 e2e 用的 **800px**（比应用 `minWidth: 960` 更狠一档）：

```
800 − 24 − 2 − 24 = 750；750 + 16 = 766 ÷ 232 = 3.30 → 3 列
每格 = (750 − 32) / 3 = 239.33px
```

130% 下最长的单行串逐条估算（CJK 全宽 ≈ 1em、数字 ≈ 0.55em、`M` ≈ 0.72em、
空格 ≈ 0.25em；`--fs-xs` 11 × 1.3 = 14.3px、`--fs-md` 15 × 1.3 = 19.5px）：

| `累计压缩次数`（最长名称，6 字） | **85.8** | 名称行 | ✓ |
| `首个 Agent / Task 调用`（最长口径） | 28.6 + 3.6 + 90 + 3.6 + 28.6 = **154.4** | 口径行（有省略号兜底） | ≤ 239.3 ✓ |
| `2026-05-31`（首次类值槽） | 19.5px 档 10 字符 ≈ **107** | 值槽 | ≤ 239.3 ✓ |
| 值槽 + 副读数（`48.2M` + `2026-10-02`） | 57 + 8 + 79 = **144** | 槽 2 一行两列 | ≤ 239.3 ✓ |
| `4h12m30s` | 8 × 7.87 = **63**（`--fs-md` 档约 84） | 记录类值槽 | ✓ |

**结构性保证**（不靠上面这些估算）：网格轨道全是 `minmax(0, 1fr)`，没有一处 `min-width`；
所有文本行 `min-width: 0` + `overflow: hidden` + `text-overflow: ellipsis`。
因此横向溢出在结构上不可达，真机门禁在 `[data-probe="milestones-view"]` 上量
`scrollWidth <= clientWidth` 作为保险（§11.2 第 3 条）。

### 9.3 130% 下不裁行

单元固定 `min-height: var(--ms-tile-h)`，而 `--ms-tile-h` 里的每一段都乘了同一个
`--font-scale`（通过 `--lh-*`），所以 130% 下盒子跟着长；**不写死 px 行高**是 Round W
「修正二」的照搬。真机几何断言加一条：每枚单元 `scrollHeight <= clientHeight + 1`。

## 10. 无障碍

### 10.1 每枚是一个可读的语义单元

- 三组各是一个 `Panel`（`ariaLabel` = 具名 landmark），组内的单元是 `<li>`，列表是 `<ul>`。
  读屏按「区域 → 列表 → 项」三层跳。
- 单元内部**按 DOM 顺序朗读**：名称 → 值 → 副读数 →（阶梯）进度 → 距离 → 证据 / 入口 → 口径。
  不给 `<li>` 加 `aria-label`（`listitem` 不支持命名，硬加会造出第二个名字）。

### 10.2 值 / 口径 / 入口的可访问名

| 部位 | 可访问名 |
| --- | --- |
| 值 | 文本即名；`title` 放**全精度原值**（`String(value)` / 原始毫秒），沿用 `formatTokenCount` 的既有立场 |
| 副读数（档位） | `title` = `已达 3 / 4 档`；文本 `3/4 档` |
| 副读数（日期，记录类） | `title` / `aria-label` = `2026年10月2日` |
| 口径行 | 文本即内容；**省略号截断时完整句必须在 `title` 上**（`.attributionFootnote` 的既有做法：「宽度不够时省略号截断的是补充说明，不是分母本身」） |
| 证据行（可点） | `<button aria-label="打开会话：{会话标题}" title="打开会话 · {标题} · {YYYY年M月D日}">`——**完整句子在可访问名里**，与 `ProvenanceBadge` 的立场一致（视觉给短、读屏给全） |
| 证据行（无目标，不可点） | 渲染 `<span>`，**不是 disabled 按钮**（`InsightDate` 的既有立场） |

### 10.3 阶梯进度的语义：`role="progressbar"` 带真实值

轨道用**真值**而不是 0–100 的百分比：

```html
<span class="track" data-probe="milestone-track" role="progressbar"
      aria-valuemin="10000000" aria-valuemax="100000000" aria-valuenow="12400000"
      aria-valuetext="12.4M，距 100M 还差 87.6M">
  <span class="fill" data-probe="milestone-fill" style="width: 2.7%"></span>
</span>
```

- `aria-valuemin` / `aria-valuemax` 是**本档门槛 / 下一档门槛**（不是 0 / 100），因此读屏
  播报的区间与距离行说的是同一件事；`aria-valuetext` 用 `formatTokenCount` 拼同一句话。
- **未达成项（0 档）走同一条 progressbar**：`aria-valuemin="0"`、
  `aria-valuemax="{第一档门槛}"`、`aria-valuenow="{当前值}"`——它的真实值就是当前值。
- **已达最高档：不渲染 `role="progressbar"`**，轨道 `aria-hidden="true"`，语义由距离行的
  `已到最高档` 承担。理由：`min === max` 的进度条是一个假控件。
- **整条轨道不可聚焦、不进 Tab 序**（它没有交互）。

### 10.4 键盘与焦点

- Tab 序：分段控件 → 首次组的证据行（每枚一个按钮）→ 记录组的证据行 →（页级错误态时）重试。
  **阶梯组没有可聚焦元素**（§5.2 的裁决）。
- 证据行是**全宽按钮**（宽度 = 单元宽，而不是内容宽），焦点环用
  `outline-offset: var(--focus-ring-inset)`（负偏移）——正偏移的环会被列表容器的 `overflow`
  裁掉（`.dayRow` / `.pulseRowButton` 两处的既有做法）。
- 不需要新的 Escape 行为：本页没有展开 / 收起的浮层。

### 10.5 装饰件的 `aria-hidden`

`◆` 记号、轨道壳里不承载语义的部分、以及任何纯装饰元素都不朗读。`<Icon>` 自带
`aria-hidden="true"`（既有实现）。

### 11.2 几何事实（真机门禁量什么，逐条可对账）

1. **同一组内所有轨道落在同一条基线上**：同一 `data-group` 的 `milestone-track` 的

2. **两态**：`[data-state="reached"] [data-probe="milestone-fill"]` 的 `offsetWidth ≥ 2`；

3. **三档主题**：`milestones-view` 的 `scrollWidth <= clientWidth`（浅 / 深 / HC 浅 / HC 深
   四块各量一次）；130% 字号下再量一次。
4. **不裁行**：每枚单元 `scrollHeight <= clientHeight + 1`（130% 下尤其要量）。
5. **枚数**：`data-milestone` 的键集合 = 夹具算出来的集合（阶梯恒 7 枚；首次 / 记录按夹具）。

## 12. 动效

### 12.1 裁决：**本轮零新增动效**

1. 本页**没有「正在发生」的东西**可以呼吸——与脉搏的 `live` 行不同，里程碑全是回溯性事实。
2. 「刚刚达成」的时刻在本页**不存在**：昨天跨过的档，今天打开只是看到。没有时刻，就没有
   庆祝的落点；而庆祝动效被 PRD 明令禁止。
3. 加载骨架的呼吸是**既有**的（`cca-breathe`），那是加载态的语言，不是本页新增。

### 12.2 三条被明确禁止的动效（写给实现期）

1. **不给轨道填充加 `width` 过渡**。那会让每次挂载、每次切档所有条从 0 长出来——正是
   「游戏化」的招数，也会让「已达 / 未达」这两条几何事实在动画期间短暂失真。
2. **不给达成项加一次性高亮 / 闪烁 / 缩放**。
3. **不加数字滚动（count-up）**。数字是事实，不是转盘；而且 tabular 数字在滚动时会横向抖动。

### 12.3 允许保留的过渡（全部既有）

证据行的悬停底与文字色走 `--dur-hover` + `--ease-out`（同 `.dayRow` / `.topRow`）；
焦点环无过渡（既有）。`prefers-reduced-motion` 不需要新增降级：本页没有任何动画，
既有全局兜底覆盖骨架的呼吸。

### 15.2 三处待复核判断的裁决

1. **§1 的「已达成 / 未达成」几何裁决：通过。** 填充墨迹的有无是一个布尔几何事实
   （0px 对 ≥2px），与透明度无关，四个主题下都成立；把「未达成」限定为阶梯的 `0/N` 档
   与本轮 R3 的措辞一致（首次类没原料就整枚不渲染、记录类有会话就有极值，两者确实
   没有未达成形态）。三条附加要求：
   ① 组件测试断言 `[data-state="unreached"]` 下**取不到** `milestone-fill`
      （而不是断言宽度为 0）——宽度 0 与不渲染在真实浏览器里是两回事；
   ② 档位读数 `0/N` 必须**恒在场**，让状态在没有颜色的情况下也读得出来；
   ③ 未达成项的当前值**不降权**（同字号 / 同字重 / 同 `--text`）——这是本轮
      「不许变成灰剪影」的落点，写进组件测试。
2. **§3 成本类本轮不做：通过。** 理由成立且与 PRD 的 Goal 一致——「定价未知的天不计入」
   造成的是**不可见**的低估，而累计成本正是全轮唯一读一张会过期表的数字。它已经由
   KPI「估算成本」与日历色深承载，不需要第二处口径。
3. **§2.3 轨道底换 `-soft` + HC 1px 描边：通过。** 我用脚本独立复现了「`--border-strong`
   轨道在 HC 下只有 1.19 / 1.27」——那是真的塌缩，不是审美偏好。两条尾巴：
   ① 既有那两条同样写法的进度条**不在本轮改**（会波及已入库截图），但我以维护者身份
      **另开 Issue** 跟踪（见 §15.3）；
   ② 组件测试要钉住「HC 下轨道有 1px 描边」这条声明（CSS 不变量或几何断言皆可）。
4. **§5.3 日期带年：接受 `YYYY-MM-DD`，但实现成一个具名函数。** 裁决与理由：里程碑没有
   年份表头，日期必须自解释；而 `lib/format.ts` 是全站格式化的**唯一**落点，
   所以新增 `export function formatFullDate(ms: number): string`（`YYYY-MM-DD`），
   组件里**不许**内联拼日期。**不**把日历的同年短式上提共用——那两个场景的呈现不同
   （洞察句是句子里的日期链接，里程碑是卡片上的日期），强行统一只会给两边都加参数。
