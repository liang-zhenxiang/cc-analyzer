## 1. 红线与术语（本设计不得违反）

1. **没有分母就没有比率**：未设预算 → 托盘任何位置都不出现 `%`。
2. **来源如实**：读自日志 / 估算 / 推算不混用、不隐藏（`hasEstimate` 为真必须显式写出）。
3. **隐私**：托盘任何文本不出现会话内容、会话标题、项目名、cwd、文件路径。
4. **无 emoji 装饰**（状态标记 `!` 例外）；**只用简体中文**，数值单位用拉丁字符（`k` / `M` / `%`）。

术语：菜单栏（macOS）≡ 系统托盘（Windows）。**标题**＝图标旁的文字（仅 macOS 有）；**提示**＝悬停提示（tooltip，两平台都有）；**菜单**＝点图标弹出的菜单。

## 2. 标题（图标旁文字）

### 2.1 平台边界

- macOS：`TrayIcon` 有 `title`，文字出现在菜单栏图标旁；菜单栏空间与其它 App 的状态项共享，放不下时被系统截断。
- Windows：托盘图标**没有**旁注文字，只有悬停提示 → **标题恒为空字符串**，读数走 §3 提示与 §4 菜单。

### 2.2 标题只放一个读数（与页面的分叉同源）

- **有分母**（`percent !== null`）→ 显示百分比（`42%`）；**无分母** → 显示紧凑 token（`88k`）。
  依据：页面 `shareText` 就是这么分叉的（有分母 `当前窗口已用 X%（估算限额）`，无分母 `当前窗口消耗`）；
  "有分母才谈比率"已是全局规则，标题照搬即可。
- **主层＝5 小时窗口**（"此刻在烧"的那层，也是页面 `Gauge` 的主角）；`block === null` 时退回**滚动 7 天**；
  两层都无 → 空标题（只留图标）。
- 为什么标题**不**跟"最紧迫层"切换：菜单栏读数的**含义必须稳定**——`42%` 今天指 5h、明天指周会让人误读。
  周窗口的状态在提示里有明确后缀（§3.1），不必挤进 5 个字符的标题。

### 2.3 紧凑 token 格式（Rust 侧纯函数 `format_tray_tokens`）

| 范围 | 写法 | 例 |
| --- | --- | --- |
| `n < 1000` | 原样整数，无千分位 | `980` |
| `1000 ≤ n < 1_000_000` | 四舍五入到千 + `k` | `1k` / `88k` / `980k` |
| `1_000_000 ≤ n < 10_000_000` | 一位小数 + `M` | `1.2M` |
| `10_000_000 ≤ n < 1_000_000_000` | 取整 + `M` | `22M` / `220M` |
| `n ≥ 1_000_000_000` | 一位小数 + `B` | `1.1B` |

- 边界：`999_500` 四舍五入成 `1000k` → **规范化为 `1M`**（绝不允许出现 `1000k`）。
- 与页面 `formatTokenCount` 的**刻意差异**：去千分位、`< 1M` 用 `k`（页面写 `980,000`）。理由：菜单栏以像素计宽，逗号是纯开销；`k` 让中英文环境宽度一致。

### 2.4 百分比：照实，不封顶

- 文本 = `Math.round(share * 100)` + `%`。**超 100 照实显示**（`112%`），不写 `100%`、不加 `+`、不写 `100%+`。
  理由：读数是事实，"超了 12%" 正是用户要的；封顶会把"刚超"与"远超"抹平。
- 极端兜底：`share ≥ 10`（≥ 1000%）时，十几倍的比率已不可读，标题改为 `!` + 紧凑 token（`!1.2M`）——
  token 数更诚实，也把标题宽度封在 5 个字符内。

### 2.5 状态标记

- **接近限额**（`0.8 ≤ share < 1`，阈值见 §6）与**超预算**（`share ≥ 1`）：标题前置半角 `!`（**与数字之间不留空格**），
  如 `!91%` / `!112%`。
- 无分母时该状态**不可能出现**（没有百分比）→ 永远没有 `!`，标题就是 `88k`。
- 为什么用 `!` 而非换图标 / 染色：v1 没有第二套图片资源（§8）；`!` 是纯 ASCII，任何字体与主题下都渲染得出来，
  属"状态标记"，未触犯"不用 emoji 装饰"。

### 2.6 空格与宽度（菜单栏不撑爆）

- 数字与 `k` / `M` / `%` 之间**不加空格**（`980k` / `1.2M` / `42%`）；`!` 与数字之间也不加。
- 标题**不含任何汉字**——汉字更宽且度量随字体变；纯数字字母让中英文环境宽度一致。
- **字符数硬上限 = 5**（`!112%`、`!1.2M` 各 5）；建议渲染宽度 **≤ 48pt**（约 6 个西文字符 / 3 个汉字）。
  超过这个量级，多图标或窄菜单栏下必被系统截断——我们主动不超过 5。
- 标题每 60 秒可能变化、菜单栏随之重排；这是允许的（状态项本就该更新）。

## 3. 提示（悬停，多行）

提示是托盘唯一的"完整读数"面。行序固定（自上而下）：**5 小时窗口行 → 倒计时行 → 滚动 7 天行 → 数据时间·来源行 →（条件）估算标注行**。
没有独立品牌行：macOS 提示浮在图标下、Windows 图标也看得见，品牌留给菜单与窗口标题。

### 3.1 逐行模板

| 行 | 模板 | 说明 |
| --- | --- | --- |
| L1 | `5 小时窗口 <token> · 已用 <pct>%` | 有分母 |
| L1 | `5 小时窗口 <token>` | 无分母（**不加任何 `%`**） |
| L1 | `5 小时窗口内暂无活动` | `block === null` |
| L2 | `还有 <h> 小时 <m> 分关闭` | 常规 |
| L2 | `还有 <m> 分钟关闭` / `还有 <h> 小时关闭` | `< 1 小时` / 整点（省略"0 分"） |
| L3 | `滚动 7 天 <token> · 已用 <pct>%` | 有周预算 |
| L3 | `滚动 7 天 <token>（未设周预算）` | 无周预算 |
| L4 | `读数生成于 <相对时间> · 读自本地日志` | 见 §3.3 |
| L5 | `百分比中的限额为社区估算值，非官方数字` | 仅 `hasEstimate` 为真 |

- 近 / 超状态**并入 L1**，以括号后缀表达：`… 已用 91%（接近限额）` / `… 已用 112%（已超预算）`。
- L1 与 L3 都用 ` · ` 分隔 token 与百分比（与 `readoutTitle` 的分隔符一致）。
- 周层状态只在 L3 出现；标题（§2）只反映 5 小时窗口，两者不互相冒充。

### 3.2 没有读数时（`readout === null`）

```
尚未计算
打开应用并切到「用量总览」生成读数
读自本地日志
```

- 首行 `尚未计算` 就是 §6 的提示首行。**不显示 0**（`0` 会被读成"今天没用量"）。
- 第二行是"去哪里看"：打开应用 → 用量总览。这是唯一的动作指路，其余一律省。

### 3.3 相对时间口径

- **倒计时**用成句口径 `还有 2 小时 15 分关闭`，与页面的 `2 时 15 分` **刻意不同**：提示有整行空间、读成一句话；
  页面那一列窄，用 `2 时 15 分` 省宽。
- **数据时间**用 `读数生成于 …`（相对，回答"这份读数多新"）：`刚刚读数` / `N 分钟前` / `N 小时前`，超过 24 小时退化为 `M-D`（沿用 `formatRelativeTime` 的档位）。
- 提示里中文量词一律**留空格**（`3 分钟前`、`2 小时 15 分`）；列表里 `3分钟前` 的紧凑写法不搬过来。
- 读数是"按需收窄扫描"得来的（不是实时），**数据时间必须每次显式写出**，否则用户会把 5 分钟前的读当成此刻。

### 3.4 含估算必须写出来

- `hasEstimate` 为真 → **L5 必须出现**，不得只靠颜色或图标暗示。
- 来源词与页面同源：托盘的 `读自本地日志` ＝ 页面的 `读自日志`（多写"本地"，与隐私说明一致）。
- 本读数里"含估算"的来源只有一处：百分比的**分母**（来自「设置 → 计费窗口」的计划限额，是社区估算值）。
  token 本身是读自日志的事实，不标估算。

### 3.5 绝不出现的字段（隐私红线）

- 会话文件路径（`~/.claude/projects/…/*.jsonl`）、项目名、cwd、会话标题 / 摘要 / 内容。
- 模型名、估算成本（USD）、原始错误串、任何日志原文。
- 这些不是"这一版先不做"，而是**永远不进托盘**：托盘文本会浮在其它应用之上、可能被用户截图外发。

### 3.6 平台长度上限

- Windows 的 `NOTIFYICONDATA.szTip` 上限约 **127 个 UTF-16 单元**。最长提示（超预算 + 含估算 + 百万级数字）
  实现后必须**实测 ≤ 127**。
- 若超限：先删 L1 的 `（已超预算）` 括注（数字 `112%` 已自明），**绝不删 L4 / L5**（来源与估算不许藏）。
- macOS 提示无硬限，但同样保持 ≤ 5 行。

## 4. 菜单项

### 4.1 三项与顺序

| 序 | 文案 | 行为 |
| --- | --- | --- |
| 1 | `打开 CC Analyzer` | 聚焦主窗口；已最小化则恢复；已在前台时也是聚焦（no-op） |
| 2 | `用量总览` | 聚焦并切到「用量总览」标签 |
| — | （分隔线） | 把"导航"与"退出"分开，符合两平台惯例 |
| 3 | `退出` | 退出应用（现状：关窗即退出，生命周期不改） |

- 第 1 项用**品牌全名** `CC Analyzer`（与窗口标题一致），不用泛称"打开应用"。
- 菜单**不随状态变化**：三项目恒定，无勾选、无禁用切换。状态只由标题（§2）与提示（§3）表达。

### 4.2 为什么「用量总览」单独一项

- 托盘读数回答"是多少"，用量页回答"为什么 / 趋势 / 分布 / 历史窗口"；看到 91% 的下一步就是打开用量页，
  单列一项把"读数 → 明细"缩成**一次点击**。
- 落点明确：托盘标题与提示里的两层数字（5 小时、7 天）都在用量页**首屏**（`BillingWindowCard`），跳过去不用再找。
- 代价只有一个菜单行；收益是主路径少一步。

### 4.3 将来可能加，以及 v1 为什么不加

| 将来可能 | v1 不加的理由 |
| --- | --- |
| 按会话归因（哪个会话烧得多） | #151 尚未实现，是另一个功能面 |
| 暂停常驻读数（菜单快捷项） | 与设置开关重复；偏好只留一个真源（单一入口） |
| 复制诊断信息 | 会把本机数据带进剪贴板，须专门设计（隐私红线） |
| 切换计划 / 开机自启 | 超出 #150 契约，不夹带 |

## 5. 设置里的开关

- **位置**：设置面板「计费窗口」之后的独立小节，标题 `常驻读数`（紧挨产生读数的计费设置，用户为"从哪来 / 怎么关"而来时顺手就能找到）。
- **可见标题（label）**：`显示用量读数`
- **复选框可访问名**：`显示用量读数` —— 用 `aria-labelledby` 指向可见标题，不另写 `aria-label`（照 `启用本地归档`，避免视觉名与朗读名分叉）。
- **说明（一句话）**：`在 macOS 菜单栏与 Windows 托盘常驻显示，读自本机日志；关掉只隐藏读数，统计不受影响。`
- **关闭时的补充 hint**（照归档节，选中态隐藏）：`关掉只是不显示读数；「用量总览」与统计照常，随时可再打开。`
- **行为**：切换 → `set_tray_visible(visible)`。默认**开**，偏好存本机（`cca-tray-visible`，与 `cca-billing-plan` / `cca-archive` 同范式）。
- **"关掉之后会发生什么"要如实说清**：只是**不显示**菜单栏 / 托盘读数。日志解析、用量总览、统计口径**完全不受影响**，
  重新打开即恢复显示。（实现可在隐藏时跳过多余的 60 秒重算——对用户不可见，属允许的优化，写进 PR 备注。）

## 6. 状态表

阈值说明（本规格唯一新增的常量）：`NEAR_LIMIT_SHARE = 0.8`。**接近限额** = 使用率落在 `[0.8, 1)`；
**超预算** = `≥ 1`。它只作用于**已有分母**的层——没有预算就没有这个状态（既无百分比，也无"接近"可言）。
这就是"沿用设置里既有语义"的落法：状态完全由「设置 → 计费窗口」里的分母决定，本规格不新增任何设置项。

| # | 状态 | 标题（macOS） | 提示首行 | 菜单 |
| --- | --- | --- | --- | --- |
| ① | 无读数 | （空，只留图标） | `尚未计算` | 不变 |
| ② | 有读数 · 无预算 | `88k` | `5 小时窗口 88k` | 不变 |
| ③ | 有预算 · 正常 | `42%` | `5 小时窗口 88k · 已用 42%` | 不变 |
| ④ | 接近限额 | `!91%` | `5 小时窗口 88k · 已用 91%（接近限额）` | 不变 |
| ⑤ | 超预算 | `!112%` | `5 小时窗口 88k · 已用 112%（已超预算）` | 不变 |
| ⑥ | 有读数 · 本窗口无活动 | `620k`（周，退回） | `5 小时窗口内暂无活动` | 不变 |

- Windows 列同，仅"标题"恒为空字符串。
- 工程实现（Rust 排版单测 + web 构造单测）**逐行照本表比对**：每个状态一个夹具，断言**标题字符串**与
  **提示首行字符串**逐字相等。表里没有的字符串不许出现在实现里。

## 7. 验收清单（每条都能被断言或逐字复核）

1. 未设预算（`percent === null`）时，托盘**标题与提示的任何位置都不出现 `%`**（页面同理）。
2. 无读数（`update_tray_readout(null)`）时，标题为空字符串，提示含 `尚未计算` 且**不含 `0`**。
3. 百分比**照实不封顶**：`share = 0.42 → 42%`、`share = 1.12 → !112%`；文本里不出现 `100%+`、`+` 或 `≥`。
4. 数字与单位之间无空格：标题匹配 `/^!?\d+(\.\d+)?(k|M|B|%)$/`（**无内部空格**）。
5. 标题**不含汉字**，UTF-8 字符数 ≤ 5（`!1.2M`、`!112%` 各 5 个）。
6. 提示行序固定：L1 5 小时窗口行 → L2 倒计时行 → L3 滚动 7 天行 → L4 数据时间·来源行；`hasEstimate`
   为真时追加 L5，为假时 **L5 不出现**。
7. **隐私**：喂一条含 `~/.claude/projects/...`、项目名、会话标题、cwd 的夹具，断言标题与提示文本里**一个都不出现**。
8. 倒计时口径逐字：`还有 2 小时 15 分关闭` / `还有 45 分钟关闭` / `还有 2 小时关闭`；`now > endsAt` → `已关闭`。
9. 菜单三项恒为 `打开 CC Analyzer` → `用量总览` →（分隔线）→ `退出`，顺序与文案逐字，且**不随状态增删**。
10. 开关关闭后触发 `set_tray_visible(false)`；隐藏后重开应用，「用量总览」显示的数字与关闭前**逐字相同**。

## 8. 已知偏差

- **v1 不换图标**（#150 已锁定：没有第二套图片资源）。**用户在哪会感觉到**：进入"接近限额 / 超预算"时，
  图标本身毫无变化，唯一的变化是标题里多一个 `!`、提示里多一句括注；若菜单栏被系统截断了标题（多图标、窄屏），
  `!` 也就看不见了——此时"接近限额"在**视觉上完全不可见**，只能悬停查看。**为什么现在可以接受**：
  ① 托盘读数本就是"按需 glance"的仪表，主读数（`!91%`）就在标题里；② 第二套图标要新增图片、补齐深浅主题、
  还要面对色觉场景（红 / 绿分不出），代价与收益不成比例；③ 真正的告警能力应留给后续的阈值 / 通知设计。
- **标题只反映 5 小时窗口**，周窗口的"接近 / 超"只在提示 L3 里。若主会话更希望"最紧迫的层上标题"，
  这是**单一决策点**（改读数构造里挑 headline 层的那一行）；本规格默认选稳定而非紧迫。
- **`0.8` 阈值是新常量**（不是新设置）：与"设置里已有语义"的衔接点是"只在有分母时成立"，数值本身由本规格定死，要调只改一处。

## 9. 工程落点（一句话）

- **web**：新增读数构造函数（复用 `billingWindow` / `weeklyWindow` 与 `planLimits`，产出 `TrayReadout`）；
  新增设置存储 `cca-tray-visible`（默认 `true`，范式同 `thresholds.ts`）；在应用启动、每 60 秒、设置变化、用量扫描出新数据时调用 `update_tray_readout`。
- **Rust**：`update_tray_readout` / `set_tray_visible` 两个命令；排版是**纯函数**（`format_tray_tokens` / 标题 / 提示），必须能在 Linux CI 上单测。
- **文档**：README（双语）与 `docs/USAGE.md` 各加一节——在哪、显示什么、怎么关、支持哪些平台。
