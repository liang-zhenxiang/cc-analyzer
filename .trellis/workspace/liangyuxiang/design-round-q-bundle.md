## 0. 语境与现状（写前逐字读过）
读过：Issue #152 维护者评论（契约）、`ThresholdsPanel.tsx`（本地归档一节）、`ExportDialog.tsx`（应用内模态的既有画法）、`ErrorState.tsx`（原始串默认不进 DOM）、`archiveIndex.ts` / `archiveStore.ts`、`design-round-k-archive.md` / `design-round-p-tray.md`、`docs/USAGE.md`。

**#152 冻结事实（后文只在此范围内展开）：** 产物是单文件 `.ccabundle`（`tar` + `age` 口令收件人）；去重键是 `sourcePath`（同一份包导入两次，第二次全部「已存在」）；`sessionId` 相同但 `sizeBytes`/`mtimeMs` 不同 → **并列保留**；口令不落盘、不上传，无后门、无找回；导入只写临时目录再搬进归档、不碰 `~/.claude`，整包坏了或被截断要**明确失败**、不部分写入；v1 不做自动同步 / 云后端 / 增量包。

**可复用的现有资产（不另造）：** 模态骨架照 `ExportDialog.tsx` + `.module.css`（`--overlay` 遮罩、`--r-lg` 面板、`role="dialog"` + `aria-modal`、Esc、焦点回位）；按钮走 `components/Button.tsx`（`primary` 执行 / `secondary` 取消）；输入走 `components/TextInput.tsx`（本次 `type="password"`）；读数与告警复用 `ThresholdsPanel` 的 `.readout`（`role="status"`）与 `.alert`（`role="alert"`）；信任句照 `在本机复制，不联网，不改动 ~/.claude 的原始文件。` 的句式。

## 1. 入口与按钮
### 1.1 位置与 DOM 顺序
「本地归档」一节内，**在「立即归档」按钮行之下**新增一行两个按钮，顺序为
`启用本地归档`（开关）→ `立即归档`（把 `~/.claude` 复制进本机归档）→ `导出归档包…` / `导入归档包…`
（`.bundleRow`，本节唯一新增的 DOM，排在既有 `.archiveRow` 之后）。

顺序就是数据流向：**先启用 → 再归档 → 才有东西可导出**。导出 / 导入排在归档按钮之后，用户读着读数行的
「已归档 N」时，手边就是把它带走的入口。

### 1.2 两句按钮文案
- 导出用 `导出归档包…`：省略号＝**先弹层再执行**，与全站 `保存…`（`ExportDialog` 的写盘按钮）同惯例，不用两个字就让人以为一点就写文件。
- 导入用 `导入归档包…`：同惯例；「归档包」是用户唯一需要记住的名词，两个按钮共用它。
- 不写「加密导出 / 解密导入」：加密是**包的性质**、不是动作的名字，写进按钮会让人以为要选加密方式。不用图标：`Icon.tsx` 里没有 archive / import 图标，加图标要扩 `IconName`，而两个按钮的文字已经很能区分。

### 1.3 与「启用本地归档」「立即归档」的关系（谁先谁后）
- `启用本地归档`（开关）＝偏好：决定**今后**是否继续把 `~/.claude` 的会话复制进本机归档；它是前置偏好、不是前置条件——关掉后副本仍保留，导出照样可用。
- `立即归档`＝动作：把 `~/.claude` 的会话复制进**本机归档目录**；导出**读**的就是它产出的条目，先归档才有内容可打包。
- `导出归档包…`＝动作：把本机归档的条目打成加密 `.ccabundle`，交给用户带走（下游动作）。
- `导入归档包…`＝动作：把别人给的 `.ccabundle` 解密、搬进**本机归档目录**；与「导出」互逆，不依赖开关。

### 1.4 禁用条件（逐条，实现照抄）
- `导出归档包…` 禁用当：① 正在归档；② 正在导出或导入；③ 本机归档条目 `count === 0`。③ 的 `title` 写 `先归档，才有内容可导出`；①② 不写 title（按钮文案或进度已说明）。
- `导入归档包…` 仅当 正在归档 / 正在导出或导入 时禁用，无 `title`。
- **导出不禁用当「启用本地归档」为 off**：关闭只停止后续归档，已归档副本仍在（`design-round-k-archive.md` §1.4），凭什么不让用户把已有的带走。
- **导入恒可用**（只要没有并发操作）：它只写本机归档目录与临时目录、不读 `~/.claude`，与开关无关；不让「先开归档才能导入」变成一道隐形门槛。

### 1.5 为什么放在这一节，而不是「数据与隐私」
1. **本地归档是唯一产出、也是唯一接收这些条目的地方**；按钮离开它的读数行，用户就要在两处之间来回确认「我到底有多少东西可导出」。
2. 设置面板里**并没有**「数据与隐私」这一节——隐私声明写在 `docs/USAGE.md` 与面板顶部说明里。那是一块**只读说明区**；把会写盘、会弹层的动作塞进说明里，会把「声明」和「操作」混成一层。
3. 导出 / 导入的可信度句（§4）**就地**贴在弹层里，不需要靠一个「数据与隐私」标题来担保。

## 2. 口令弹层（应用内模态）
### 2.1 为什么是应用内弹层，不是系统对话框
- 导出要**输入两次**并做一致性校验、要挂一句**常驻警告**、要有**进行中态**——系统对话框给不了这三样。
- 全站已有一个应用内模态的先例（`ExportDialog`）：`--overlay` 遮罩、`--r-lg` 面板、`role="dialog"` + `aria-modal="true"`、Esc 关闭、关闭后焦点回到开启它的按钮。口令弹层**照这套骨架实现**，用户学一次就够。

### 2.2 导出弹层（逐字文案）
- 标题（`h2`，`aria-labelledby` 指向它）：`导出归档包`
- 说明（`.note`）：`把本机归档打包成一个加密文件，方便换机器或长期保存。`
- 输入框 1——label / 可访问名 `设置口令`，placeholder `至少 8 位，越长越难猜`
- 输入框 2——label / 可访问名 `再输一次`，placeholder `再输入一遍确认`
- 校验提示：两次不一致 → `两次输入的口令不一样。`；少于 8 位 → `口令至少 8 位。`
- 警告行（`.warn`，紧贴按钮上方）：`忘记口令就打不开这个包——口令不保存在任何地方，也没有找回的办法。`
- 信任小字（`.hint`）：`加密与打包都在本机完成，不联网、不上传。`
- 取消（`secondary`）/ 确认（`primary`）：`取消` / `导出`
- 两个输入框都是 `type="password"`、`autoComplete="new-password"`；**不提供「显示口令」开关**（防肩窥，用户可用系统输入法自行核对）。
- 确认按钮**唯一禁用条件**：任一输入为空 / 少于 8 位 / 两次不一致。禁用时在下方显示对应校验提示，用 `.hint` 灰字即可——它还不是错误，只是没填完。

### 2.3 导入弹层（逐字文案）
- 标题：`导入归档包`；说明：`输入这个包的口令，把里面的会话并进本机归档。`
- 输入框——label / 可访问名 `口令`，placeholder `输入打包时设置的口令`（`type="password"`、`autoComplete="current-password"`）
- 警告行：`口令不对或忘了就打不开——我们不保存口令，也没有找回的办法。`
- 信任小字：`解密与搬运都在本机完成，不联网、不上传。`
- 取消 / 确认：`取消` / `导入`；空口令时确认按钮 `disabled`（不显示多余的校验文案——这一栏没什么可校验的）。

### 2.4 「忘记口令就打不开」怎么写才醒目又不劝退
- **位置**：紧贴确认按钮**上方**、独立成行；**不塞进说明段、不缩成 hint 小字**——它要落在用户准备点「导出」的视线路径上。
- **颜色**：用正文档 `--text` / `--text-secondary`，**不用 `--danger`**。危险色留给「操作失败」；把一句必然为真的说明染红，只会养出对红色的免疫。
- **语气**：动词用「打不开」（说用户自己的处境），而不是「数据将永久丢失」（后果词，制造恐惧却无新信息）；收尾斩钉截铁——`也没有找回的办法`，不是「暂时无法找回」（后者暗示存在后门）。
- **句式定死**：`忘记口令就打不开这个包——口令不保存在任何地方，也没有找回的办法。`

### 2.5 进行中态
- 导出进行中：两个输入框 `readonly` + 变灰；按钮改 `正在加密导出…`；`aria-busy="true"`；取消 `disabled`。
- 导入进行中：输入框 `readonly` + 变灰；按钮改 `正在解密导入…`；`aria-busy="true"`；取消 `disabled`。
- 进行中**不显示进度百分比**：`age` 与搬运的进度粒度不可靠，一个会跳的假进度条比一句实话更糟。

### 2.6 Esc / 点遮罩：空闲可关、进行中不可关

| 状态 | Esc | 点遮罩 | 标题栏 `×` |
| --- | --- | --- | --- |
| 空闲（未开始） | **可关** | **不可关** | 可关 |
| 进行中 | 不可关 | 不可关 | 不可关（`disabled`） |

- **`Esc` 空闲可关**：键盘用户必须有一个出口；这也是 `ExportDialog` 的既有行为，不制造第二套键盘语言。
- **点遮罩空闲不可关**：与 `ExportDialog` 唯一的刻意分叉。这里的输入是**易失的口令**，一次手滑点到遮罩就清空全部输入、还要重敲两遍；`ExportDialog` 里丢的只是两个可随手重选的档位，代价不对等。
- **进行中一律不可关**：命令已经在跑、口令还在内存里，关掉弹层会让用户失去「它在干活」的唯一信号，重开还会撞上同一操作；这条也保证「结果读数」一定被看到（§3）。

## 3. 结果读数
读数**住在弹层里**：导出成功、导入结束都**不自动关闭**，用户看到数字后自己点「完成」关掉。理由与 `ExportDialog` 一致——结果要就地、要看得见；多项目的读数（新增 / 已存在 / 并列 / 失败）太长，塞进两秒就消失的 toast 等于没给。

### 3.1 导出成功
- 读数行（`role="status"`，`.count` 台阶）：`已导出 {N} 个会话，写入 {文件名}`
- 补充行（`.hint`）：`包放在安全的地方——它含你的会话记录。`
- 关闭按钮（`primary`，替换 footer）：`完成`
- `{N}` = 本次打包的归档条目数，`toLocaleString("en-US")`；`{文件名}` 用 `<code>`，`title` 给完整路径。用户在系统保存对话框里取消（`savePath === null`）**不算失败**：什么都不说、弹层保持打开、可重试（照 `ExportDialog.save()`）。

### 3.2 导入结束的四个计数
一行，固定顺序 `新增 → 已存在 → 并列 → 失败`，用半角空格 + `·` + 半角空格分隔（与读数行同分隔符）。
- `新增 {a}`：**恒出现**——`sourcePath` 不在本机索引里的条目，已写入归档。
- `已存在 {b}`：**恒出现**——`sourcePath` 已在索引里、跳过（幂等，「同一包导入两次第二次不动」的读数）。
- `· 并列 {c}`：仅 `c > 0` 时出现——`sessionId` 相同、`sizeBytes`/`mtimeMs` 不同，两份都留。
- `· 失败 {m}`：仅 `m > 0` 时出现——搬运级失败（见 §3.4）。
- `新增 0 · 已存在 5` 也要**如实**显示 0、不省略：它回答的是「这个包我到底动没动过」。并列与失败只在真有的时候出现——**罕见结果不制造噪音，但一旦出现必须解释**。

### 3.3 「并列保留」必须给一句解释
- 条件：`c > 0` 时，在读数行下方追加一行 `.hint`：`同一会话在这台和那台各自更新过，两份都保留了——列表里会看到它出现的两个时间点。`
- 为什么必须写：用户刚导入完、列表里出现两条同标题记录，**默认会被读成 bug**（「不是去重了吗」）；一句解释把「两个时间点」讲在前面，重复就成了预期。

### 3.4 失败点名（五类，简体中文，且不回显底层串）
**先分两层**（这是读数正确的关键）：**整包级失败**（口令错 / 包被篡改或损坏 / 不是本应用的包）——一条都没搬、**不写索引**，读数行整行替换为失败行；**搬运级失败**（磁盘满 / 权限）——已成功的条目保留，读数行在 `新增 / 已存在` 之后追加 `· 失败 {m}`。
- 口令错：`口令不对，请重新输入。`
- 包损坏：`这个包已损坏或不完整，打不开。`
- 不是本应用的包：`这不是 CC Analyzer 导出的归档包。`
- 磁盘满：`磁盘空间不足，请清理后重试。`
- 权限：`没有权限读写这个位置，请检查权限后重试。`
- 兜底（无法归类）：`操作没有完成，请重试。`

- **接口要求**：命令须返回一个**稳定标识**（枚举）而不是裸异常串，前端据此选上方的一句；**分类不了就走兜底**。这是 #152「失败要点名原因、不静默」的落地要求，不是新功能。
- **禁止**把底层串拼进界面：不出现 `/Users/…`、`os error`、`No such file`、`Permission denied`、`.rs:` 行号。照 `ErrorState.tsx` 的红线——原始串默认不进 DOM。
- 失败时**不关闭弹层**：口令错 / 损坏留在导入弹层改口令重试，磁盘 / 权限留在原处修环境重试。

## 4. 口令丢失与隐私（弹层里逐句给出，不增不减、不许诺）
- P1 `口令不保存在任何地方，关掉这个窗口就没了。`——**不落盘**：应用不留、不进 localStorage、不进日志。
- P2 `加密与打包（解密与搬运）都在本机完成，不上传、不联网。`——**不出本机**：照「在本机复制，不联网」的句式。
- P3 `忘记口令就打不开这个包，我们没有找回的办法。`——**丢了打不开**：明确无后门、无找回。
- P4 `包放在哪里，就按哪里的敏感度对待它——它是一份加密的会话记录。`——**放哪儿安全**：去向由用户决定，应用不替他保管。
- **绝不出现**：`我们会帮你找回`、`可申请恢复口令`、`同步到你的云端`、`备份到服务器`、`重置口令`——这些承诺应用做不到，写出来就是撒谎。应用**不代为上传、不代为同步**，也不把包默默写进某个自动备份目录。

## 6. 验收清单（每条都能被断言或逐字复核）
1. **无明文**：弹层里的输入框 computed `type === "password"`；DOM、`title`、`aria-*`、`localStorage` 里都不出现已输入的口令。
2. **不回显底层串**：喂五类失败夹具，断言告警文本**不含** `/Users/`、`os error`、`No such file`、`Permission denied`、`.rs:`。
3. **输入框数量**：导出弹层里口令类输入恰为 2 个；导入弹层恰为 1 个。
4. **校验门**：两次不一致 → `导出` `disabled===true` 且提示 `两次输入的口令不一样。`；少于 8 位 → 提示 `口令至少 8 位。`。
5. **进行中不可关**：进行中按 `Esc`、点遮罩、点 `×` 均不触发 `onClose`（弹层仍在 DOM）。
6. **读数逐字**：`新增 0 · 已存在 5`（全部命中）与 `新增 2 · 已存在 1 · 并列 1`（跨机两版本）两串逐字相等，分隔符是 ` · `。
7. **幂等**：同一包导入两次，第二次 `新增 0`，且对归档目录**零写调用**（除索引外的写调用集合为空）。
8. **并列有解释**：`并列 1` 时同屏出现「两份都保留了」那句解释；`并列 0` 时不出现。
9. **禁用语**：全弹层文本不出现 `找回口令` / `恢复口令` / `同步到云` / `上传到服务器` / `重置口令`（P1–P4 已用正向句覆盖同一事实）。
10. **禁用条件**：`count===0` 时 `导出归档包…` `disabled===true` 且 `title === "先归档，才有内容可导出"`；「启用本地归档」为 off 时 `导入归档包…` 仍 `disabled===false`。

## 7. 已知取舍（v1 不做，以及用户会在哪感到不便）
- 自动同步 / 云后端：两台机器之间要**手动**导出一次、拷过去、再手动导入。红线是「数据默认不出本机」；一条会自动联网的路径等于给「本机」这个承诺开了洞——手动一次的代价，换的是整条链路可解释。
- 增量包：归档攒到几 GB 后，每次全量打包都慢、包也大。去重键是机器相关的 `sourcePath`，增量要引入「基线包 + 补丁」的新格式与新失败面；v1 先保证**能搬、搬不坏**。
- 跨机器口令托管 / 找回：换机器后忘了口令，就真的打不开。托管口令＝把「口令只在你手里」推翻，与 #152 的加密模型直接冲突；宁可少一个便利，不引入一个后门。
- 包内合并同一会话的两版本：列表里会出现两条同标题记录。并列保留是「宁可多留不可丢」的直接结果；给一句解释（§3.3）比冒险做合并更稳。

## 8. 给实现者的一句话
重量压在四处：**口令只在内存、只在 password 输入框里**；**失败只点名、不回显原文**；**进行中不给假进度、也不让关**；**结果数字逐字照本表**。四件事做完，「数据不出本机、丢了不撒谎」就是弹层自己说出来的。
