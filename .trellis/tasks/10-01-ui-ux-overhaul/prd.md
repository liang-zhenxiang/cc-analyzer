# PRD：UI/UX 精品化

**父任务**：`10-01-v030-overhaul` · **GitHub Issue**：待建

## 背景

维护者对这个项目的判断很明确，而且把它排在第一优先级：

> 「首先界面美观度必须是第一位的，然后好用，想用」

这不是审美偏好，是**产品判断**：CC Analyzer 是一个要被反复打开的桌面工具。
同类工具的功能差异往往不大，决定用户第一次打开后会不会留下来的，
是「看起来是不是一个正经产品」。当前的界面是**功能驱动**做出来的——
能用、信息密度高、但视觉上没有一个连贯的设计意图。

## 期望

### 1. 先定方向，再动手

- [ ] 派**专业设计方向**产出若干条**互不相同**的视觉方向（不是同一套换配色）
- [ ] 每条方向要能说清：给谁用、什么气质、和同类工具的差异在哪
- [ ] 选出方向后再落地，**不要边做边改方向**

### 2. 落地

- [ ] 建立完整的设计 token（色彩、间距、字号、圆角、阴影、动效时长），
      收敛到 `web/src/styles/tokens.css`，**组件里不再出现硬编码颜色**
- [ ] 统一组件视觉语言（按钮、面板、输入框、空状态、提示）
- [ ] 信息密度与可读性的平衡：这是个数据工具，**不能为了好看牺牲密度**
- [ ] 深浅色主题都要成立（现有 `ThemeProvider` 已支持切换）
- [ ] 关键交互有恰到好处的反馈与动效，**不喧宾夺主**

### 3. 用真实截图验证

- [ ] **每个主要界面都要有真机截图**作为证据
- [ ] 截图要能看出改了什么（改前 / 改后对照）
- [ ] 截图归档进仓库（`docs/` 下），README 里能展示

## 验收标准

- [ ] 设计 token 成为唯一色彩来源；`grep` 不到组件里的硬编码十六进制色值
- [ ] 深浅色主题下**每个主要界面**都有截图，且都看得过去
- [ ] README 有一张能代表产品气质的界面图
- [ ] 视觉改动不破坏任何现有测试

## 非目标

- 不重构信息架构。这一版是**视觉与交互质感**升级，
  信息架构的调整另有任务
- 不引入重型 UI 库。现有组件是自己写的，保持这一点——
  引入组件库会把「统一视觉语言」这件事变成「和组件库打架」

## 入手位置

- `web/src/styles/tokens.css` —— 设计 token 的唯一来源
- `web/src/styles/global.css` —— 全局样式
- `web/src/components/*.module.css` —— 共享组件样式
- `web/src/app/AppShell.module.css` —— 应用外壳
- `web/src/features/*/**.module.css` —— 各功能页样式
- `web/src/app/ThemeProvider.tsx` —— 主题机制

## 难度

中等。技术难度不高，**难在审美判断与克制**——
在一个信息密集的工具里，做出「好看」而不牺牲「好用」，
需要在每个界面上反复取舍。
