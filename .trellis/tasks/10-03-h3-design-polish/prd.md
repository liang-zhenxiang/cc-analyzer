## 背景

上一轮「通电」（v0.6.0）把评审 Top10 里识别度最高的四条做完了：首屏读数行、
时间刻度轴、三表键盘导航、图表色板。剩下六条是**一致性**与**状态语言**问题——
它们不产生新的「哇」，但正是「好用」与「专业感」的来源：

| # | 问题 | 现状证据 |
| --- | --- | --- |
| 5 | 分段控件画法**逐字复制 4 份**（顶栏标签、侧栏视图切换、视图 tab、报告 tab），一致性靠注释维系 | 各处约 25 行相同 CSS |
| 6 | 加载态**三处三个样**：侧栏裸文本「加载中…」、会话头「总耗时 …」、监控页「探测中」 | 无统一语言 |
| 7 | 侧栏工具栏：低频的「刷新会话列表」文字按钮与搜索框同行，把搜索框压到约 150px；三张数据表**三种行内边距**（7/9、6/10、4/9），切换视图时密度会「跳」 | 截图可见 |
| 8 | `components/Panel.tsx` 是**死代码**（只有自己的测试引用），而五个面板各自手写同构的 `.panel` 样式；`ErrorBoundary` 的按钮样式手写在 `global.css` 里，绕过了 `Button` 组件 | 同构五份 + 全局 CSS 里藏控件样式 |
| 9 | `SessionHeader` 的 8px 绿点**常亮**，不表示任何状态——指示灯不指示就是装饰 | 「仪器面板」品牌叙事的缺口 |
| 10 | `FilterBar` 里「记录类型」用 checkbox、「状态」用 ghost Button + `aria-pressed`：同一个「多选开关」概念，两种控件、两种视觉 | 表单感与仪器气质相悖 |

此外评审指出：`--r-lg` 全仓无消费者；`--warning` 只在 `TokenPanel.unknown` 用了一次；
25 处 2px/3px/6px 微间距字面量（违反 tokens.css 自立的精神）。

## 用户故事

- 作为**使用者**，我在不同视图间切换时，控件长相与行的呼吸感应当一致——
  不该因为是「另一个视图」就换一套画法。
- 作为**使用者**，等待数据时我看到的应当是同一种「正在取数」的信号，而不是三种各异的提示。
- 作为**新贡献者**，我照着一个共享组件去用，而不是复制 25 行 CSS 再手改。
- 作为**使用者**，会话标题旁的状态灯应当在告诉我点什么（今天有活动 / 有失败记录）。

## 功能需求

0. **先设计后实现（硬性流程）**：由 UI/UX 设计师角色产出一份 `design.md`，包含：
   每条改动的**设计意图**、**视觉规格**（用哪些 token、状态如何表达、hover/focus/disabled 各态）、
   **信息层级依据**、以及**明确不做**的清单。没有 `design.md` 不开工。
   设计师的评判标准是「每个视觉元素都承载信息」——**只加信息，不加装饰**；
   渐变、玻璃拟态、彩色主题、装饰性动效一律不做。

1. **抽取 `SegmentedControl` 共享组件**（新增 `components/SegmentedControl.*`）：
   一份 CSS Module、四个调用点替换、补齐**方向键导航**（`role="tablist"` 的
   ArrowLeft/Right/Home/End）。
2. **统一加载态语言**：定义一种 skeleton 画法（`--bg-hover` 圆角条 + 呼吸动画，
   `prefers-reduced-motion` 下静止），替换侧栏首载、表格首载、会话头「总耗时 …」三处。
   若某处确实不适合 skeleton，在 `design.md` 里说明理由。
3. **侧栏工具栏重排**：「刷新会话列表」改为 `IconButton`（`refresh` 图标已存在，
   `label` 保底 tooltip），搜索框拿回全宽。
4. **密度统一**：定义行内边距令牌（如 `--row-pad-x` / `--row-pad-y`），
   三张数据表统一引用；差异用 `calc()` 表达而不是另写一组字面量。
5. **组件收口**：`Panel` 要么被改造成真正被五处复用的 `DataPanel`，要么**删掉**——
   不允许保留「有测试、无消费者」的死代码。`ErrorBoundary` 的按钮改走 `Button` 组件。
6. **状态灯语义化**：`SessionHeader` 的圆点按会话状态着色并给出可访问文本
   （今天有记录 / 含失败记录 / 更早），数据在 `records` 与 `mtimeMs` 里已有。
7. **筛选控件统一**：记录类型与状态收敛为同一种 chip-toggle 画法（沿用既有
   `aria-pressed` + `--accent-soft` 按下态先例），**保持两者的可访问名与既有 e2e 选择器可用**
   （若必须改选择器，同步更新测试并在 PR 里说明）。
8. **令牌收尾**：`--r-lg` 与 `--warning` 要么用起来要么删除；微间距字面量收进令牌档位。

## 约束

- 严格遵守 `tokens.css` 纪律：不引入颜色/高度/圆角/时长的字面量。
- **不得改变信息架构**：不加新页面、不搬动主要区块的位置。
- 所有既有 e2e 用例（含键盘导航、搜索面板、录制详情、计费窗口、更新设置）必须继续通过；
  本轮最容易踩的坑是**共享组件抽取导致既有选择器失效**。
- 改完必须重出 `docs/screenshots/` 全套（浅/深 × chromium/webkit）并更新 README 描述文字
  （若画面有可见变化）。
- 每一处视觉改动都要有对应的**组件单测**（交互/无障碍标注）与必要的 e2e 断言。

## 非目标

- 不做整体视觉重设计；不改配色体系；不加装饰性动效。
- 不做字号缩放 / 高对比度模式（那是 Issue #73，独立任务）。
- 不做虚拟滚动 / ANSI 渲染（同上）。

## 验收标准

- [ ] `design.md` 先于代码存在，且每条改动都能在实现里对上号

- [ ] 三处加载态使用同一种画法；`reduced-motion` 下不产生动画

- [ ] 记录类型与状态是同一套 chip-toggle 画法
- [ ] 单测 + e2e + `./scripts/lint.sh` 全绿；既有用例一条不少
