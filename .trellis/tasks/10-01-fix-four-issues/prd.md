# 修复四个用户可见缺陷并沉淀发布语言规范

## Goal

维护者在使用 v0.3.0 打包产物时报了四个问题。本任务是它们的父任务：拆成四个
可独立验收的子任务，各自带测试，并补上「发布说明必须中文」这条规范。

## 用户原话（问题来源）

1. release 的发布后面都改成中文，沉淀到 Trellis spec。
2. 点「生成整会话分析」报错「未找到 claude CLI」，但用户**已经装了**
   Claude Code CLI；要求同类路径问题一并测到位。
3. 右边的记录详情**无法收起**；下方复制**没有成功提示**；
   **「复制摘要」复制不到任何数据**。
4. 实时监控点进去**不应立刻打开**，要有开关；而且现在打开也失败
   （提示「端口 8090 无响应…可能被旧 cc-monitor 占用」）。
   并追问「cc-monitor」是不是本项目名称（本项目叫 cc-analyzer），
   要求全局排查同类命名问题一并改掉。

## 任务树

| 子任务 | 覆盖 | 验收焦点 |
| --- | --- | --- |
| `10-01-release-notes-zh` | 问题 1 | 发布说明产物中不再出现英文模板串 |
| `10-01-claude-cli-probe` | 问题 2 | 装了 CLI 就能跑起来（含 nvm 等版本管理器路径） |
| `10-01-record-detail-panel` | 问题 3 | 可收起、复制有反馈、复制摘要有内容 |
| `10-01-monitor-explicit-open` | 问题 4 | 显式打开、文案不再误导、命名统一 |

## 跨子任务约束

- **不给用户增加新的必填步骤**：修复「装了 CLI 却报未找到」时，
  不能让用户去配 PATH 才算修好；应用要自己找到 CLI。
- **不许把外部服务的名字写进用户可见文案**：`cc-monitor` 是**外部**
  仪表盘的名字，不是本项目（本项目叫 CC Analyzer）。用户可见文案一律
  用中性描述。
- **红线照旧**：`${{ }}` 表达式经 `env:` 中转；`uses:` 按 SHA pin；
  release 构建不引入缓存；会话数据不出本机。
- 子 agent 只改自己子任务范围内的文件；跨文件冲突由主会话统一。
