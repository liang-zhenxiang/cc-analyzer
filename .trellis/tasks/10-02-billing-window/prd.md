# PRD：5 小时计费窗口仪表盘与订阅计划感知

> 对应 Issue #68 · 创建于 2026-10-02 · Round D
> 依据：`.trellis/workspace/liangyuxiang/research-competitors.md` 建议 1+2

## 背景

竞品调研结论：5h 计费窗口是订阅用户**每天看几十次**的信息（ccusage 的 `blocks`
与 Usage-Monitor 的核心功能），而 CLI 只能打印数字——桌面应用可以做成真正的
仪表盘。竞品的最大软肋恰是「窗口预测不准」（ccusage 高赞 issue：「Live Blocks
not accurate, Limit reached earlier」+11），用本地计算余量把它做准是差异点。
monitor 用户还明确要求：预测给**具体日期时刻**而非时长、时区与重置时刻显式化。

## 用户故事

- 作为订阅用户，打开应用即见：当前 5h 窗口何时开启、还剩多久关闭、已消耗多少。
- 作为 Pro/Max 用户，选好自己的计划档位后，看到限额仪表：已用 / 限额 / 余量。
- 作为重度用户，按当前 burn rate 看到「预计 HH:mm 达到限额」的具体时刻，而非
  一个抽象时长。
- 窗口关闭后历史窗口可回看（近 N 个窗口的消耗对比）。

## 功能需求

1. **窗口聚类引擎**（纯函数）：把全部会话记录按「最后一条活动时刻向前 5h」
   的滚动窗口语义聚类（对齐 ccusage 的 blocks 口径，实现前先核实其聚类规则：
   窗口起点 = 一段 ≥5h 静默后的首条活动）。
2. **当前窗口仪表**：环形/表盘式进度（复用 chartPrimitives）、开启时刻、
   关闭倒计时、四类 token 消耗、provenance 徽章（读自日志）。
3. **订阅计划感知**：设置里选计划（不选 / Pro / Max5 / Max20 / Team / 自定义）；
   限额数值常量表内嵌并标注来源（公开资料整理，非官方 API）；**未选计划时
   只显示消耗不显示百分比**——没有分母就没有比率，不猜。
4. **burn rate 预测**：按窗口内最近 N 小时的消耗速度线性外推，给出
   「预计 MM-DD HH:mm 达到限额」；速率样本不足（<30 分钟活动）时明确标注
   「样本不足，仅供参考」，provenance=推算。
5. **历史窗口条**：近 7 个窗口的消耗小柱图（BarChart 复用）。
6. 挂载位置：「用量总览」页顶部新增一块仪表区（不是新标签页）。

## 约束

- 纯本地零网络；计划限额常量表必须标注「整理自公开资料，非官方」
- 延续 provenance 三档语言；预测值一律带「推算」徽章
- 时区：窗口边界按本地时间计算；不引入「每日重置」概念（5h 窗口无日界）
- 既有三层测试全绿；新引擎有夹具单测（含跨窗口边界、静默分隔、时钟推进）

## 非目标
