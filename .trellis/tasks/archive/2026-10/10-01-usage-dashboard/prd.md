# PRD：用量总览仪表盘

> 对应 Issue #65 · 创建于 2026-10-01 · Round B

## 背景

竞品调研（`.trellis/workspace/liangyuxiang/research-competitors.md`）的横向对比显示：
ccusage / opcode / CCHV / phuryn 全部具备「成本估算 + 趋势图表」，cc-analyzer 两者皆无。
这是当前最大的功能空白。订阅用户每天都要回答的问题——「我今天/这周烧了多少 token、
都在哪些项目上烧的、什么时段最活跃」——现在只能在应用外获得答案。

同时调研指出头部竞品（ccusage）被骂最多的恰恰是**数字不准**。因此本轮的功能必须
带一套贯穿始终的 **provenance 置信标签**（读自日志 / 估算 / 推算）：把「估算非账单」
从遮遮掩掩变成设计语言，让「诚实仪表」成为仪器面板品牌叙事的一部分。

## 用户故事

- 作为订阅用户，我打开「用量总览」就能看到最近 N 天每天的 token 消耗趋势，
  不用去翻每条会话的 Token 面板。
- 作为多项目用户，我想知道用量按项目、按模型怎么分布，找到最烧 token 的项目。
- 作为重度用户，我想知道自己几点钟最活跃（7×24 热力图），回顾自己的工作节律。
- 作为想知道「订阅值不值」的用户，我想要一个明确的**估算**成本数字
  （按 API 定价折算的虚拟成本），且应用诚实告诉我这是估算、依据哪份定价快照。
- 作为浅色/深色主题用户，仪表盘在两套主题下都要好看、可读。

## 功能需求

1. 第三个标签页「用量总览」（现有「会话分析」「实时监控」不动）。
2. KPI 汇总行：所选时间范围内的 tokens 总量、会话数、消息数、估算成本，
   每个数字带 provenance 徽章。
3. 按天趋势图：7 / 30 / 90 天三档切换，展示每日 token 消耗（四类 token 可切换或堆叠）。
4. 按项目分布（水平条形，Top N + 其他）。
5. 按模型分布。
6. 7×24 活跃时段热力图（消息数为热度）。
7. 估算成本：内嵌离线定价快照（标注快照日期与来源），四类 token 分别计价；
   快照必须能在不联网的情况下工作，未来可整体替换。
8. 空状态：无会话数据时给出引导（指向会话扫描），不是空白页面。
9. 深浅主题全覆盖；数据可视化用色来自设计令牌（categorical 色板），不硬编码。

## 约束

- **零新增运行时依赖**：图表用 SVG 手绘（延续 TimelineTrack / sessionGraph 的路线），
  不引入图表库——供应链红线与包体都 hold 不住。
- 全部计算在本机完成，不发起任何网络请求（隐私红线）。
- 大会话历史（数百会话）下首屏可交互时间可接受：聚合可渐进完成，
  已聚合部分先渲染（具体策略见 design.md）。
- 既有功能零回归：全量既有单测 / E2E / GUI 测试通过。

## 非目标（后续轮次）

- 5h 计费窗口、订阅计划感知、burn rate 预测（Round C）
- 全局搜索、备份归档、导出 CSV/HTML
- 多 agent CLI 支持
