# 实时监控改为显式打开并统一命名

## Goal

`web/src/features/monitor/MonitorPage.tsx` 在挂载时立刻 `useEffect(() => void probe())`,
即**一进入「实时监控」标签页就探测并内嵌 iframe**。用户要求：点进去不要马上���开,
要有开关，点击之后才打开。同时用户对现状有两处困惑：

- 失败文案「端口 8090 无响应（已尝试 3 次，可能被旧 cc-monitor 占用）」
  里的 **cc-monitor 是外部仪表盘的名字，不是本项目**（本项目叫 CC Analyzer）。
  这个说法既让用户以为是自家组件出问题，又在瞎猜原因。
- 要求全局排查同类命名问题一并改掉。

## Requirements

### A. 显式打开

1. 初始状态改为**未打开**：展示说明 + 一个明确的「打开监控」按钮,
   不自动探测、不挂 iframe。
2. 只有用户点击后才进入 `probing` → `ready` / `unavailable` 的既有状态机。
3. `unavailable` 状态下保留「重试」按钮（既有行为）。
4. `ready` 后提供**关闭**入口，回到未打开状态（否则「开关」只有开没有关）。
5. `onEnterFloat`（浮窗）消息协议、`postTheme` 主题同步、
   `isLocalMonitorOrigin` 的来源校验**行为不变**。

### B. 命名与文案

6. 用户可见文案中不再出现 `cc-monitor`。用中性描述（如「本机监控仪表盘」
   /「外部仪表盘服务」），不臆造第三方产品名。
7. 「可能被旧 cc-monitor 占用」这类**猜测性归因**改成陈述事实：
   说明「默认探测 `localhost:<port>`；该服务不在本仓库内，需要另行运行」。
8. 全局排查并改掉同类命名问题（README 中英双语、`docs/` 全部相关文档、
   前端源码）。**归档的历史研究笔记（`.trellis/tasks/archive/`）不改**——
   那是历史记录，改它等于篡改历史。

## Acceptance Criteria

- [ ] 单元测试：初始渲染**不调用** `pingMonitor` / `monitorPort`
      （断言 mock 未被调用——这是「不要马上打开」的机器化表达）
- [ ] 单元测试：点击「打开监控」后才调用探测；探测成功渲染 iframe 且 `src`
      含正确端口
- [ ] 单元测试：探测失败显示失败态与「重试」；重试会再次探测
- [ ] 单元测试：`ready` 状态下可关闭回到初始态，且 iframe 被移除
- [ ] 单元测试：失败文案**不含** `cc-monitor` 字样（防回归的字符串断言）
- [ ] 全局搜索 `grep -rn "cc-monitor"` 在**源码与文档**中 0 命中
      （`.trellis/tasks/archive/` 除外，需在 PR 说明里讲明例外）
- [ ] 端到端（Playwright）：切到「实时监控」标签 → **不自动打开** →
      点击按钮才进入探测/失败态
- [ ] `npm --prefix web test` 与 `npm --prefix web run test:e2e` 全绿

## Notes

- 外部服务不在本仓库内，所以**「打开后连不上」是预期内的正常分支**,
  任务不是「让它连得上」，而是「让它行为可控、文案诚实」。
- 若既有测试断言了「挂载即探测」，那些断言正是本条要求要改掉的东西,
  改断言时要写清为什么（不能为了过测试而把新行为测没）。
