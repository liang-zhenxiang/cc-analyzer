# 设计轻规格：菜单栏常驻限额读数（N4 视图层）

> 依据：`prd.md`、`design.md`（定案架构）、`tray-capability-facts.md`（平台限制）、
> `BillingWindowCard.tsx` / `weeklyWindow.ts` / `planLimits.ts` / `provenance.ts`
> （读数语义与数字格式惯例）、`tokens.css`（设置页 UI 走令牌）。
> 本文只管**视图层**：title 字符串、tooltip 全文、托盘菜单、两态图标、设置开关文案。
> 实现逐字照抄；改动本文的逐字面须回设计师过一遍。

## 0. 裁决表

| # | 议题 | 裁决 | 一句话理由 |
| --- | --- | --- | --- |
| 1 | title 是否加「CC」前缀 | **不加**。图标即品牌位，文本只留数据 | 图标+文本并存（研究报告已核实），前缀是冗余宽度；竞品同时在场时靠图标形状区分，不靠文字 |
| 2 | title 用已用还是剩余 | **已用**，与应用内 Gauge / 周预算条同口径 | PRD 硬要求「同一份计算」；BillingWindowCard 全部是已用口径，托盘单开「剩余」就是第二套口径 |
| 3 | 两层数字排法 | `59%·周45%`——5h 在前（主）、`·` 分隔、「周」单字标签标第二层 | 顺序约定不可靠（用户记不住哪个在前），单字标签是唯一低成本辨识；紧凑读数内不加空格 |
| 4 | 未选计划的 title | 显示**消耗 token 数**（`52,300`，复用 `formatTokenCount`），不显示百分比 | 「没有分母就没有比率」是 BillingWindowCard 的既有诚实原则，托盘不得破例 |
| 5 | near_limit 阈值 | **5h 已用 ≥ 80% 或周已用 ≥ 80%，任一即 true**；两层都无分母则恒 false | 项目内本无警戒阈值（Gauge 是单色弧），「沿用」的是口径而非数字；80% 是通用「快满了」阈值，60s 刷新粒度下留有反应余量。v1 固定常量，不进设置 |
| 6 | 强调态图标做法 | **保持 template、描边环 → 实心饼**（同外接圆几何），不用彩色 | 彩色菜单栏图标违反 macOS 单色惯例且深浅菜单栏必有一边不可读；template 让系统替我们适配明暗。「环变饼」=「容器变满」，形状自释 |
| 7 | tooltip 首行 | 以「CC Analyzer」标识开头 | Windows 无 title，tooltip 是唯一全文载体，必须自带出处 |
| 8 | 菜单快捷读数行 | **加**，置顶、disabled、一行 | tooltip 要悬停 1~2 秒才出；左键弹菜单是点击即见，也是 Windows 一期唯一的主动读数路径 |
| 9 | 刷新间隔设置 | 不做，固定 60s | 读数分钟级变化；可配间隔是竞品的形态，不是我们的需求（见「不做」） |

## 1. title 字符串（macOS 菜单栏文本）

### 1.1 状态矩阵（逐字）

| 状态 | title 逐字示例 | 规则 |
| --- | --- | --- |
| 已选计划（或自定义上限），有活动窗口，周层有预算 | `59%·周45%` | `f5h(pct)` + `·` + `周` + `fW(pct)` |
| 已选计划，周层无预算 | `59%` | 只 5h 层 |
| 未选计划，周层有预算 | `52,300·周45%` | 5h 层退化为 `formatTokenCount(consumed)` |
| 未选计划，周层无预算 | `52,300` | 同上，无周段 |
| 无活动计费窗口（`currentBlock` 为空） | **`None`**（隐藏文本，只剩图标） | 应用内 BillingWindowCard 此态返回 null，托盘同语义；不造「0%」——没有窗口不是零消耗 |
| 启动后首次推送前（数据未就绪） | `None` | 不显示猜测值 |

### 1.2 格式函数（实现照抄此语义）

- `f5h(pct)`：`(progress * 100).toFixed(0)`，与 BillingWindowCard.tsx:124 完全同式；
  结果 > 999 时钉在 `999`（防宽度溢出），≥ 100 照实显示（「估算限额被超过」本身是诚实信息，
  应用内 Gauge 弧 clamp 到满但数值不隐藏，托盘同口径）
- `fW(pct)`：`Math.round(weeklyShare * 100)`，与 BillingWindowCard.tsx:211 同式；同样 999 上限
- 消耗数：直接复用 `formatTokenCount`（`web/src/lib/format.ts`）——同一函数即同一口径，
  **不得在托盘侧新写格式化**
- 分隔符是 U+00B7 `·`，紧凑读数内**不加空格**；「周」标签固定一个汉字，不用「7d」「W」

### 1.3 宽度预算

最长常态 `100%·周100%` ≈ 9 字符（含一个全宽汉字），在研究报告「≤10 字符」红线内。
超过 999 的病理值被 1.2 的上限钉死，宽度有硬上界。

### 1.4 更新时机

数值变化即 `set_title`（60s tick 重算后）；无变化不重复设置。竞品「刷新闪零」的坑
（tray-capability-facts.md 第五节）在于先清后设——title 全程只赋完整新串、不赋空串过渡。

## 2. tooltip 全文（全平台，含 provenance）

多行文本，`\n` 换行（NSStatusItem 与 Windows tooltip 都支持）。**六行结构，逐字模板**：
（`【】`内是插值，其余字符含标点逐字照抄）

```
CC Analyzer
5 小时窗口：已用【consumed】 / 【limit】 tok（【pct】%，估算限额）
【countdown】后关闭（【endClock】）【· 预计【eta】到达限额（按消耗速度推算）】
滚动 7 天：已用【weeklyConsumed】 tok · 日均【dailyAvg】 tok【 · 周预算已用【weeklyPct】%（预算为自设数字）】
读自本机日志；限额为社区整理的估算值，非官方数字，估算与预测都不是账单
```

插值来源（全部复用既有函数，口径与应用内一致）：

| 插值 | 来源 | 例值 |
| --- | --- | --- |
| `consumed` / `weeklyConsumed` / `limit` | `formatTokenCount` | `52,300` |
| `pct` / `weeklyPct` | 同 1.2 的 `f5h` / `fW` | `59` |
| `countdown` | `formatCountdown(active.end - now)` 的输出（BillingWindowCard.tsx:21，`2 时 12 分` / `38 分钟` / `已关闭`） | `2 时 12 分` |
| `endClock` | `formatClock(active.end)`（HH:mm） | `15:47` |
| `eta` | `formatPredictionTime(prediction.reachAt)`（MM-DD HH:mm） | `10-10 14:32` |
| `dailyAvg` | `formatTokenCount(Math.round(weeklyConsumed / 7))` | `58,857` |

条件段的取舍规则（与应用内 BillingWindowCard 的呈现条件一一对应）：

| 条件 | 变化 |
| --- | --- |
| 未选计划（`limitTokens === null`） | 第 2 行整行换为 `5 小时窗口：已用【consumed】 tok（未选计划，只看消耗）`；第 3 行的「预计…」段省略 |
| `predictLimitReach` 返回 `insufficientSample` | 第 3 行「预计…」段省略（样本不足不外推，同 BillingWindowCard.tsx:174） |
| 周层无预算（`weeklyLimitTokens === null`） | 第 4 行「 · 周预算已用…」整段省略（同 BillingWindowCard.tsx:199 的「未设周预算——只显示消耗」语义） |
| 无活动计费窗口 | tooltip 整体换为两行：`CC Analyzer\n当前无活动计费窗口——开始一次 Claude Code 会话后出现` |
| 数据未就绪（首次推送前） | tooltip 为 `CC Analyzer\n正在读取本机日志…` |

最后一行固定句是 provenance 档位语言的托盘版：消耗数字是 `logged`（读自日志）、
限额分母是社区 `estimated`、预计句自带 `inferred`（按消耗速度推算）——四档语言
（provenance.ts）在 tooltip 里各就各位，不新造档位名。

## 3. 托盘菜单结构（muda，逐字）

```
┌──────────────────────────────────┐
│ 5h 已用 59% · 周已用 45%          │  ← disabled，纯读数行
│ ──────────────────────────────── │  ← 分隔线
│ 打开 CC Analyzer                 │  ← 显示主窗口并聚焦
│ 用量总览                         │  ← 显示主窗口 + emit "tray:goto-usage"
│ ──────────────────────────────── │  ← 分隔线
│ 退出 CC Analyzer                 │  ← app.exit(0)
└──────────────────────────────────┘
```

规则：

- **读数行**：disabled（不可点、不高亮），文案随 title 同步刷新；逐字格式
  `5h 已用【f5h 或 formatTokenCount】 · 周已用【fW 或「未设」】`。
  宽松版空格排版（与 title 的紧凑版不同——菜单行宽充裕，可读性优先）。
  周层无预算时该段省略；未选计划时 5h 段用 `5h 已用 52,300 tok`；
  无活动窗口时整行 `暂无活动计费窗口`。「5h」写法沿用设置页 `tok/5h` 单位的既有先例。
- **「打开 CC Analyzer」**：主入口，永远第二位（读数行之后第一个可点项）。
- **「用量总览」**：读数的来龙去脉入口，点开直达产生该数字的页面。
- **「退出 CC Analyzer」**：菜单唯一的退出路径（常驻模式下关窗不退出），
  带全名与「打开」项对仗；放在末位、分隔线隔开（不可逆操作永远最后 + 隔离）。

## 4. 两态图标（纯代码位图规格）

两枚位图，启动时用 `Image::new_owned(rgba, w, h)` 生成并缓存（design.md 1.2 已定），
**只在 near_limit 态切换时调用一次** `set_icon_with_as_template`（原子、防闪；态未变不重设）。

### 4.1 共同规格

- 画布：**32×32 px RGBA**（macOS 菜单栏 16pt @2x；系统自动缩放，Windows 同源位图可用）
- 颜色：**RGB 恒为 (0,0,0)，形状只存在于 alpha 通道**（template image 的硬规则——
  系统按菜单栏明暗自动反色，这是「深浅菜单栏都安全」的机制本身）
- 几何：外接圆直径 **22px**，圆心 (16,16)（四周留 5px 边距，保证菜单栏垂直居中裁切安全）
- 边缘 1px 抗锯齿（alpha 渐变），无阴影、无渐变填充

### 4.2 两态形状

| 态 | 形状 | 几何 |
| --- | --- | --- |
| 正常（idle） | **圆环（描边）** | 外半径 11px、内半径 8px 的环形区域 alpha=255 |
| 接近限额（near） | **实心圆（饼）** | 半径 11px 整圆 alpha=255 |

形状语义：同一外接圆内「环 → 饼」＝「容器 → 满」。二者并排可辨、单看也自释
（电池低电量图标的同款形状语言）。不画指针、不画进度弧——进度已在 title 数字里，
图标再画一遍是双倍面积的低分辨率复读（60s 重画位图还引入闪烁面）。

### 4.3 Windows 版

同两枚形状，但 template 机制不存在，任务栏深浅不可控。生成 Windows 变体时给形状加
**2px 白色描边底衬**（先画白色放大形状、再叠黑色形状），深浅任务栏都保底可见。
v1 不做 Windows 数字徽章（PRD 已定二期）。

## 5. 设置开关文案（逐字）

设置面板新增一节「菜单栏读数」，置于「计费窗口」节之后（同一数据链路的两个出口）。
结构照 ThresholdsPanel 既有 field 形态（label / control / hint，全部走令牌）：

- **节标题**：`菜单栏读数`
- **节导语（note）**：`菜单栏图标常驻显示限额读数，数字与本机日志同步，不联网。`
- **开关 label**：`关闭窗口时驻留菜单栏`
- **开关 hint（开态默认）**：
  `开启后点窗口关闭按钮只隐藏窗口，读数继续在菜单栏更新；退出请点菜单栏图标选「退出 CC Analyzer」。`
- **关态补充 hint（勾掉后追加一行，照「启用本地归档」的先例）**：
  `关闭后恢复原行为：关窗即退出应用。`

语义变化本身进 CHANGELOG 的 Changed 段（design.md 1.1 已定，此处不重复）。

## 6. 数字格式惯例对照（托盘 vs 应用内）

| 数字 | 托盘 | 应用内出处 | 一致性 |
| --- | --- | --- | --- |
| 百分比 | 整数、无小数、无空格 | BillingWindowCard `(p*100).toFixed(0)` / `Math.round` | 同式 |
| token 数 | `formatTokenCount` 原样 | Gauge 中心值、周消耗 | 同函数 |
| 倒计时 | `formatCountdown` 原样（`2 时 12 分`） | 窗口关闭读数 | 同函数 |
| 时钟 | `formatClock`（HH:mm） | 窗口开启/关闭读数 | 同函数 |
| 预计时刻 | `formatPredictionTime`（MM-DD HH:mm） | 预计到达限额 | 同函数 |

**红线**：托盘侧禁止出现任何新格式化函数——一个数字两种写法就是两套口径的开端。

## 7. 明确不做（v1）

- 不做菜单栏读数的颜色自定义、主题、字体设置（title 是系统渲染文本，本就不可样式化）
- 不做多账号 profile（PRD 红线，此处重申：托盘读数只反映本机日志）
- 不做刷新间隔设置（固定 60s；竞品的 5–300s 可配是它 API 拉取的避险需要，我们数据在本机）
- 不做 Windows 数字徽章图标（二期，PRD 已定）
- 不做点击托盘弹自定义 popover（muda 菜单已够；竞品 popover 是 macOS 独占形态，与跨平台定位冲突）
- 不做按模型分解的托盘读数（tooltip 保持「两层窗口」骨架，模型分解留在应用内「工具与 skill」面板）
- 不做「已用 / 剩余」切换（口径固定为已用；一切换就是第二套口径）
- 不常驻轮询网络（PRD 红线）
