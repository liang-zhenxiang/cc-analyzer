### 命令形态的核实

`claude --help` 实测确认：`-r, --resume [value]  Resume a conversation by session ID`。
命令本身没问题，但有个容易踩的点：**Claude Code 按项目目录组织会话**，
从别的目录执行 `claude --resume <id>` 未必能找到该会话。

所以复制的命令必须**自带目录**：

```
cd "<会话的 cwd>" && claude --resume <session-id>
```

这样用户粘进终端就能直接续上，而不是粘完发现「找不到会话」再来提 issue。
若实现时发现 `cwd` 缺失（老会话或元数据不全），降级为只复制
`claude --resume <session-id>`，并在旁边明示「需在该会话的项目目录下执行」——
**降级要可见，不能静默给一条会失败的命令**。

## 用户故事

- 作为**使用者**，我在应用里翻到一个想接着聊的老会话，点一下就拿到能直接粘贴执行的命令，
  不用自己去翻 UUID、不用回忆那个会话在哪个目录。
- 作为**使用者**，复制成功后我得到明确反馈（复制到了什么），而不是「点了没反应」。
- 作为**隐私敏感的使用者**，我复制的命令只进我的剪贴板，应用不把它写进任何日志。

## 功能需求

1. **复制 resume 命令**：会话详情处提供一个按钮，复制
   `cd "<cwd>" && claude --resume <session-id>`（`cwd` 缺失时按上面的降级规则）。
   - 位置由设计决定，建议放在会话头部（`SessionHeader`）的既有动作区，
     与「打开位置」同一档；也可同时出现在会话列表的右键/更多菜单（若成本允许）。
   - 走既有 `clipboard` 桥（`web/src/api/types.ts` 的 `ClipboardService`），
     不新增 Tauri 命令、不加 capability。
   - 反馈沿用既有 `runAction(...)` 的提示语言（如「已复制 resume 命令」）。
2. **`sessionId` 缺失的降级**：没有 `sessionId` 的会话，按钮应**禁用并说明原因**，
   而不是复制一条残缺命令。
3. **不在日志中输出**：命令里含用户路径与会话 ID，属敏感数据（`AGENTS.md` 红线）。
   实现不得 `console.log` 该命令内容；测试断言用假数据。
4. **标题可读性核验**：抽查若干真实形态的 JSONL 夹具，确认列表标题不是原始首行
   （含命令标签、系统提醒噪声）而是清洗后的摘要；若有明显退化则一并修，
   并在 PR 里附「改前 / 改后」的标题对照。

## 约束

- **保持只读定位**：不内嵌恢复执行、不调用 `claude` 进程、不写 `~/.claude` 下任何文件。
- 剪贴板是既有的平台桥；不得为此放宽任何 capability 或文件系统权限。
- 不得把 `cwd` 之外的敏感字段（API key 之类）拼进命令。
- 新增 UI 必须带单测（复制内容、降级禁用、可访问名）与必要的 e2e 断言。

## 非目标

- 「用 AI 为会话生成标题」的轻量入口（Issue 里提到「可沿用报告生成能力」）——
  本轮不做，理由是它要调外部 CLI、与只读定位的边界需要单独讨论；另开 Issue。
- 一键在应用内恢复会话（越界，见`AGENTS.md` 与竞品调研的「不建议跟进」条目）。
