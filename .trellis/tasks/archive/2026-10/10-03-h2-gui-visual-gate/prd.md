# PRD：真机截图视觉门禁（几何断言 + 多页归档）

> 对应 Round H 子任务 2 · 创建于 2026-10-03
> 发现方式：本轮 H1 的两处门面缺陷，**都是靠人肉看截图发现的**——这不是可持续的防线

## 背景

### 现状：真机层能出图，但不判定

`scripts/gui-test.sh` 已经很强：真机启动 → 进程存活 → 元数据缓存条目数与隔离性 →
把 webview 渲染成 PDF → 转 PNG → **非空白判定**（≥20 种颜色）。取图走
`WKWebView.createPDF`（`src-tauri/src/lib.rs` 的 `gui_capture` 模块），**不需要屏幕录制权限**。

但它对**界面本身**只判「非空白」。「表盘被撑成 1020px」这种缺陷在它眼里完全合格——
图有内容、颜色够多、链路走通。于是缺陷一路漂到 README 首图。

### 而且文档写错了自己的能力边界

`.trellis/spec/testing/index.md` 的三层表里写着 GUI 层「**抓不到什么**：界面细节
（截图受系统权限限制）」。这句话在 `gui_capture` 落地之后就已经不成立——
权限限制是「不能截屏」，而它根本不需要截屏：它让 WebKit **渲染自己**。
一句过时的自我设限，会直接导致「界面问题不用在真机层防」的错误结论。

### 还有一个能力缺口：只覆盖默认视图

`CCA_GUI_CAPTURE_TAB` 只接受**一个**标签页名，所以每次真机运行只能额外覆盖一个非默认视图。
本轮已经出现「默认视图正常、切到用量总览才发现表盘炸了」的实例。

## 用户故事

- 作为**维护者**，我改完 CSS 跑一次真机测试，若布局回归（元素被拉伸、列被裁切、
  出现横向溢出），测试**直接失败并指出是哪个不变量破了**——而不是等我在截图里用眼睛找。
- 作为**贡献者**，我提交 PR 时真机截图覆盖全部主要视图，维护者不必要求我补图。
- 作为**未来的自己**，我读 spec 时不会被「GUI 层抓不到界面细节」这种过时结论误导。

## 功能需求

1. **真机几何探针**：应用在 `gui-capture` feature 下支持 `CCA_GUI_PROBE=<path>`，
   在 webview 渲染稳定后取回一份**原始几何事实**并写入该路径（JSON）。
   - 取回方式用 WebKit 的 `evaluateJavaScript:completionHandler:`（与既有
     `createPDF` 同一套 objc2 调用路径），**不要**用 `eval`——`eval` 是单向的，
     拿不到脚本返回值。
   - 探针只收集**事实**（元素矩形、`scrollWidth`/`clientWidth`、视口尺寸），
     **不内置任何断言或阈值**。判定逻辑留在测试脚本里——应用不该携带测试策略。
   - 未设该环境变量时完全惰性，与 `CCA_GUI_CAPTURE` 的既有行为一致；
     仍只在 macOS + `gui-capture` feature 下编译。
2. **多视图取图**：`CCA_GUI_CAPTURE_TAB` 接受**逗号分隔的多个**可访问名，
   依次点击并各出一张 PDF。保持向后兼容（单个值仍工作，输出文件名规则不变）。
3. **测试脚本判定布局不变量**：`gui-test.sh` 读取探针 JSON 后断言
   - **无横向溢出**：文档 `scrollWidth <= clientWidth + 1`
   - **表盘有界**：表盘宽度 ≤ 阈值且**完全落在其所在卡片矩形内**
   - **表格末列可达**：记录表最后一列的右边界不超出其滚动容器右边界，
     或该容器确实处于可横向滚动状态（`scrollWidth > clientWidth` 且容器有滚动提示）
   - **视图覆盖完整**：本轮约定的全部主要视图都有对应产物，缺一即失败
4. **每个产物都过同一套判定**：多出的每张 PDF 都走与第一张相同的
   「转 PNG + 非空白」流水线，任何一张取不到都计失败（不是跳过）。
5. **文档纠正**：更新 `.trellis/spec/testing/{index,gui-tests}.md`，
   把 GUI 层「抓不到界面细节」的过时结论改成它**能**判定的东西，
   并写明探针机制与「断言在脚本、事实在应用」的分工。

## 约束

- 不得引入屏幕录制权限依赖；不得读屏幕像素做判定（阈值脆弱且与渲染差异耦合）。
- 探针与多标签支持**只在 `gui-capture` feature 下编译**；
  发布产物（不带该 feature）不得包含任何测试代码路径。
- `gui-artifacts/` 仍为 gitignore，不得提交。
- 断言的值必须**与渲染引擎差异无关**（几何关系、包含关系、是否溢出），
  不得断言具体像素坐标或颜色。
- 现有 8 项检查（存活/内存记录/缓存存在/条目数与隔离/取图/转 PNG/非空白/正常退出）
  不得削弱；新增检查接进同一套 `step`/`ok`/`bad` 计数器与退出码。

## 非目标

- 不做像素级截图 diff 或视觉回归基线比对（噪声高、维护成本高、意图不明确）。
- 不把真机测试搬进 CI（CI 无 macOS runner，成本不划算——见 gui-tests.md 既有结论）。
- 不引入浏览器自动化驱动真机（`osascript` AX 在本项目已验证不可达）。
