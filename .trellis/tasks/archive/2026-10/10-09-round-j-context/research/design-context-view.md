## 0. 设计原则

**把上下文当作一种会被耗尽、也会被主动放掉的资源来读。** 曲线画出它如何涨满，
断崖记录它何时被重置；这台仪器的职责是让用户能指认「哪一句话是在这里离开
上下文的」——只陈述日志里读得到的（何时、丢了多少、幸存什么），不推测日志里
没有的（上限是多少、下次何时触发）。

由此派生三条视觉纪律：

1. **断崖本身是主角，标记是注脚。** 压缩在数据里已经是一个剧烈的视觉事件
   （pre→post 通常差 30–40 倍），标记（竖线 + 菱形）只负责「可定位、可点击」，
   不负责「更醒目」——不加重、不加底色带、不加旗标杆。
2. **压缩不是第七种类别，是结构。** 六个行类别回答「活动去哪了」（时长 / 占比
   的分区）；压缩边界是 system 记录，回答「对话在哪重启」。它用几何（通栏带行）
   与形状（◆）表达身份，不占用色相（论证见 §6）。
3. **取证清单用用户已认识的语言。** 「被丢出的内容」逐行复用日志表的行语言
   （时间 · 类型徽章 · 动作 · 摘要），用户不需要学第二种扫读格式。

## 1. 关键取舍（先读这张表，别在实现时重新发明）

| # | 问题 | 决定 | 理由 |
| --- | --- | --- | --- |
| 1 | X 轴用墙钟时间还是消息序号 | **消息序号**（第 N 条 assistant 消息），时间进 tooltip 与事件条 | 压力是「对话推进」的函数；墙钟轴下跨天的会话会把密集段挤扁、把午休拉成悬崖。用户的痛点句式是「40 轮前给的约束」，按轮计数才对得上 |
| 2 | 画不画「满 200K 危险区」参考线 | **不画** | 没有官方上下文上限的可靠数字；画一条无来源的刻度线违反 provenance 原则（本应用的立身之本）。断崖位置本身就是「何时触发」的经验证据，Y 轴顶格即峰值 |
| 3 | 压缩标记的形 | 竖发丝线 + 实心菱形（◆），全事件同形；trigger（自动/手动）不进图 | 断崖已抢眼，标记要能反向找到即可。trigger 是次要属性，进 tooltip / 事件条 / 取证卡（文字），不进图形——也顺手满足了「不靠颜色区分语义」 |
| 4 | 压缩行 / 标记用什么颜色 | **不新增颜色**。图上菱形 = `--chart-1`（该系列的注记），日志表 = 中性通栏带行 | 两主题下七个色系各有主：深色橙区被 `--warning` 占死（`#e69f00` 与 `#e0a33e` ΔE 仅 2.3）、亮蓝区被 `--accent` 占死（`#7cc7f2` 与 `#7fa8ff` ΔE 9.0）、青区被 `--chart-2` 占死。实测数据见附录 |
| 5 | 曲线形态 | **面积图，直折线，不平滑** | 单系列（form heuristic：trend + 单系列 → area）。样条平滑会捏造数据里没有的形状，仪器不造假 |
| 6 | 子 agent 侧链画不画 | **不画，只画主对话**（`isSidechain === false`） | 侧链是另一个上下文，混进主曲线会画出一条从未存在过的压力 |
| 7 | 上下文页是否受 FilterBar / 时间轴筛选 | **不受，且这两条在上下文标签页隐藏** | 取证口径是「压缩点之前全部消息 − 幸存清单」，筛选会让口径漂移；隐藏还回收约 120px 垂直空间给取证清单 |
| 8 | 用量面板「自动/手动」两系列用哪两档 | **`--chart-1` + `--chart-4`**（蓝 × 金，暖冷对峙） | 相邻堆叠下 `chart-1/chart-2` 深色 CVD ΔE 仅 3.7（蓝/青塌缩）；1+4 两主题实测 ΔE 21–24。固定槽位顺序让位于验证结果，且只是本面板内的槽位选择，不是全局改序 |
| 9 | 解析覆盖率全绿时显不显示 | **M=0 时不显示任何东西** | 「全部解析」是默认期望，不是新闻。常驻「覆盖 100%」会重蹈 Round I 的 provenance 噪音（一句「读自日志」重复 5–6 次成了全页最响的颜色） |

### 2.2 上下文压力曲线（图表规范）

**数据**：主对话（`isSidechain === false`）每条 assistant 记录一个点：
`x = 序号（1..N）`，`y = input_tokens + cache_read + cache_creation`。
压缩边界记录本身没有 usage，不产生数据点——断崖由 pre 侧末点与 post 侧首点的
落差自然形成。

**形**：单系列面积图。描边 `--chart-1` 2px（round join/cap）；填充
`--chart-1-soft`；直折线，**禁用任何平滑**。

**降采样**（长会话 5k+ 消息）：目标 ≤720 点（= viewBox 宽）。分桶
`ceil(N/720)`，每桶保序保留 `{min, max}` 两点；**强制保留**：每个压缩边界的
pre 侧末点与 post 侧首点、全局峰值点——朴素 LTTB 会把断崖磨圆，这几类点
不许被采样掉。

**坐标轴**（复用 `chartPrimitives.tsx`，不另起炉灶）：

- Y 轴：`niceAxisMax(峰值)` + `axisTicks(max, 3)`（1/2/5×10ⁿ），`formatAxisValue`
  compact（`400K`），`GridLine` 中性灰，基线 `strong`。从 0 起（面积图的底线）。
- X 轴：刻度为消息序号，步长取 `niceStep(N/8)`（同样 1/2/5×10ⁿ），只标数字；
  轴下一行 `caption`（沿用 `BarChart` 的 caption 惯例）写口径：
  「横轴 = 模型消息序号（非墙钟时间）· 纵轴 = 该次调用喂给模型的 token 总量
  （输入 + 缓存写入 + 缓存读取，与日志表『提示词』同口径）」。
  同一数字两个名字（提示词 / 上下文规模）必须在某一处被一句话缝合，否则
  跨视图对不上账。
- **选择性直标**：全局峰值点标 `峰值 422.9K`（`--fs-xs`，`--text-secondary`，
  点上方 4px；与事件标记碰撞时向右上避让）。其余读数交给轴 + tooltip。

**压缩事件标记**（不抢戏的三件套）：

1. **竖发丝线**：`--border-strong` 1px，全绘图高，立在断崖 x 的中点
   （pre 末点与 post 首点之间）。它是定位线（chrome），不是数据——所以用
   中性色而非 `--chart-1`，与水平网格线（`--border`）只差一级、方向正交。
2. **菱形**：`--chart-1` 实心，外接圆直径 ≈10px，2px `--bg-subtle` 表面环
   （dataviz 标准做法，压线也可辨），中心落在竖线上、y 取 pre 值——标记
   「上下文在此触顶后跌落」。
3. **命中区**：每个事件一根 24px 宽 × 绘图高的透明矩形（菱形本身太小，
   永远不要让用户瞄准 10px 的点）。

选中态（见 §7）：菱形外再加 2px `--accent` 环 + 事件 chip 联动高亮。
hover 态：竖线加深为 `--chart-1`、菱形放大到 12px（`--dur-hover`）。

**图例**：单系列不设图例盒（标题已命名该系列）。◆ 的含义由事件条与 caption
的文字承担。

**tooltip**（HTML 浮层，复用 `TimelineTrack` 的 tooltip 画法与定位逻辑）：

- 悬停曲线（crosshair 吸附最近点，二分查找）：第一行 **值打头**
  （`422,858 tok`，`--text` 600）+ `第 1,402 条`（`--text-tertiary`）；
  第二行 `16:52:41`；第三行 breakdown `输入 1.2K + 缓存写入 210K + 缓存读取 211K`。
- 悬停事件命中区：`◆ 压缩 #2 · 16:53:12 · 自动`；
  `422,858 → 11,359（丢弃 411,499）`；`耗时 37.5s · 幸存 6/186 条`；
  末行 `--text-faint` 提示「点击查看取证」。
- tooltip 不做唯一通道：事件条与清单是它的 DOM 文本孪生（§8）。

### 2.3 压缩事件条与取证卡

**事件条**：一行 chip，横向滚动（`overflow-x: auto`，常驻滚动条
`--scrollbar-size`）。每个 chip：`#2 09-30 16:53 · 自动 · 423K→11K`，
`--bg-inset` 底 + `--border` 发丝边 + `--fs-xs`；选中 =
`--accent-soft` 底 + `--accent` 描边 + 文字转 `--text`（与 SegmentedControl
选中态同一套三信号）。chip 是真 `<button aria-pressed>`。编号 `#k` 是会话内
时间顺序号，与日志表带行、取证卡共用同一编号（三个视图指同一个事件用同一个
名字）。

**取证卡**（选中事件后渲染；未选中时此位置显示一行
`--text-tertiary` 引导：「点击曲线上的 ◆ 或上方事件条查看取证」）：

数字栏（`<dl>` 形态，label `--fs-xs` tertiary / value `--fs-md` 600 tabular-nums，
与 KPI 卡同构但降一级字号——卡内层级低于页面 KPI）：

| 字段 | 内容 | 备注 |
| --- | --- | --- |
| 上下文规模 | `422,858 → 11,359` + `(−97.3%)` | 百分比 = (pre−post)/pre |
| 曲线两侧读数 | `422.1K / 11.9K`（`--fs-xs` tertiary） | 元数据与曲线互证的一致性检查，仪器的自证 |
| 本次丢弃 | `411,499 tok` | 用 `pre − post`；**不要**再累加 `cumulativeDroppedTokens`（它已是累计值，数据约束 #4） |
| 累计丢弃 | `411,499 tok` | 直读元数据 |
| 压缩耗时 | `37.5s`（`formatDuration`） | |
| 幸存消息 | `6 / 186 条 [▸]` | 展开列出幸存清单（时间 + 摘要行，最多十几条，直接铺开） |

数字栏顶部：`◆ 压缩 #2 · 2026-09-30 16:53:12 · 自动`（trigger 一律文字，
永远不编码成颜色）+ 一枚 `ProvenanceBadge logged` 圆点（整块数字同一来源，
一枚就够——Round I 的教训：同一句话不重复五遍）。

### 2.4 被丢出上下文的内容（清单）

口径（写进组件注释，防实现走样）：**该边界之前出现过的全部消息 −
`preservedMessages.uuids`**；跨多次压缩时同一条消息只在**首次**被丢的边界下
列出（按 uuid 去重）。挂靠边界用 `logicalParentUuid`（`parentUuid` 是 null，
数据约束 #1）。

- 表头行：`被丢出上下文的内容 · 180 条` + 右侧 `SegmentedControl`
  （`全部 | 仅用户`，默认**全部**——完整事实在前，过滤是用户的选择）。
  「仅用户」是第一问（「我的约束是什么时候丢的」）的一键答案。
- 行：完全复用日志表的行语言——`时间 · 类型徽章（带各自类别色竖条）· 动作 · 摘要`。
  这里的类别色是对的用法：清单里列**是**消息，消息有类别。
- 行高 `--row-h`，**虚拟滚动**（复用 `virtualWindow` / `measuredRows` 基建，
  与 LogView 同一套），5k 行与 50 行同一体验。
- 行可点击 / Enter：跳到日志视图并定位该记录（现有 `locateInLog` 流程），
  高亮闪烁沿用 `highlight` 动画。「在哪丢的 → 去哪看全文」一步到位。
- 侧链消息照列（它们同样离开上下文），徽章注明所属类别即可。

### 2.5 多次压缩的节奏

曲线的多段锯齿 + 事件条的 `#k … pre→post` 序列共同回答「节奏」：两次压缩的
间隔（横轴跨度）、每次触顶的高度是否一致（视觉上一排等高断崖 = 稳定的自动
触发水位；忽高忽低 = 手动混入）。不为此再加缩略图或小多图——数据已在主图上。

### 2.6 空态与降级

| 情形 | 呈现 |
| --- | --- |
| 无压缩、有 usage 数据 | 曲线照画（单调增长本身有信息），事件面板体 = 一行 `EmptyState inline`：「本会话未发生压缩——上下文从未重置」+ 峰值已在上面板 actions 里。**不**渲染空 chip 条、不渲染大空盒 |
| 无 assistant usage（画不出曲线） | 上面板体 = `EmptyState panel`「没有可绘制的上下文数据（本会话没有带用量的模型消息）」；事件面板不渲染 |
| 压缩元数据缺字段（旧版本日志） | 取证卡对应行显示 `—` 并降级说明「该字段此记录未记录」；曲线照画。宁可说数据不足，不猜 |

## 3. 视图 B：日志表第七种行类型——「压缩边界」行

**放置**：按边界时间戳插入行序（`logicalParentUuid` 挂靠）。紧随其后的
`isCompactSummary: true` 摘要消息**不单独成行**——折叠进带行的展开区
（数据约束 #3：它不是用户发言；这也顺手修掉现有解析把它当 user 行的问题）。
实现上与 `buildGapRows` 合成 wait 行同一模式：从 records 里摘出，另行合成。

**形态：通栏带行（`colspan=8`），不是带列的消息行。**

```

├───────────────────────────────────────────────────────────────────────────────────┤
│ 16:53:12  ◆ 压缩 #2（自动）· 422,858 → 11,359 tok · 丢弃 411,499 · 37.5s    ▶   │ ← 带行

│ 16:54:02 │ 用户+LLM │ 继续改测试 · 好的… │ 11.9K/0.9K │ 12.0s │▓0.9%│ 正常 │ ▶│
```

- 底色 `--bg-inset`（比白卡低一级的台阶），上边框 `--border-strong`

  与「在树视图定位」同款按钮）。
- 树视图 / 耗时统计**不**纳入压缩行（它是结构，不参与「时间去哪了」的分区）。

## 6. 令牌映射表

**结论：本模块零新增令牌。** 每个新界面元素都落在既有令牌上：

| 元素 | 令牌 |
| --- | --- |
| 曲线描边 / 菱形 / C 面板「自动」系列 / 覆盖率分布条 | `--chart-1`（浅 #2f6b9f / 深 #82b5e8，面板底对比 5.17 / 7.83:1） |
| 曲线面积填充 | `--chart-1-soft`（0.24 / 0.30） |
| 事件竖发丝线 / 带行上边框 | `--border-strong`（chrome，与网格 `--border` 差一级） |
| 菱形表面环 | `--bg-subtle` |
| 事件 chip 底 / 带行底 | `--bg-inset`（台阶语言） |
| 事件 chip 选中 | `--accent-soft` + `--accent` + 文字 `--text`（SegmentedControl 同款三信号） |
| 菱形选中环 / 键盘焦点行 | `--accent`（选中是 accent 的本职：「选中底」） |
| 取证卡数字 | `--fs-md` 600 + `font-variant-numeric: tabular-nums`（KPI 同构降一级） |
| 清单 / 带行文字 | `--text-secondary` / `--text-tertiary` / `--fs-sm` / `--row-h` / `--row-pad-*` |
| 覆盖率圆点 | `--warning`（琥珀 = 非确定信息，语义严丝合缝） |
| 弹出卡 | `--bg-elevated` + `--r-lg` + `--shadow-md`（浮层分工） |
| C 面板「手动」系列 | `--chart-4` + `--chart-4-soft`（论证见 §1-8） |
| 间距 / 圆角 / 时长 | 全部 `--sp-*` / `--r-*` / `--dur-*` 档位 |

**为什么不新增第七个类别色（被否掉的候选，防止后人再试一遍）：**

- Okabe-Ito 橙 `#e69f00`：浅色下与 `--cat-delegated` ΔE 13.1/15.6 勉强过，
  但深色下与 `--warning #e0a33e` **ΔE 2.3**（同色）；加深躲 warning 又撞
  delegated（`#d08700` vs `#d55e00` = 5.8/9.3，FAIL）。橙区两主题无解。
- Okabe-Ito 天蓝 `#56b4e9`：浅色过；深色提亮后 `#7cc7f2` 与 `--accent #7fa8ff`
  ΔE 9.0（普通视觉地板 15 之下）。亮蓝区被 accent 占死。
- 青/teal（`#0e8a7d` / `#4ecdb8`）：浅色 vs `--cat-compute` 6.8（FAIL），
  深色 vs `--chart-2` 5.9（FAIL）。青区两头被占。
- 黄 `#f0e442`：白底对比 ~1.6:1，出局。

即：**色轮盘在两套主题下已经铺满，任何新色要么撞语义色、要么撞类别色、
要么撞图表色。** 而压缩边界恰好不需要颜色——它不是活动类别（§0-2），
几何（通栏带）+ 形状（◆）+ 文字承载身份，两主题零成本、CVD 零风险。
这是「约束逼出来的正确答案」，不是妥协。

## 7. 交互规格汇总

**指针**

- 曲线：crosshair 竖线吸附最近点（x 二分查找）+ tooltip；离开绘图区即消隐。
  指针移动经 rAF 合帧，不逐 mousemove setState。
- 事件：24px 全高命中区；hover = 竖线加深 + 菱形放大（`--dur-hover`）+
  事件 tooltip；click = 选中该事件（取证卡渲染、chip 同步选中）。选中是
  视图内状态，不进路由。
- 图空白处 click = 取消选中（回到引导行）。
- chip / 清单行 / 带行 / 覆盖率 chip：原生 button / 行点击，无自定义指针目标。

**键盘**

- 图容器：`tabindex=0`，`role="img"` + 描述性 `aria-label`
  （模板：「上下文压力：1,842 条模型消息，峰值 422,858 tok，3 次压缩」）。
  聚焦后 `←/→` 在压缩事件间移动（roving 高亮，朗读事件摘要），`Enter/Space`
  选中，`Esc` 取消。事件本身不各自占 tab 位（事件条是它的键盘孪生）。
- 事件条 chip：原生 button，Tab 可达，`aria-pressed`。
- 被丢清单：复用 `useRowNavigation`（↑↓ 移动、Enter 激活跳日志视图、
  焦点行 = `--bg-hover` + `inset 2px --accent`，与日志表逐字一致）。
- 焦点可见性永远不依赖颜色单信号（选中态有底色 + 字重双信号）。

**性能约束（长会话 5k+ 消息）**

- 曲线 ≤720 采样点（§2.2 规则），路径一次生成 `useMemo`（随 parsed 变化）。
- 被丢清单虚拟化（`virtualWindow` + 实测行高缓存），`--row-h` 行高。
- 事件条 ≤ 数十个 chip，横向滚动即可，不分页。
- 取证数字随选中事件 `useMemo`，切事件不重算全量。
- 无布局动画；过渡只用 `--dur-hover` / `--dur-state`。

**字号缩放 90–130%**

- 全部文字走 `--fs-*`/`--lh-*` 成对令牌，自动缩放。
- SVG 内 `tickText` 用 CSS `font-size: var(--fs-xs)`，随 viewBox 等比——
  与现有图表行为一致，不单独处理。
- 带行 / chip 单行放不下时 ellipsis + `title` 兜底；事件条横向滚动；
  取证卡 <880px 上下堆叠。

## 8. 无障碍

- **压缩身份永远不靠颜色单独承载**：曲线 = ◆ 形状 + 竖线；日志表 = 通栏带
  几何 + 「压缩」文字；事件条 / 取证卡 = 文字。灰度打印 / 全色盲下全链路可辨。
- **trigger（自动/手动）永远是文字**，不进颜色 / 形状编码。
- 对比度：数据标记（`--chart-1`、`--chart-4`、类别色竖条）≥3:1（图形件门槛，
  两主题实测达标，tokens.css 注释为证）；正文 ≥4.5:1（`--text-secondary`
  两主题 7:1 上下）。事件竖线（`--border-strong`）≈1.5:1，**接受**——它是
  recessive chrome（定位线），身份由达标的 ◆ 与文字承担；水平网格线同理
  且是既有惯例。
- tooltip 同样作用于键盘聚焦（focus 显示 = hover 显示），且每个 tooltip 值
  都有 DOM 文本孪生（事件条、清单、直标）——tooltip 增强、不设卡。
- 屏幕阅读器：带行读出其完整文字；清单是真列表；图是 `role=img` 带摘要；
  弹出卡 `role=dialog`（非模态）+ `aria-labelledby`。
- 色盲（protan/deutan）专项：本模块唯一相邻彩色对是 C 面板的 chart-1/chart-4
  （实测 ΔE 21–24，两主题），且带 2px 表面缝 + 图例 + 数值直标三重冗余。

## 9. 明确不做什么（防实现者跑偏）

1. **不画 200K / 1M「官方上下文上限」参考线**，也不做用户自设参考线设置面
   （无可靠来源的刻度 = 伪造仪器；断崖即经验证据）。
2. **不引入第三方图表库**；不加曲线平滑 / 渐变填充 / 阴影。
3. **不给压缩新增第七个类别色**，不借 `--warning` / `--success` / `--danger`
   表达压缩（§6 的完整论证与被否候选）。
4. **不把压缩行塞进树视图 / 耗时占比**（结构不参与活动分区）。
5. **不在上下文标签页渲染 FilterBar / TimelineTrack**，也不让记录筛选作用于
   曲线或被丢清单（取证口径不可漂移）。
6. **不做压缩预测 / 水位预警 / 「还能聊多少轮」**（推断层，宁可说数据不足）。
7. **不把 `isCompactSummary` 摘要渲染成用户行**（数据约束 #3）。
8. **不自己累加 `cumulativeDroppedTokens`**（它已是累计值，数据约束 #4）。
9. **不画侧链（isSidechain）的上下文曲线**——那是另一个上下文。
10. **覆盖率报告不上传、不落盘**——纯剪贴板；报告里不用绝对路径。
11. **tooltip 不做唯一读数通道**；任何值都有非悬停路径。
12. **不给「压缩统计」面板画每会话排行图**（top 3 文本清单足够，图表化是花哨）。
