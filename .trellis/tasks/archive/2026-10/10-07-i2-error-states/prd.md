# PRD：I2 · 错误态与空态统一（含用户路径不再进 UI）

**父任务**：`10-07-round-i-truth` · **优先级**：P0

## 为什么

设计评审用「声明的路径不存在」触发了真实错误路径，发现**三种互不一致的呈现**，
其中两条直接踩到项目的红线：

1. **侧栏内联**：粉色底红字四行，内容是
   `扫描会话列表失败: Error: E2E 虚拟文件系统: readDir 遇到未声明的路径 /Users/e2e/.claude/projects。请在夹具里声明它——静默返回空数组会把夹具错误伪装成成功缺陷。`
   - **夹具说明进了用户界面**
   - **绝对用户路径进了用户界面**（红线：用户路径视同敏感数据）
   - 同一屏下面还显示「没有匹配的会话 / 调整搜索词后重试。」
     ——**错误与「没有匹配」自相矛盾**，且后者的建议完全错
2. **用量页整页**：图标 + 标题 + **一整行横跨约 1000px 的 12px 灰字**（远超可读行长）、
   **顶部对齐**（与其它空态的居中不一致）、**无重试、无退出**
3. **监控页**：居中、有按钮、可操作——**这一种是对的**

> 错误态是用户对「这软件可靠吗」的全部判断依据。

## 需求

### 1. 新增 `components/ErrorState`，三个调用点归一

```ts
type ErrorStateProps = {
  title: string;   // 一句话说清什么失败了，面向使用者
  hint: string;    // 可执行的下一步
  detail?: string; // 原始错误串 —— 只进 <details> / 复制按钮
  onRetry?: () => void;
  size?: "page" | "panel" | "inline";
};
```

- 三种位置差异用 `size` 表达，**同一套语义只有一个组件**
- 必须复用既有 `Button`，不得手写第二套按钮画法（v0.11.0 已立此规矩）
- `size="page"` 的内容宽度受限（可读行长 ≤ 约 640px），不得横跨整屏

### 2. 原始错误串不进正文（P0，红线）

- 界面上**不得出现** `/Users/...`、`/home/...` 这类绝对路径
- 界面上**不得出现**写给维护者的话（「夹具」「静默返回空数组」「E2E 虚拟文件系统」）
- 原始串收进 `<details>` 折叠区或「复制详情」按钮；复制内容是用户的主动动作，
  与「把路径糊在脸上」是两回事
- **测试强制**：渲染错误态后断言可见文案里不含 `/Users/`、不含 `夹具`

### 3. 错误与空态不再同屏矛盾（P0）

错误发生时不再渲染「没有匹配的会话」那类空态，也不给错误的建议。

### 4. 文案给可执行的下一步

- 监控页：「打开后会内嵌本机 localhost 上运行的监控仪表盘。**该服务不在本仓库内，
  需要另行启动。**」→ 终端用户读到这句就结束了。
  改为给出**端口号、启动方式、文档链接**中的至少两样，并保留重试。
  **不得**出现「不在本仓库内」这类维护者内部信息。
- 用法说明所需的端口/命令若在 `src-tauri` 或文档里有权威来源，从那里取；
  没有则先确认再写，**不许编一个端口号**。

### 5. 加载态与空态的位置一致

三种语义（加载 / 空 / 错误）在同一个容器里的**垂直位置与对齐方式**必须一致。

## 非目标

- 不做全局错误上报 / 遥测（红线：零遥测）
- 不改 `ErrorBoundary` 的崩溃兜底逻辑（v0.11.0 已收口）
- 不动用量页的错误**判定条件**（只动它的呈现）
