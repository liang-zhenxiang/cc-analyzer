## 本轮主题

**从「花了多少」走到「做得好不好」，再让最重要的数字常驻眼前。**

Round M 竞品调研的判断：赛道上「分析」正从用量走向质量（sniffly 把错误分析当
第二卖点），而我们手里的解析数据（isError、工具调用、文件路径）早已齐备，
只是没有聚合视图。本轮一次性吃下机会清单中的四个主题，串行推进：

1. **跨会话错误分析**（#146，机会清单第 1 名）——把会话里的红字变成跨会话的规律；
2. **会话改动文件视图**（#148）——补读 `file-history-snapshot`，回答「这次会话到底动了哪些文件」；
3. **工具 / skill / MCP 使用统计**（#153）——「我装了 30 个 skill，到底哪些真的在用」；
4. **菜单栏常驻限额读数**（#150）——Tauri 原生托盘能力首次启用，限额数字常驻菜单栏。

四者共享同一条价值观：**一切数字可下钻到原始证据行，口径写在界面上**（继承
项目 provenance 传统）。

## 各子任务需求要点（细则见各子任务 prd.md，以 Issue 正文为底）

- **N1 错误分析**：按工具的失败次数与失败率、按会话/项目的失败密度、按时间的趋势
  三个切面；每条可下钻跳回日志视图定位；「什么算失败 / 分母是什么」写在界面上；
  不把「等用户输入」算失败。
- **N2 改动文件**：补解析 `file-history-snapshot`（与同批次 `attachment` / `cost-state`
  登记为已知类型进 ParseCoverage 分桶）；会话详情新增「改动」视图：按文件聚合
  Read/Edit/Write（次数、首末次时间、Write 标注新建）；路径只显示项目内相对路径；
  只读统计不做回滚。
- **N3 工具统计**：按调用次数排行 + 涉及会话数 + 时间趋势；分桶口径（内置工具 /
  skill / MCP `mcp__*` / 子 agent）写在界面上；skill 识别规则以实机抽样证据为准
  （进 PR 描述）；与既有「子 agent 全量表」不许出现两套口径。
- **N4 托盘读数**：macOS 菜单栏图标 + 读数（5h 窗口剩余 / 已用 + 周窗口），Windows
  形态按研究报告的可行方案退化（tooltip / 徽章）；托盘菜单（打开主窗口 / 用量总览 /
  退出）；数字与用量总览**同一份计算**，provenance 文案如实标注；不常驻轮询网络、
  不做 Dynamic Island、不做多账号。

## 全轮不做（继承各 Issue 的「不做」并汇总）

- 不做 MCP server 管理与编辑、不做「建议卸载哪些」（写操作与猜测都越界）；
- 不做会话回滚 / 文件恢复（file-history-snapshot 只读展示）；
- 不做服务端 / 云端同步、多账号 profile；
- 不引入新图表库（延续自绘 SVG 路线）；
- 不在日志中输出会话内容与用户路径（研究报告已脱敏，实现亦然）。

## 风险

- 四主题一轮体量大——靠严格串行 + 每子任务独立 PR 控制爆炸半径；
- N2 的 `file-history-snapshot` 结构未经实测（研究先行，结构不明确则视图先只基于
  已解析的 tool_use 聚合，快照仅登记类型）；
- N4 是本轮唯一动 Rust 侧的任务，且菜单栏文本读数在 Windows 无直接对等——
  以研究报告的跨平台方案为准，宁可 Windows 退化得朴素也不做两套口径；
- 时间预算：若中途发现单个子任务过大，允许把该子任务再拆 PR，但不允许并行实现。
