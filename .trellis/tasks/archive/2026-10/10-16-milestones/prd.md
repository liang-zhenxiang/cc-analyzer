# 里程碑：可核对的成就体系

## Goal

把**全历史**用量折成一组里程碑——每一枚都**能从本机日志逐条核对**。已达成项给的是
一份可以查证的证据（数字、日期、点得进去的会话 / 那一天），不是一句「你解锁了 X」；
未达成项给的是**诚实的距离**（「还差 12.4 万 token」），不是悬念式的灰色剪影。

用户价值：这个应用一直在回答「我花了多少 / 我的上下文怎么了」，从没回答过
**「我这一路走到哪了」**。而竞品的成就体系（TokenTracker 有 15 条轨道）恰恰是最不透明
的那类设计——徽章是别人定好的趣味，不是你自己的事实。我们的差异化很简单：
**每枚徽章都必须能被日志复算**，复算不出来就不发这枚徽章。

## Background（已核实的事实）

- **数据地基已经就位，不需要新扫描**：`useUsageOverview` 的注释逐字写着
  「this hook only ever grows the full-history view」——窗口过滤是页面的活，
  hook 本身**不做时间收窄**，全历史 `UsageSessionInput[]` 就在手边
  （`web/src/features/usage/useUsageOverview.ts:31-36`）。里程碑只要吃同一份 inputs。
- **每条里程碑的原料都在 `UsageSessionInput` 上**（`usageAggregations.ts:50-90`）：
  `records`（时间戳 / kind / usage / model）、`projectLabel` / `projectPath`、
  `compactEvents`（J1 的压缩边界）、`toolCalls`（N3 的工具事实，含子 agent 双口径）、
  `session`（`SessionMeta`：`mtimeMs`、`sessionId`、`gitBranch`、`archived`）。
- **已有现成口径，不许另写一份**：`totalsSum` / `aggregateAll`（`usageAggregations.ts`）、
  `dayStartOf` / `addLocalDays` / `formatDayLabel`、`sessionKeyOf`、
  `buildUsageCalendar` 的天粒度事实、`calendarInsightsOf` 的连胜算法、
  `dayReview` 的当天口径。里程碑的每一个数都必须**引用**这些函数，而不是重算一遍。
- **不重复 `calendarInsightsOf` 的六句**（最长连胜 / 当前连胜 / 最贵一天 / 最长空白 /
  活跃占比 / 本月环比）：那六句的口径是**滚动 365 天**，里程碑的口径是**全历史**。
  两个窗口不同的同一个概念（比如连胜）如果都出现，用户会看到两个打架的数字——
  所以里程碑**不做连胜**，连胜归日历洞察。
- **成本是估算**：金额来自 `pricingSnapshot`，且存在「定价未知」的天 / 模型
  （日历那轮已立此规矩：**定价未知的天不计入「有消耗」**）。成本类里程碑必须带
  `ProvenanceBadge`（既有组件）并把「按定价快照折算」写在明处。
- **落点**：`用量总览` 的分段控件（现在是 `用量 | 错误`，`UsageOverviewPage.tsx:44-47`）
  加第三项 `里程碑`，顺序 `用量 | 里程碑 | 错误`。理由：① 同一份全历史 inputs，
  零新增扫描；② 里程碑与「消耗日历 / 一年洞察」是同一个「用量随时间」家族；
  ③ 顶栏三个标签是应用骨架，不为一个「偶尔看一眼」的页面加第四个。

## Requirements

**R1 落点与结构。** `用量总览` 分段控件新增 `里程碑` 子视图（持久化键沿用既有
`readStoredView` 的模式，未知值回落 `用量`）。挂载里程碑**不新增任何 I/O**：
吃 `useUsageOverview` 已有的 `inputs`，与用量 / 错误两档共用同一次扫描。

**R2 口径必须是全历史。** 里程碑的窗口是**全部已扫描的会话**（含本地归档，
`SessionMeta.archived` 为真者口径同其他面板）。页面必须**逐字写明**这个窗口
（与日历的「近 12 个月」形成对照），并写明「不含 Claude Code 已清理且未归档的会话」
——我们只能对读到的日志负责。

**R3 三类里程碑，全部可核对。**

1. **首次**（firsts）：第一次会话 / 第一次压缩 / 第一次用子 agent / 第一次用 skill /
   第一次用 MCP 工具。每枚给：日期 + 可点开的目标（会话 → 打开会话；那天 → 一日回望）。
   原料不存在的（例如从没用过 skill）**不显示这枚**，不显示成「未达成」——
   「你还没用过」与「离达成还差多少」是两件事。
2. **累计阶梯**（cumulative tiers）：累计 token / 累计会话数 / 累计消息数 /
   涉及项目数 / 用过模型数 / 累计压缩次数 / 累计调用工具种类数。每枚给：当前值 +
   已达档位 + **到下一档的诚实距离**。档次是**写死的常量并逐条可测**。
3. **单会话记录**（records）：单会话最多 token / 单会话最长时长 / 单会话最多压缩次数。
   每枚给：值 + 是哪个会话（标题 + 日期）+ 点进去打开那个会话。

**R4 未达成项的形态。** 阶梯未达下一档时显示的是**距离**（`还差 N`）与当前值，
不显示灰色剪影、不显示锁定图标、不显示「??」。没有下一档（已达最高档）显示
「已到最高档」而不是留白。

**R5 证据必须可展开 / 可点。** 每枚里程碑都有：值（tabular 数字）、口径一句话、
以及（有目标时）一个可点入口。数字与入口指向同一份事实——点进去看到的会话 / 那天，
必须能对上卡片上的数。

**R6 空态与失败态。**
- **扫到 0 个会话**：整页一条事实行（不是「0 枚徽章」的空货架）。
- **扫描失败**：沿用 `ErrorState`，与用量页同一套（不另造错误语言）。
- **扫描中**：里程碑区与用量页同款骨架，不出现「0」这种假读数。
- **数据不足但 ≥1 个会话**：能算的照算，算不出的那几枚**不渲染**并给一行原因
  （例如「本机日志里没有 skill 调用记录」）。

**R7 视觉。** 界面美观度第一位：由 UI/UX 设计师 agent 出规格，主会话独立评审后再实现。
浅 / 深 / 高对比度三档、字号 130% 下无横向溢出；**全部用既有令牌**（目标零新增颜色；
若设计师判定必须新增，须给出可复算的对比度表与理由）。已达成 / 未达成两态必须
由**几何与层级**区分，不能只靠灰一档（高对比度下灰阶会塌缩）。

**R8 无障碍。** 每枚里程碑是一个可读的语义单元；值、口径、入口都有可访问名；
阶梯进度条（若有）用 `role="img"` + 文字摘要或 `progressbar` 语义；键盘可达。

**R9 性能。** 里程碑计算必须 `useMemo` 且只在 `inputs` 变化时重算；
在合成大夹具（≥300 会话）上量一次单次重算耗时并写进 PR。目标：**< 150 ms**，
超出则先优化再合并（不许「反正只算一次」）。

**R10 隐私。** 纯本地、不新增网络请求、不新增 Tauri 命令、不加权限。
里程碑文案里**不出现绝对路径**，项目名走既有的 `formatProjectPath`。

**R11 测试（全部自动）。**
- 单元：三类里程碑的纯函数——正常 / 边界（正好达成 / 差一点）/ 并列（同值取谁）/
  全空 / 畸形输入（NaN、负值、重复路径）；阶梯常量逐条钉死。
- 组件：已达成与未达成两态、距离文案、空态、失败态、点入口回调。
- 端到端（Chromium + WebKit）：切到里程碑档看到确定值；点一枚首次里程碑的入口
  能落到对应会话 / 那天；浅深截图入基线（进现有截图矩阵）。
- 真机 GUI：`./scripts/gui-test.sh` 加里程碑步骤，探针取几何事实（卡片数、有无
  横向溢出、值在场）。

**R12 文档。** README 中英双语、`docs/USAGE.md`、`docs/ARCHITECTURE.md`、
`CHANGELOG.md` 的 `[Unreleased]`（中文，Added）同步；新约定经 `trellis-update-spec`
沉淀。

## 边界与不做

- **不做连胜 / 最贵一天 / 活跃占比**——那是 `calendarInsightsOf` 的六句，口径不同
  （滚动 365 天 vs 全历史），两者同屏会让用户看到打架的数字。
- **不做排行榜、云同步、分享链接、成就通知 / 系统通知**——违反「数据不出本机」。
- **不做动画庆祝（撒花 / 音效 / 弹窗）**——与「安静的仪器」调性不合；达成与否靠
  排版与层级表达。
- **不做可自定义 / 用户新增的成就**——每枚都必须是我们能复算的事实。
- **不改 `useUsageOverview` 的扫描口径**（不含新增数据通道、不含增量解析）。
- **不追求覆盖 Claude Code 的全部活动**——只看日志里真实存在的四类 token 与事件。

## 验收标准

- [ ] 单元：阶梯常量与阈值逐条钉死；正好达成 / 差一点两侧各一例
- [ ] 单元：并列记录（同值取谁）有确定规则且被测试固定
- [ ] 单元：全空输入返回空清单而不是报错；NaN / 负值 / 非有限值不污染结果
- [ ] 单元：距离（还差 N）计算在「已达最高档」时为 `null` 而非 0 或负数
- [ ] 单元：首次类只在原料存在时返回；无原料时该枚缺席（不是「未达成」）
- [ ] 组件：已达成 / 未达成两态的几何差异可断言；口径脚注在场
- [ ] 组件：空态是一条事实行；失败态与用量页同款
- [ ] 端到端：切到里程碑档的确定值（与夹具账逐项吻合）
- [ ] 端到端：点一枚入口落到对应会话 / 那一天的日回望
- [ ] 端到端：浅 / 深截图入基线，`check-screenshots.sh` 与其自测通过
- [ ] 端到端：130% 字号与高对比度下无横向溢出（几何断言，不进基线图）
- [ ] 真机 GUI：真实 `.app` 打开里程碑，探针事实通过，维护者亲自看截图
- [ ] 性能：合成大夹具（≥300 会话）下里程碑重算 < 150 ms，数字写进 PR
- [ ] 门禁：`./scripts/lint.sh`、`npm --prefix web test`、`npm --prefix web run build`、
      `npm --prefix web run test:e2e`、`cargo fmt --check`、`cargo clippy -D warnings`、
      `cargo check`、`cargo test`、`./scripts/gui-test.sh --build` 全绿
