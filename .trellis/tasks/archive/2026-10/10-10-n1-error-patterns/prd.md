# PRD：N1 · 跨会话错误分析——把「会话里的红字」变成跨会话的规律

> 任务对应 Issue #146（机会清单第 1 名，来源 sniffly Error breakdown）。
> 本文件定需求与验收；技术设计见 `design.md`（研究报告回来后补）。

## 问题

单个会话内的失败已经可见（日志表 `--danger` 状态列、`isError`、`sessionHealth`
红灯、导出带失败标记）。但跨会话的**聚合**不存在：「这个月哪类工具失败最多」
「哪几条命令反复报错」「换模型之后失败率有没有变」——只能一个会话一个会话点开看。

分析器区别于浏览器的正是聚合；整个赛道目前只有 sniffly 做了这件事。

## 数据地基（已核实，`research/error-data-facts.md`，382 会话 / 28.2 万行 / 966MB 全量实测）

- **API 错误**：65 行 / 28 会话（7.3%），status 分布 402×28、500×8、400×6、401×3、
  无 status×20（全是 Connection refused 传输层失败）；429/529 本机 0 例（按 API 语义
  预留分类）。API 错误与工具错误是两个独立通道，**sniffly 不区分 API 错误——单列
  它是我们的天然差异化点**；
- **工具错误**：825 块 / 201 会话（**52.6% 的会话含工具错误，视图有料**）；
  Bash 79.9%、Edit 11.6%；`tool_use_id` 回溯 100% 成功；**35.4% 在 sidechain**，
  聚合必须显式表态（并入或单列），只看主链会静默丢三分之一；
- **分类可靠**：错误文本头部全是平台固定文案（`Exit code N` / `String to replace not
  found`…），regex 可靠；Bash stderr 正文不可靠，分类只到「非零退出」层；
  关键字扫描（429/overloaded 子串）**不可用作错误信号**（命中几乎全来自对话内容）；
- **趋势必须带分母**：实测 09-14 每千条 assistant 25.1 个错误（真异常，基线 2.5 倍），
  09-30 原始数 100 像爆发、归一后 8.4 是基线——不带分母会把「忙一天」误报成「错一天」；
- **解析层不阻塞 v1**：`isError`+`toolName`+`timestamp`+会话归属全在 record 上；
  分类字段（errorKind）、API 错误 message 入结构、会话级错误摘要等 7 条缺口是 v2
  准备（见报告第 3 节）；
- **判定优先级**：结构化字段 > status/枚举 > 文本固定前缀；「其他」桶保留
  **未匹配率**指标自监控（文案漂移的烟雾报警）。

## 功能需求

### F1 错误聚合层（纯函数，可单测）

- 从会话集合聚合出：按工具的失败次数与失败率、按会话/项目的失败密度
  （失败记录数 ÷ 总记录数）、按时间区间的失败趋势；
- 分类法以研究报告的实测建议为准（限流 / 超载 / 上下文超长 / 工具自身失败等），
  判定规则必须**可编码、有测试**（status 码优先，文本模式兜底时要写明模式与误判风险）；
- **不把「等用户输入」算失败**。

### F2 错误视图（界面美观第一，按设计师规范实现）

- 入口与形态由设计师裁决（用量总览「错误」分区 vs 独立标签页，与用量页同区间
  选择器 7/30/90 天）；
- 三个切面都要有：按工具（次数 + 失败率）、按会话/项目（失败密度）、按时间（趋势）；
- **每条可下钻**：点工具 → 涉及它的失败会话与记录 → 点记录**跳回日志视图定位**
  （复用现有定位/高亮机制，这是硬要求，不许做成只能看不能跳）；
- **口径写在界面上**：什么算失败、分母是什么，如实用 provenance 语言标注。

### F3 空态与诚实性

- 没有错误的区间要有真实内容的空态（不是一片空白）；
- 解析覆盖率提示（若该区间日志有未知行）遵循现有机制，不新造一套。

## 验收

- 单元测试：聚合纯函数（含分类判定、分母口径、空输入、等用户输入不算失败）；
- e2e：双引擎（Chromium + WebKit）覆盖新视图的可见性、下钻跳转、空态；
- 真机 GUI 门禁：新视图进默认视图清单 + 至少一组几何事实（图表有界、下钻元素可达）；
- 归档截图：新视图（亮暗两主题 × 双引擎）；
- 变异验证至少一条（先红后绿）；
- 现有测试零回归；`./scripts/lint.sh` 全绿。

## 不做（v1）

- 不做「修复建议」（那是猜）；
- 不做错误与模型切换的自动归因分析（数据里不一定有可靠的模型切换点）；
- 不引入新图表库。
