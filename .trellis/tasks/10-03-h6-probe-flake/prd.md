# PRD：修复真机门禁的间歇性失败（默认视图探针缺失）

> 创建于 2026-10-03 · 上一轮：H2（#107）交付了真机几何门禁
> 发现方式：维护者在 H3a 验收时实跑 `./scripts/gui-test.sh --build`

## 现象（实测记录）

H3a 验收时首次带 `--build` 运行：

```
▶ 断言：界面布局不变量（真机几何探针）
  ✗ 默认视图：几何探针没有产出（app-probe.json）
  ✓ 日志视图：文档无横向溢出（scrollWidth 1400 ≤ clientWidth 1400）
  ✓ 用量总览：表盘有界且含于卡片（140×140px ≤ 200px，卡片内）
  ...
通过 24 · 失败 1 · 跳过 0
```

紧接着**用同一产物复跑（不带 `--build`）：`通过 26 · 失败 0`**。

即：**只有默认视图**的探针缺失，四个标签页视图的探针都正常产出；且不是每次复现。

## 为什么必须修（优先级 P0）

**不稳定的门禁比没有门禁更危险**：它会训练贡献者「这个检查偶尔会红，重跑就好」，
于是真的布局回归也会被当成噪声重跑掉。本项目刚把「界面布局」纳入自动防线，
第一条命就是它不能是噪声。

## 当前已知事实（供定位起点，不必重新推）

- 默认视图探针路径 = `${WORK_DIR}/app-probe.json`（`gui-test.sh:143` 的 `CAPTURE_PROBE`），
  与 `CCA_GUI_PROBE` 一致；标签页视图是 `app-probe-<slug>.json`
- 应用侧（`src-tauri/src/lib.rs` 的 `gui_capture`）：默认视图**先取图**，
  `wait_for_file(默认 PDF)` 成立后才 `probe_at`；每个标签页同理
- 探针走 `WKWebView.evaluateJavaScript:completionHandler:`；
  失败路径只打日志（`gui-probe: 求值失败 …` / `写文件失败 …`）**不 panic**
- 脚本侧：等所有 PDF 落盘 → 再一次性断言所有探针文件是否存在

## 待查清的两种可能（都要给出结论，不能只挑一个）

1. **应用侧瞬时求值失败**：`evaluateJavaScript` 偶发返回错误（页面处于过渡态等），
   于是文件从未写出。若是这种，**日志里应有 `gui-probe: 求值失败`**——
   请把应用日志留住验证（脚本现在会删掉 `WORK_DIR`，需要临时手段取证）。
2. **脚本侧断言早于探针落盘**：脚本等到所有 PDF 就断言，而某个探针的写入
   排在更晚。若是这种，属脚本时序缺陷。

**不接受「没复现所以不知道」**：请用**重复运行**（至少连跑 5 次 `--build` 与 5 次不带）
建立观测，并给出两种可能各自的证据或排除理由。

## 功能需求

1. **先取证再改**：让失败现场可诊断——把应用日志（或至少探针相关行）在失败时打印出来，
   并在失败信息里给出**探针路径与最后修改时间**，而不是只说「没有产出」。
2. **消除不确定性**（按根因二选一或都做）：
   - 应用侧：探针求值失败时**重试**（有限次 + 短间隔），重试仍失败才放弃并记录；
   - 脚本侧：断言前**先等待探针文件**（带超时，与既有 `wait_for_file` 同一纪律），
     超时再判失败。
3. **失败必须可复现地归因**：无论是「应用没写出来」还是「脚本等太短」，
   失败信息要能直接区分这两类。
4. **不削弱既有断言**：探针缺失仍算失败（不是跳过）；四条布局不变量一条不少。

## 非目标

- 不改探针收集的字段与四个标签页的取图流程。
- 不引入重试掩盖真实缺陷：重试只针对「求值瞬时失败」，**不得**用它绕过
  「布局不变量不成立」——后者必须是硬失败。
