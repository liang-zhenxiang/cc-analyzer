## 0. 设计原则

**错误视图是一台质量仪器：读数是中性的，警报是罕见的。** 它回答「我的 Claude Code
在哪里反复失败」，不渲染焦虑。由此三条视觉纪律：

1. **数据中性，警报珍稀。** 全部数据墨水（柱、线、条、占比）走图表色板；
   `--danger` 只花在「仪器判定异常」这一处——异常日标记 ▲、异常线、KPI 的异常日
   读数。90 天窗口里异常日通常 0~5 个，红色像素占比远低于 1%，警报语义因此保持
   锋利。**错误计数本身不涂红**：825 这个数是测量结果，不是警报；整页全红只会
   教用户无视红色。
2. **通道身份贯穿全局。** 工具错误 / API 错误是两个独立通道（我们的差异化点），
   各领一个图表色 + 一个形状语言，从 KPI 瓦片、趋势图、按项目堆叠段到事件行
   的行首记号是**同一套身份**——分得开（各自可辨）也合得拢（同轴同单位可加总）。
   通道永远色 + 文字双信号，不靠颜色单扛。
3. **归一数是主读数，原始数永远可达但不并列。** 不带分母的趋势把「忙一天」误报成
   「错一天」（09-30 实证：原始 100 像爆发、归一 8.4 是基线）。所以趋势图的柱与
   线只画归一数；原始数住在 tooltip、异常日直标与切面读数里——悬停之外每个原始数
   都有非悬停路径（纪律承自上轮：tooltip 不做唯一通道）。

## 1. 关键取舍（先读这张表，别在实现时重新发明）

| # | 问题 | 决定 | 理由 |
| --- | --- | --- | --- |
| 1 | 入口形态：用量总览分区 vs 独立标签页 | **用量总览页内的分段子视图**：页头左侧新增 `用量 \| 错误` 分段控件（复用 `SegmentedControl`），区间选择器 7/30/90 天与扫描进度行两档共用 | 错误内容（KPI + 三切面 + 下钻列表）是「半个页面」的体量，塞进 board 的一格或一行会把每个切面压成缩略图、下钻列表无处容身；独立标签页则复制一套区间状态，违反 design.md「不另造第二套窗口状态」。分段子视图两头兼得：全宽舞台 + 同一窗口控件。默认档仍是「用量」，错误是显式选择，首屏不被垄断 |
| 2 | 红色（`--danger`）用在哪一级 | **只给「异常日」判定**：柱顶 ▲ 标记、异常线（虚线）、KPI「异常日」读数（>0 时）。数据墨水零红色 | 见 §0-1。这是本规范最重要的一条裁决：错误数是读数（中性），异常是判定（警报）。`--danger` 一旦涂到计数上，「警报」就通胀了 |
| 3 | 两通道的色与形 | 工具错误 = `--chart-1` **柱**；API 错误 = `--chart-4` **线**。同轴同单位（每千条模型消息） | 1+4 是上一轮验证过的合格对（两主题 CVD ΔE 21–24）；柱 vs 线给通道第二个（形状）信号；量级悬殊（实测 825 vs 65，归一 10.7 vs 0.8/千条）下线不会被柱淹没——线在柱区间下方独立可读，且 API 爆发日（10-03 ×11）在线上清晰 |
| 4 | 趋势图归一数与原始数怎么共存 | **归一为主**（柱 + 线只画归一数），**悬停 tooltip 给原始数 + 分母**，异常日直标同带两数（`25.1/千条 · 131 条`）。**不加「归一/原始」切换控件** | design.md 允许「以归一为主、悬停出原始数」；页头已有区间控件、Token 面板已有类别控件，第三个控件是泛滥。两数并列画双轴是被 dataviz 明令禁止的第一反模式，不做 |
| 5 | 按工具切面的次数与失败率 | **单条横条 = 失败次数（定排序与条长），行尾双读数列：次数 + 失败率**。率只用数字，不画第二条轨道 | 两个指标共用一个行序（次数降序），率作为行尾读数扫读即可；双条/双轨会把「次数大但率低」与「次数小但率高」画成两张不同强调度的图，视觉系统承载不了双排序 |
| 6 | 按项目切面的形态 | **堆叠横条**：条长 = 失败密度（失败 ÷ 该项目记录总数），段 = 工具（chart-1）/ API（chart-4）两通道，2px 表面缝 | 密度是切面本体；通道构成是免费搭车的洞察（「这个项目的错误全是 API」一眼可见）。需要契约拆通道，见异议 §7-1 |
| 7 | 异常日的标记方式 | **柱顶 ▲（`--danger` 实心三角，底 8px）+ 异常线（1px `--danger` 虚线，标阈值读数）**。两件都消费聚合层的异常判定（异议 §7-2） | ▲ 是逐日标记（在哪天），线是连续参考（谁接近异常）。异常线与上轮否掉的「200K 官方上限线」不同类：阈值是窗口数据派生量（中位数 × 2），有来源、可复算，caption 写明判据即符合 provenance 原则 |
| 8 | 折尾规则 | 两个分布切面统一 **Top-5 + 「其他 N 类」**；「其他」条用中性台阶色（`--bg-active` 填充 + `--border-strong` 描边），不用通道色 | 实测前四名占 96.4%，第 5 名 1.8% 后断崖——5 行已覆盖叙事，长尾折进一行；「其他」是折尾容器不是通道，涂彩色会伪造类别身份。与用量页 `DEFAULT_TOP_N=6` 不强求一致：那是 token 分布（长尾平缓），这是错误分布（断崖），按数据形状取 N |
| 9 | 下钻列表形态 | **面板内嵌展开**（切面点击 → 过滤下方整行的「错误事件」面板），不是路由跳转、不是折叠面板 | design.md §2.3 定的链路是「切面条目 → 事件列表 → 跳会话分析」两跳；第一跳留在本页（上下文不丢），第二跳（onRevealRecord）才离页 |
| 10 | 0 错误区间的空态 | **面板骨架保留 + 事实行**：「近 N 天检查了 X 个会话的 Y 条模型消息与 Z 次工具调用，没有失败记录」 | 承压缩面板先例（不画 0 柱空图）；「0 是被验证过的」由分母数字证明，不用抒情句 |
| 11 | 扫描中的呈现 | 与用量档同款渐进更新，header 进度行共用，无专属骨架 | 同一扫描、同一批数据（design.md §2.2），数字渐进增长本身就是「正在测量」的信号 |

## 3. 逐组件规格

### 3.1 KPI 行（复用 `kpiRow` / `kpi` 结构与 CSS）

四瓦片，结构与用量档 KPI 逐字同构（标签 `--fs-xs` tertiary / 值 `--fs-lg` 600
tabular-nums / `ProvenanceBadge` 在标签行右端 / `kpi + kpi` 左发丝线）：

| 瓦片 | 标签 | 值 | 值行右侧次读数（`--fs-sm` tertiary，tabular） | 特殊态 |
| --- | --- | --- | --- | --- |
| API 错误 | `■ API 错误`（■ = 8px `--chart-4` 方块，`--r-xs`，`aria-hidden`） | `65` | 无 | — |
| 工具错误 | `■ 工具错误`（■ = 8px `--chart-1` 方块） | `825` | 无 | — |
| 最常见失败工具 | `最常见失败工具` | `Bash` | `659 次` | 无工具错误时值 = `—`，次读数省略 |
| 异常日 | `异常日` | `1 天` | `9/14`（1~2 个时列日期，逗号分隔；≥3 个省略，趋势图看） | **值 >0 时 `color: var(--danger)`**；=0 时 `--text` 常规色——0 异常不是喜讯，是读数 |

- 通道色块放在**标签文字前**（8×8，与图例 / 事件行记号同款同尺寸）：标签行已有
  ProvenanceBadge 占右端，色块前置不挤；标签行因此同时携带「通道身份」与「来源」
  两个信号，值行保持纯数字。
- 通道色块不替代任何文字：瓦片标签本身写着「API 错误」，色块是冗余信号（CVD
  双保险），`aria-hidden`。
- 千分位：`toLocaleString("en-US")`（现页惯例）。

**KPI 脚注**（`kpiFootnote` 跨列，常显、不做悬停展开）：

> 失败 = 工具结果被标记为错误，或 API 返回错误消息（不含「等用户输入」的拒绝）；
> 含子 agent 记录。分��——趋势：每千条模型消息；按工具：该工具总调用次数；
> 按项目：该项目记录总数。

provenance 是本应用立身之本，三句口径常显两行 `--fs-xs`，不藏进浮层（KPI 脚注
先例本来就是常显段落；藏起来的口径等于没有口径）。

### 3.2 趋势面板「每日错误率」（新自绘组件 `ErrorTrendChart`）

**数据**：`ErrorStats.daily` 逐日 `{dayStart, api, tool, assistantMessages}`（归一数
视图自算：`tool/messages*1000`、`api/messages*1000`，异议 §7-4）。

**画布**（遵循现有 `viewBox 720` 约定，等比缩放）：`viewBox="0 0 720 200"`；
`padLeft 56`、`padRight 10`、`padTop 14`（给 ▲ 留空）、`padBottom 24`；plot =
654×162。整行面板内宽 ≈1384，实际渲染高 ≈385px——趋势是本功能的主角（带分母的
洞察是研究的核心发现），全宽高图是这个地位的版式表达；与「每日 Token 消耗」
170px 的半宽柱图刻意拉开层级。

**坐标轴**（复用 `chartPrimitives`，不另起炉灶）：

- Y 轴：`max = niceAxisMax(max(per1kTool, per1kApi, 异常阈值))`（阈值也要落在线内
  ——轴域必须容纳参考线，否则线画出界）；`axisTicks(max, 3)`；`GridLine` 中性灰 +
  基线 `strong`；刻度文字 `formatAxisValue`（per1k 值域 0~30，tick 全为整数，
  compact formatter 输出 `10`/`20` 正常）。
- X 轴：`formatDayLabel`（`9/14`），`labelStride = Math.ceil(n / 12)`（BarChart
  惯例）。
- **0 值天**：工具柱画 1.5px 短桩（BarChart 惯例——「没有错误」是事实，不是缺口）；
  API 线照常走到 0。
- **无分母天**（`assistantMessages = 0`）：归一数 undefined，**不是 0**。工具柱画
  短桩 + tooltip 注明「当日无模型消息」；API 线**断开**（缺口），不贴 0——
  0/0 画成 0 是撒谎。

**工具柱**：`fill: var(--chart-1-soft)` + `stroke: var(--chart-1)` 1px（`BarChart.bar`
同款仪器画法）；`barWidth = min(slot*0.72, 44)`；hover 单柱实色 0.55（同 BarChart
CSS，含 `--dur-hover` 过渡与 reduced-motion 关闭）。

**API 线**：`stroke: var(--chart-4)` 2px，round join/cap，不平滑（直折线，仪器
不造假）；**默认不画数据点**（线可读；90 天下点会粘连）。7/30 天档（≤31 点）常显
`r=3` 实心点。悬停吸附点：`r=4` 实心 + 2px `--bg-subtle` 表面环（dataviz 标记
规格）。

**异常线**：`y = 阈值`，`stroke: var(--danger)` 1px，`stroke-dasharray: 4 3`；
右端上方小字 `异常线 20`（`--fs-xs`，`--danger`，右对齐 padRight 内）。阈值来自
聚合层（异议 §7-2）；**若口径未定案，异常线是可选层，▲ 是必选层**——线删掉不伤
叙事，▲ 删掉 KPI 就没了着落。

**▲ 异常日标记**：异常日的工具柱顶中点上方 3px 处，实心等边三角形底边 8px、
高 ≈7px，`fill: var(--danger)`；同 x 若 API 线高于柱顶（罕见），▲ 移到线之上
4px。▲ 不与轴/图例碰撞（padTop 14 保证）。**异常日直标**：窗口内异常日 ≤2 个时，
▲ 右侧 6px 标 `9/14`（`--fs-xs` `--text-secondary`）；≥3 个不逐个标（KPI 次读数
与 tooltip 承担）。

**图例**（≥2 系列必设）：面板体内、图上方右对齐一行，三项——

- `■ 工具错误`：10px `--chart-1` 方块（小徽章允许实色）
- `— API 错误`：16×2px `--chart-4` 短线段
- `▲ 异常日`：8px `--danger` 三角

文字 `--fs-xs` `--text-secondary`，`gap: var(--sp-3)`。三项三种形 + 各自文字，
色盲 / 灰度打印下全可辨。

**caption**（面板底，`--fs-xs` tertiary，`BarChart.caption` 惯例）：

> 纵轴为每千条模型消息的错误数（归一，消解「忙一天」与「错一天」的混淆）；
> 悬停任一天可看原始条数与分母。异常日 = 归一数超过窗口中位数 2 倍且当日错误
> ≥ 10 条。

## 4. 颜色裁决表

**结论：零新增令牌。** 每个用色点 → 令牌 → 为什么是它：

| 用色点 | 令牌 | 为什么 |
| --- | --- | --- |
| 工具错误通道（趋势柱、按工具条、堆叠段、KPI/图例/事件行记号） | `--chart-1` / `--chart-1-soft` | 面板第一系列槽位（图表色板「只论顺序」的既定语义）；与用量档「每日 Token 消耗」柱同色是**同语言**而非冲突——「每天的竖条都是这个蓝」降低再学习成本 |
| API 错误通道（趋势线、堆叠段、记号） | `--chart-4` / `--chart-4-soft` | 面板第二系列；1×4 是上轮 CVD 实测合格对（两主题 ΔE 21–24），chart-1×2 深色塌缩（3.7）被否；金褐色与蓝的冷暖对峙在柱线并置下可辨性最好 |
| 异常日 ▲、异常线、KPI 异常值 | `--danger` | **确定的错误判定**——tokens.css 三档「确定性」语义里 danger 的本职。且只在此处：警报不通胀（§0-1）。danger↔chart-4 是三色中最近的对（deutan ΔE 10.3/13.5，附录），但 ▲/线/柱三形互异，双保险成立 |
| 「其他」折尾条 | `--bg-active` + `--border-strong` | 台阶色声明「折尾容器，非通道」；信息在文字读数，条只是位置辅助 |
| 通道 / 图例色块、▲ | 实色（各令牌实值） | 「小徽章允许实色」的既定规则（8px 方块、10px 图例块）；大面积（柱/条/段）一律 -soft + 实色描边 |
| 事件行 / 切面行文字 | `--text-secondary` / `--text-tertiary` / `--text` | 文字穿文字令牌，永不用系列色写正文（dataviz 铁律） |
| 选中态（切面行、焦点行） | `--accent-soft` + `--accent` | 「选中是 accent 的本职」，与 SegmentedControl / 日志表逐字一致 |
| 子 agent 徽标 | `--bg-inset` + `--border` + `--text-tertiary` | 归属信息不是警报，中性台阶 |
| KPI 值、次数、率、密度 | `--text` + tabular-nums | 读数是主角，中性墨 |

**冲突检查**（为什么不是别的）：

- **为什么错误数据不用 `--danger` 系画柱？** ① 825 次失败是测量读数，红柱把整页
  变成警报器，之后真警报（异常日）没人看；② `--danger-soft` 大面积平涂与
  `--danger` 描边会在趋势图里把「错误量」与「异常判定」两个语义压成一个——
  用户该学到的是「蓝色 = 我的失败分布（中性事实），红色 = 仪器判定异常（要去看）」。
- **为什么 API 通道不用 `--chart-2`（青）？** 与 chart-1 相邻堆叠 / 并置在深色下
  CVD 塌缩（上轮实测 ΔE 3.7，deutan）。本项目两通道并置是常态，1+2 出局。
- **为什么不用 `--warning` 表达 API 错误？** warning 的语义是「非确定信息」（估算、
  beta），API 错误是确定的失败——借警告色会同时毁掉两个语义档（tokens.css 注释
  明言三档并列）。
- **`--danger` 做文字（KPI 异常值、异常线标签）的对比度**：浅 6.54:1 / 深 6.52:1
  （面板底实测，附录）——≥4.5 文字门槛，合法。
- **同页共处检查**：错误档与用量档不同时渲染（分段互斥），无跨档颜色打架；错误档
  内部彩色只有三系（chart-1 / chart-4 / danger）+ accent 选中 + 中性台阶，全部
  载荷点已在附录实测。

## 5. 交互规格汇总

**指针**

- 趋势图：crosshair 竖线（`--border-strong`，rAF 合帧）吸附当日 → tooltip
  （§3.3）；离开绘图区消隐。**点击某天 = 过滤事件列表为该日**（日是切面之一，
  与工具 / 项目行同权）；点空白 = 不做任何事（无「取消选中」语义——取消走
  清除过滤按钮）。
- 切面行（工具 / 项目）：hover `--bg-hover` + `title`；click = toggle 过滤
  （`aria-pressed`）；过滤切换后事件列表**立即更新并滚回顶部**。
- 事件行：hover `--bg-hover` + 行尾箭头显现；click = `onRevealRecord` 离页
  （不 toggle）。
- 「其他」行同样可点（过滤 = 该折尾集合）。

**键盘**

- 趋势容器：`tabindex=0` + `role="img"` + 摘要 `aria-label`（模板：「近 30 天
  错误率：工具 825 次、API 65 次，1 个异常日」）。聚焦后 `←/→` 逐日移动
  （焦点日 = 柱描边加深 + 朗读该日两通道读数），`Enter/Space` 过滤该日，
  `Esc` 清除过滤。
- 切面行：原生 button，Tab 逐行（每面板 ≤6 行，不设 roving）。
- 事件列表：容器 `tabindex=0`，`↑/↓` 行移动（`useRowNavigation` 语言），
  `Enter/Space` 跳会话，焦点行 = `inset 2px var(--accent)`。
- 焦点可见性永不依赖颜色单信号（选中态 = 底色 + 左缘竖条双信号）。

**动效**：悬停 `--dur-hover`（柱、行、箭头）；过滤切换内容直换，无布局动画；
`prefers-reduced-motion: reduce` 时全部 transition none（BarChart 先例）。▲、
异常线、堆叠段无任何动画。

**字号缩放 90–130%**：文字全部 `--fs-*`/`--lh-*` 成对令牌；SVG 内文字随 viewBox
等比（现有图表行为）；切面行标签 / 事件行预览 ellipsis + `title` 兜底；KPI 四瓦片
`@media (max-width: 900px)` 变两列（`kpiRow` 现有规则继承）。

## 6. 无障碍

- **通道与异常身份永远不靠颜色单独承载**：通道 = 色块 + 文字（图例 / KPI 标签 /
  事件行身份段）；异常 = ▲ 形状 + 「异常日」文字；趋势图三系列 = 柱 / 线 / 三角
  三形。灰度打印与全色盲下全链路可辨。
- **对比度（实测，附录）**：图形件（chart-1 / chart-4 / danger 的描边、线、记号）
  两主题对面板底 ≥3:1；danger 做文字两主题 ≥4.5:1；正文走 `--text-secondary`
  （两主题 ≈7:1）。异常虚线（1px）≈6:1，达标；网格线 `--border` 是 recessive
  chrome，既有惯例，不逐条设门槛。
- 屏幕阅读器：四个 Panel 都是 `aria-label` landmark；趋势图 `role="img"` 带摘要；
  事件列表是真列表（虚拟化不破坏语义容器）；切面行 `aria-pressed`；过滤态变化
  时事件面板描述行天然朗读（它是 DOM 文本）。
- **tooltip 的 DOM 孪生**：tooltip 里每个值都有非悬停路径——原始数在切面
  `title`、异常日直标、KPI 次读数；归一数在轴与 caption。tooltip 增强、不设卡。
- 色盲专项：三色 all-pairs CVD 实测最差对 deutan 10.3（浅）/13.5（深），高于
  dataviz 目标线 8；叠加上述形状冗余。

## 7. 异议节（技术边界建议——实现前回 `design.md` 定案）

1. **`byProject` 需拆通道**：契约 `ErrorProjectBucket = {projectLabel, errors,
   records, density}` 的 `errors` 是合计，而按项目堆叠条需要 `{toolErrors,
   apiErrors}` 拆分。建议契约改为 `{projectLabel, toolErrors, apiErrors, records,
   density}`（合计可派生）。视图层对 `events` 二次聚合可行（窗口内 ≤900 条），
   但通道拆分是聚合口径，落在聚合层才能被单元测试锁住（design.md 自己的定位：
   「聚合层可单测」）。
2. **异常日判定应在聚合层并给出阈值**：`ErrorStats` 无异常字段，而 KPI「异常日」、
   ▲、异常线三处都消费它。建议增 `anomalyThreshold: number | null` 与逐日
   `anomalous: boolean`（或 `anomalyDays: number[]`）。**口径建议**：窗口内非零日
   合计 per1k 中位数 × 2，**且**当日原始错误数 ≥ 10——小样本日（40 条消息 1 个错
   = 25/千条）被下限挡住。实测自检：09-14（25.1 / 131 条）过、09-30（8.4 / 100 条）
   不过、基线日（9~11）不过，与研究报告的人判吻合。若口径另有定案，视觉只消费
   布尔与阈值数字，形态不变；**口径未定案前异常线不画，▲ 挂在 KPI 一起延后，
   其余视图不受阻**。
3. **`daily.assistantMessages` 的口径要写死**：错误事件含 sidechain（35.4%），
   分母若只数主链 assistant 消息，含子链的日子会被系统性推高。建议分母含
   sidechain 的 assistant 消息（分子分母同域）。这条不写清，「归一消解忙日误报」
   的立论会被静默侵蚀。
4. **通道归一数视图自算即可**：`daily` 已有 `api`/`tool`/`assistantMessages`
   原始数，`per1k` 单数字段若指合计则两通道归一在视图 `(x/messages)*1000` 自算，
   不必改契约——但请确认 `per1k` 的定义（合计还是工具）写进注释，避免两处口径
   打架。

以上四条都不阻碍视觉方案本身：1、2 是契约补字段，3、4 是口径写明。

## 8. 实现注意点（给实现者）

- **新组件清单**：`ErrorTrendChart`（SVG，趋势）、`ErrorRankList`（双读数横条，

- **SVG 约定**：`viewBox 720` 宽、`width: 100%; height: auto`（`chartPrimitives`
  的 `.chart`）；网格线 `shape-rendering: crispEdges`、数据墨水不设（抗锯齿）；

- **数字格式**：次数 / 消息数千分位 `toLocaleString("en-US")`；率与密度
  `(x*100).toFixed(1)+"%"`，`<0.1%` 且 `>0` → `"<0.1%"`，非法分母 → `"—"`；
  per1k `toFixed(1)`；轴日 `formatDayLabel`；事件行时间 `M/DD HH:mm`（本地时区，
  组件内格式化，复用现有日期工具拼装）。
- **tooltip**：HTML 浮层复用 `TimelineTrack` 的画法与定位逻辑（上轮同款）；crosshair
  吸附按 dayStart 二分；rAF 合帧。
- **过滤状态**：单一 `useState<{kind:"tool"|"project"|"day"; value:string|number}|null>`
  放在错误档容器（三个切面 + 事件面板 + 清除按钮共享）；切面 toggle 与趋势图
  点击日写同一个 state。
- **e2e / GUI 门禁钩子建议**：容器 `data-error-view`、趋势 `data-error-trend`、
  事件列表 `data-error-events`、过滤态 `data-error-filter`（沿用 `data-probe-pending`
  先例；归档截图亮暗 × 双引擎四张）。
- **测试夹具对齐**：`error-session.jsonl` 的数字与本规范示例无关，断言以夹具
  计算 expectation，别把本文档的实测数字（活语料）写死进测试。
- **性能**：`mergeErrorStats(inputs, days)` 已是 `useMemo`（与 `compactionStats`
  同位）；过滤只是 `events.filter`，不需要 memo 二级缓存。

## 9. 明确不做什么（防实现者跑偏）

1. **不给错误计数涂红**——柱、条、KPI 的 0/65/825 全中性墨；红色只有异常判定
   （▲、异常线、异常 KPI 值）三处。
2. **不做「归一 / 原始」切换控件**，也不画双 Y 轴（第一反模式）。
3. **不做工具错误文本分类**（Exit code / 未命中 / 超时…）——v2，契约与 regex 都
   没定案，v1 画出来是假精度。
4. **不做主链 / 子链切换器**（design.md §3 已定）；「子 agent」只做行内徽标。
5. **不新调任何颜色**、不引入图表库、不借 `--warning`/`--success`/`--cat-*`
   表达错误或通道。
6. **不画无来源参考线**；异常线是唯一参考线且必须由聚合层阈值驱动 + caption
   写明判据——两证缺一就不画。
7. **空态不画 0 柱 / 空条 / 空堆叠**（压缩面板先例）。
8. **tooltip 不做任何读数的唯一通道**。
9. **「其他」折尾桶不给率读数、不涂通道色**。
10. **事件列表不做多选过滤、不分页**——单选 + 虚拟滚动。
