## 本轮主题

**先把门面修好，再把门面锁住，然后让它更好看、更想用。**

用户的诉求是「界面美观度必须是第一位的，然后好用、想用」，并且
「务必真实打开 app 进行验证，配合截图验证」「确保后面加的每一个功能都不会影响到老功能」。

盘点后本轮的判断是：这个项目的**设计系统底子已经很好**（令牌纪律严格、对比度有据、
「仪器面板」方向清晰），短板不在「没有设计」，而在三件事：

1. **门面是坏的**——README 首图展示的是一个被撑爆的表盘（见 H1）；
2. **视觉回归没有自动防线**——缺陷是靠人肉看截图发现的，下一次还会漏（见 H2）；
3. **上一轮评审的 Top10 还有 6 条没做**，且首批体验细节（加载态、密度统一、死代码）未收口（见 H3）。

## 跨子任务验收标准（父任务负责）

      `npm --prefix web run test:e2e`、`./scripts/gui-test.sh --build`
- [ ] 每个子任务的改动都带了**能发现真实回归**的测试，且做过变异验证
      （改坏实现 → 测试必须红）。禁止「永远为真」的断言

      用量总览、会话分析、设置、实时监控四个视图在浅/深色下均无布局缺陷
- [ ] `docs/screenshots/` 与本轮新界面一致，README 双语首图正确
- [ ] 每个用户可感知的改动都有 CHANGELOG `[Unreleased]` 中文条目
- [ ] 发布一个 `v0.11.0-beta.1` 预发布 tag，确认 beta 渠道实况可用

## 非目标

- 不做整体重构、不迁移框架（React 19 是 Issue #19，独立进行）。
- 不做内嵌会话操控 / agent 执行（与「只读分析器」的隐私定位冲突）。
- 不做多 agent CLI 支持（深耕 Claude Code 是聚焦策略）。
- 不引入像素级截图 diff 框架（H2 用几何断言，噪声更低、意图更明确）。

## 风险

- **真机 GPU/字体渲染差异**让截图断言变得脆弱 → H2 断言的是**几何关系**（宽度、包含关系、
  是否溢出），不是像素位置或颜色，这类断言与渲染差异无关。
- **H3 的视觉改动会让既有截图全部失效** → 这正是 H1 的「基线防漂移检查」要覆盖的场景；
  H3 完成后必须重出全套图，并由维护者目验。
- **并行改 CSS 冲突** → 见上表的依赖说明；同一时刻只让一个子任务改同一批文件。
