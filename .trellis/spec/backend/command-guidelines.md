# Tauri Command Guidelines

> How commands are written, named, wired, and kept in sync with the frontend.
> Replaces a generic "database guidelines" file — this project has no database.

---

## The IPC Contract (read this first)

A command only works when **five places agree**. Adding a command means editing
all of them; forgetting one fails at runtime, not at compile time.

| # | Place | What to add |
|---|-------|-------------|
| 1 | `src-tauri/src/lib.rs` | `#[tauri::command] fn foo(...) -> Result<T, String>` |
| 2 | `src-tauri/src/lib.rs`, `run()` | `foo` in `tauri::generate_handler![...]` |
| 3 | `src-tauri/build.rs` | `"foo"` in `app_manifest.commands(&[...])` — otherwise no permission file is generated |
| 4 | `src-tauri/permissions/autogenerated/foo.toml` | Run `cargo check`; the file appears automatically. **Commit it** (the repo commits this directory). |
| 5 | `src-tauri/capabilities/default.json` | `"allow-foo"` in `"permissions"`. Without this the command is registered but unreachable from JS. |
| 6 | `web/src/api/types.ts` + `web/src/api/tauri.ts` | Add to the bridge interface, then `invoke<T>("foo", { ... })` |

Worked example — `read_head`:

- `read_head(path, max_bytes)` in `lib.rs`
- listed in `generate_handler!`
- `"read_head"` in `build.rs`
- `src-tauri/permissions/autogenerated/read_head.toml` → `identifier = "allow-read-head"`
- `"allow-read-head"` in `capabilities/default.json`
- `readHead: (path, maxBytes) => invoke<string>("read_head", { path, maxBytes })` in `tauri.ts`

For a **plugin** command (see `float`): step 3 becomes `InlinedPlugin::new().commands(&["enter","exit"])`,
step 5 becomes `"float:allow-enter"` (namespaced), and JS calls `plugin:float|enter`.

### 第 5 步漏掉的代价：静默失效（v0.9.0-beta.1 实录）

漏了 `capabilities` 那一行，**构建、单测、e2e 全绿**——因为 mock 与 jsdom 都不经过
权限层。真机上的表现是：

- `invoke` 一律被拒，前端 `catch` 后走自己的兜底文案（用户看到「当前版本 未知」）
- 整个自动更新链路（检查、下载、安装）形同虚设，而**没有任何地方报错**

两个衍生教训：

1. **命令名不要带 `::`**。曾用 `updater::app_version` 注册，生成的权限文件名
   含 `::`，在 Windows 文件系统上非法——checkout 当场失败。命令在 `lib.rs`
   顶层重导出，以裸名注册（`mod updater; use updater::{app_version};`）。
2. 自动生成的文件名是**下划线**（`app_version.toml`），而权限标识符是
   **连字符**（`allow-app-version`）——照文件名去写 capability 会写错。

**现已由测试强制**：`lib.rs` 的 `every_app_command_is_allowed_in_the_capability`
逐个核对 `build.rs` 清单里的命令在 capability 里有对应 `allow-<kebab>` 条目，
漏一条即失败并指名道姓（变异验证过：删掉一条授权，测试报
`capabilities/default.json 缺少这些命令的授权…["allow-app-version"]`）。

## Naming and Arguments

- Rust function name **is** the IPC name: `read_dir` → `invoke("read_dir")`. No
  `rename` attributes anywhere in this repo.
- Parameters are `snake_case` in Rust, `camelCase` on the JS side; Tauri converts
  automatically. Existing pairs: `stream_id`↔`streamId`, `max_bytes`↔`maxBytes`,
  `stdin_text`↔`stdinText`, `timeout_ms`↔`timeoutMs`. Keep the TS side documented
  in `web/src/api/types.ts` (`RunLinesOptions` is the reference).
- Prefer `Option<T>` over sentinel values; the frontend passes `?? null`
  (`tauri.ts` `runLines` — `stdinText: stdinText ?? null`).
- Argument order on the Rust side is irrelevant to the wire format, but keep it
  aligned with the TS signature so the two are diffable.

## Return Types

- Every fallible command returns `Result<T, String>`; the error channel is
  described in [error-handling.md](./error-handling.md).
- `T` is a `#[derive(Serialize)]` struct declared beside the command
  (`DirEntry`, `StatInfo`, `RunLinesResult`, `ExecTextResult`). Field names go
  over the wire verbatim, so `is_dir`, `mtime_ms`, `mtime_ms`-style snake_case is
  mirrored literally in `web/src/api/types.ts`.
- A command with nothing to return uses `Result<(), String>` (`write_text`,
  `spawn_detached`) — the TS bridge wraps it in an `async` function that awaits
  and returns `void`.
- Simple probes return the value directly: `fn monitor_port() -> u16`,
  `fn monitor_ping() -> bool`.

---

## Sync vs. Async

Only mark a command `async` if it awaits. The async set is exactly:
`run_lines`, `exec_text`, `cancel_lines`, `spawn_detached`. Everything else
(`read_dir`, `stat`, `read_text`, `read_head`, `write_text`, `home_dir`,
`app_data_dir`, `monitor_port`, `monitor_ping`) is synchronous std code.

## Streaming and Cancellation

`run_lines` is the template for any long-running work:

- Emits stdout lines as events named `proc:line:{stream_id}` via
  `Emitter::emit(&event_name, line)`; stderr is buffered and returned in the
  result struct instead of streamed.
- The caller generates the `stream_id` (a UUID in `tauri.ts` `randomId()`),
  passes it in, and **subscribes before invoking** — `runLines` does
  `listen(...)` first, `invoke` second, `unlisten()` in `finally`.
- Cancellation goes through `ProcState.cancels`: the `oneshot::Sender` is
  inserted after spawn and removed in all paths. `cancel_lines` returns
  `Ok(false)` when the id is unknown, `Ok(true)` when it signalled a live handle.
- Killed children are always reaped (`child.wait().await`) so they do not linger
  as zombies; the timeout branch kills without reaping — keep that in mind if you
  copy the pattern.

## State and Context

- App state: define a struct, `.manage(...)` it once in `run()`, take it as
  `state: tauri::State<'_, ProcState>`. Never hold a `std::sync::Mutex` guard
  across an `.await` — `ProcState` locks are scoped to a single expression.
- App handle: take `app: tauri::AppHandle` and clone it into spawned tasks
  (`run_lines` clones it into `event_app` so the task outlives the call).

## Anti-Patterns

- **Don't widen the surface.** No generic `read_file_anywhere`, `eval`, or
  `shell(command: String)` command. The existing primitives are already broad
  enough; see [security-and-permissions.md](./security-and-permissions.md).
- **Don't change a command signature without updating the frontend.** The
  `#[allow(clippy::too_many_arguments)]` on `run_lines` (lib.rs:155) exists
  precisely because its signature is a public contract with
  `web/src/api/types.ts`, not an internal refactor target.
- Don't add a command for something the frontend can already do with
  `read_text` / `run_lines`.
- Don't leave a parameter unused. `run_lines` currently does `let _ = label;`
  (lib.rs:167) — an accepted compatibility shim, but don't copy the pattern for
  new commands.
